# 代码现状调研

## 概述

**目的**：在设计前充分了解当前代码库中与需求相关的信息，确保设计与现有代码风格、架构保持一致，避免设计出与项目现状脱节的方案

**功能**：按需调研代码库的 13 个维度（代码风格、代码路径、架构模式、类似功能、技术栈、数据存储、错误处理、安全惯例、日志与监控、API 约定、测试模式、配置管理、部署与 CI/CD），根据需求特征自动筛选需要调研的维度，强制 ki 记忆索引优先获取信息

**使用场景**：
- design-craft 技能执行前置信息收集阶段时
- 任何需要在设计前了解现有代码的场景
- 用户说"了解一下现有代码"、"代码风格是什么"、"这个功能的代码在哪里"时

## 核心原则

1. **按需调研**：只调研与当前需求相关的维度，不相关的跳过
2. **ki 记忆索引优先**：项目记忆索引 → 知识库记忆索引 → 代码搜索 → 语义检索兜底。禁止跳过 ki 直接搜代码
3. **必须执行**：ki 记忆索引为必查项，即使觉得"不太可能有"，也要实际调用确认
4. **不盲目搜索**：每一步必须基于上一步的结论决定是否需要继续，避免全量搜索浪费 token

## 快速跳过判定

满足以下任一条件时，可极简化或跳过本步骤：

- 上下文成熟度为「高」（用户已充分讨论过技术方案）
- 用户明确表示已熟悉项目代码
- ki 项目记忆索引中已有充分的项目架构知识（`ki_query_group` hot 模式命中率高）

## 调研维度

**关键：根据需求特征选择维度，只调研需求涉及的部分。** 表中"需求特征"列是触发条件——需求命中该特征时才调研对应维度。

| 维度 | 调研内容 | 需求特征（命中才调研） |
|------|----------|----------------------|
| **代码风格** | 命名规范、代码组织方式、注释风格 | 首次接触该项目 |
| **代码路径** | 与需求相关的现有代码文件、模块位置 | 不清楚需求涉及的模块 |
| **架构模式** | 项目整体架构、模块划分、依赖关系 | 对项目架构不熟悉 |
| **类似功能** | 已有的类似功能实现，可参考的模式 | 不确定项目是否已有参考 |
| **技术栈** | 使用的框架、库、版本约束（可引用 dependencies/） | 首次接触该项目 |
| **数据存储** | 数据库模式、ORM 用法、迁移惯例 | 需求涉及数据模型变更 |
| **错误处理** | 异常处理惯例、错误码规范、重试策略 | 需求涉及异常/边界处理 |
| **安全惯例** | 认证方式、权限模型、输入校验模式 | 需求涉及权限或数据安全 |
| **日志与监控** | 日志框架、日志级别、监控接入方式 | 需求涉及可观测性内容 |
| **API 约定** | REST/GraphQL 风格、版本策略、分页与错误响应格式 | 需求涉及新增或修改 API |
| **测试模式** | 测试框架、测试组织方式、断言风格 | 需求包含测试相关内容 |
| **配置管理** | 配置文件组织、环境变量管理、feature flag | 需求涉及配置或环境差异 |
| **部署与 CI/CD** | 部署流程、CI 流水线、发布策略 | 需求涉及部署变更 |

### 与依赖文档的关系

技术栈维度应优先引用已整理的依赖文档（`dependencies/`），避免重复调研。仅当依赖文档未覆盖时才补充搜索。

### 调研示例

**需求："给用户列表接口增加分页功能"**
- 命中维度：代码路径（找用户列表接口）、API 约定（分页格式）、类似功能（是否已有分页实现）
- 跳过维度：安全惯例、部署与 CI/CD、测试模式（如需求未提及测试）

**需求："重构认证模块，从 session 迁移到 JWT"**
- 命中维度：代码路径、架构模式、安全惯例、数据存储（token 存储）、错误处理
- 跳过维度：API 约定（如不涉及 API 变更）、部署与 CI/CD

## 调研执行顺序（强制）

**禁止跳过 ki 直接搜代码。** 必须按优先级逐级执行，每一步都实际调用对应工具并记录结果，再决定是否需要进入下一步。

### 优先级总览

```
ki 项目记忆索引 → ki 知识库记忆索引 → 代码搜索 → 语义检索兜底
   (ki_query_group)     (ki_query_group)    (grep/符号搜索)  (ki_search)
```

### 第 0 步：检查 ki 可用性

**必须首先执行。** 检查 ki MCP 服务是否已安装：

- `ki_query_group` 工具可用 → ki 已集成，进入第 1 步
- `ki_query_group` 工具不可用 → **中断调研**，提示用户安装 ki MCP 服务后再继续

```text
⚠️ ki MCP 服务未安装，无法执行记忆索引检索。

请先安装 ki MCP 服务，安装后可获得以下能力：
  - 从项目记忆索引中直接获取之前调研过的结论
  - 从知识库记忆索引中获取结构化的模块/架构知识
  - 避免每次调研都重复搜索代码库

安装方式：<提供 ki MCP 安装指引>
```

### 第 1 步：查询项目记忆索引

**必须执行。** 使用 `ki_query_group` 查询项目维度的记忆索引。

```
ki_query_group(mode="hot", scope="${scope}-memory")
```

- **目的**：获取之前调研过的结论、项目特有的架构知识，避免重复劳动
- **mode 选择**：
  - `hot`：先看热门 Relation（常用模块、高频引用），快速建立认知
  - `full`：hot 命中不足时，拉全量 Group 树深度排查
- **若命中**：直接复用记忆内容，跳过对应维度的代码搜索，标注来源为「项目记忆索引」
- **若未命中**：记录「项目记忆索引无相关结果」，进入第 2 步

### 第 2 步：查询知识库记忆索引

**必须执行。** 使用 `ki_query_group` 查询知识库维度的记忆索引。

```
ki_query_group(mode="hot", scope="${scope}")
```

- **目的**：获取已结构化的模块信息、架构知识、API 接口等通用知识
- **mode 选择**：同第 1 步策略（hot → full）
- **若命中**：提取相关模块信息，跳过对应维度的代码搜索，标注来源为「知识库记忆索引」
- **若未命中**：记录「知识库记忆索引无相关结果」，进入第 3 步

### 第 3 步：代码搜索

**仅当第 1、2 步均无法覆盖某个维度时，才执行代码搜索。**

- 使用 `search_content`（grep）精确定位代码位置
- 使用 `search_file` 按文件名模式查找
- 使用 `task` 派遣 code-explorer 子 agent 进行大范围搜索
- 标注来源为「代码搜索」

### 第 4 步：语义检索兜底

**仅当前 3 步均无法覆盖时，使用语义检索兜底。**

```
ki_search(scope="${scope}")          # 知识库维度语义检索
ki_search(scope="${scope}-memory")   # 项目记忆维度语义检索
```

- **目的**：向量召回相关记忆，作为最后的补充手段
- **标注来源为**：「语义检索」

### 产出物中的溯源要求

产出文档必须标注每个维度的信息来源，粒度到具体检索层级：

```
> 调研来源：项目记忆索引 ✓ | 知识库记忆索引 ✗ | 代码搜索 ✓ | 语义检索 ✗
```

这确保调研过程可追溯，也方便后续复用。

## 产出物

生成简略的 **代码调研文档**，**必须落盘到文件系统**，不要只在对话中输出。

### 落盘规范

- **存储路径**：需求目录的 `reference/` 子目录下，文件名 `code-survey.md`
- **落盘方式**：使用 `write_to_file` 写入文件，确保文档持久化
- **文件命名**：`reference/code-survey.md`（如已有同名文件则覆盖更新）

### 文档要求

- 仅记录实际调研过的维度，未调研的维度不写入文档
- 每个维度标注信息来源（记忆系统 / 知识库 / 已有文档 / 代码搜索）
- 内容简略，重点是帮助设计决策，不需要非常详细

### 文档模板

