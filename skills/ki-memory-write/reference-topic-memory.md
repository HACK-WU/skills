# 专题记忆策略参考（写入侧）

ki-memory-write 的「专题记忆」策略细则。主流程见 SKILL.md。调用方为 expert-team（Step 8）。查询专题记忆走 `use_skill("ki-memory-lookup")`。

## 定位

专题记忆 = **路标 + 快查卡**，让 AI 未加载专家资产前也能快速检索到"有这个模块的知识 + 关键入口 + 去哪找详细"。**绝不缩水复制专家资产本体**（全量复制会造成双源漂移）。

## 写入 API

| API | 用途 | 关键参数 |
|-----|------|----------|
| `ki_store` | 简单文本向量存储（无分组） | `scope`（项目标识）、`text`、`tags` |

- **scope**：项目标识（与 expert-team 其他 ki 写入一致）

## 8 字段模板（每条极短，≤ 200 字）

```
【专题记忆｜{专家/专题业务名}】
- 资产路径：.module-experts/{专家/专题名}/（用 expert-lookup 加载详细资产）
- 一句话职责：{模块/专题是干嘛的（复述 agent.md/topic.md 职责）}
- 核心能力（≤5）：{最常被调用的公开能力名，指向 C1}
- 高频坑（≤3）：{最容易踩的坑：现象→正确做法（精筛 C0 已知坑）}
- 关键代码位置（≤5）：{最核心 类/方法 → 文件路径（implementation/ 路标）}
- 数据落地（如有）：{核心数据实体 → 去向（C4 摘要）}
- 检索触发词：{业务域词 + 常见问题词（与 INDEX 关键词呼应）}
- 详细资产：见 .module-experts/{名}/，契约层 C0~C4（怎么用）+ implementation/（怎么实现）
```

**字段填充来源**：逐条从已产出的专家资产提炼，禁止编造；任一字段为空则写「无」不硬凑。

## 维护规则（防双源漂移）

专题记忆是专家资产的**弱副本路标**，资产变更必须同步记忆：

- **新建专家/专题** → 写一条专题记忆
- **合并补全专家** → **更新**已有记忆的路标字段（核心能力/高频坑/关键代码位置/数据落地等），用同一 key 覆盖更新，不产生重复条目；无已有记忆则新建
- **重建专家** → **重写**记忆（删除旧记忆 + 写入新记忆）
- **删除专家** → **同步删除**对应专题记忆（或标记失效），不留僵尸记忆
- **关键约束**：记忆命中后跳转前，校验目标专家路径存在；路径失效则不做误导性跳转，回退正常查找

## 降级

ki 不可用（未配置 `ki_store` / 索引服务不可达）时，**跳过写记忆**，不阻塞专家落盘。
