# 接口信息策略参考（写入侧）

ki-memory-write 的「接口信息」策略细则。主流程见 SKILL.md。调用方为 expert-team（Step 8.3，识别专家模块的暴露接口后调用）。查询接口信息走 `use_skill("ki-memory-lookup")`。

## 定位

接口信息 = **子功能粒度的可检索原子**，记录「子功能 → 接口列表（API 路径 → 后端接口名 → 文件位置 → 职责）」，让 AI 查"某接口在哪定义 / 怎么调 / 谁提供"时直接命中，不必重新翻代码。与专题记忆（模块级路标）互补：专题记忆看模块**整体**，接口信息看模块**内**的子功能接口集合。

**适用场景**：
- 专家模块是**后端模块**（暴露 API 给前端）：记录暴露给前端的 API 路径 + 对应后端接口名
- 专家模块是**后台核心模块**（数据接收/消费）：记录核心数据接收接口 / 消费暴露接口

## 写入 API

统一用 `ki_bulk_sync_relation` 批量写入（与专题记忆、强关联同一 API，按 group 区分）。

| API | 用途 | 关键参数 |
|-----|------|----------|
| `ki_bulk_sync_relation` | 批量写入接口信息原子 | `scope`（项目标识）、`items[]`（每条含 `group`/`relation`/`module_info`/`tags`） |

- **scope**：项目标识（与 expert-team 其他 ki 写入一致）
- **group**：`接口信息/{功能模块名}`（父目录固定「接口信息」，子目录按功能模块名动态创建）
- **relation**：**子功能名**（同一子功能的接口集合共用一条 relation，如「订单创建」；不含特殊字符）
- **tags**：`api`（供查询侧用 `tags="api"` 过滤）
- **module_info**：该子功能下所有接口的列表（见下方字段模板）

## 字段模板（一个子功能 = 一条 relation，含多接口列表）

```
【接口信息｜{子功能名}】
- 子功能：{子功能名，如 订单创建}
- 所属模块：{功能模块名，关联到 group}
- 接口列表：
  - {API 路径 + 方法} → {后端函数/方法名} @ {文件路径}：{一句话职责}
  - {API 路径 + 方法} → {后端函数/方法名} @ {文件路径}：{一句话职责}
  - ...
```

**字段填充来源**：从专家资产的契约层（C1-能力契约.md）提炼公开接口，按**子功能**聚合；禁止编造；任一字段为空写「无」。

## 写入要点

- **子功能粒度**：同一子功能的接口集合共用一条 relation（如「订单创建」子功能含 POST/create、POST/batch 等多个接口，全部列在一条 relation 的 module_info 里），避免每个接口一条 relation 导致 relation 数量爆炸
- **批量写入**：子功能多时，用 `ki_bulk_sync_relation` 一次写入多条（单次 ≤ 50 条，超出分批），比逐条调 `ki_sync_relation` 快
- **tag 固定 `api`**：与强关联的 `relation` 区分，查询侧可用 `tags="api"` 精确过滤
- **职责一句话**：每个接口说清"干什么"，不要贴实现细节

## 降级

ki 不可用时跳过写接口信息，不阻塞专家落盘（与专题记忆/强关联的降级约定一致）。
