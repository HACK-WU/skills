# 数据流记忆策略参考（写入侧）

ki-memory-write 的「数据流记忆」策略细则。主流程见 SKILL.md。调用方为 expert-team（Step 8.4，识别专家模块的数据实体后调用）。查询数据流记忆走 `use_skill("ki-memory-lookup")`。

## 定位

数据流记忆 = **数据实体粒度的可检索原子**，记录「数据实体 → 生产方（谁写）/ 消费方（谁读）/ 业务用途」，让 AI 查"某张表/某个字段/某条消息是哪个模块写的、被谁读、干什么用"时直接命中，不必重新翻代码。与专题记忆（模块级路标）互补：专题记忆看模块**整体**，数据流记忆看模块**内**的数据实体流向。

**与 C4-数据流向与消费.md 的关系**：数据流记忆是 C4 的**可检索路标**——只存"实体 → 生产方/消费方 → 用途"的关键入口，详细消费逻辑（谁怎么处理）仍指向专家资产的 C4，不复制本体（对齐专题记忆"路标不复制专家本体"的原则）。

## 与其他记忆类型的边界

| 记忆类型 | 视角 | 记录口径 | 与数据流的边界 |
|----------|------|----------|----------------|
| 接口信息 | 对外接口契约 | 记"接口本身"（API 路径/方法/后端函数） | 接口信息记**接口**，数据流记**接口产生的数据落到哪张表/消息**。一个接口可能生产数据，但两者不重复：前者答"怎么调"，后者答"数据去了哪" |
| 强关联 | 模块间耦合 | 记"模块 A↔B 的契约耦合 + 方向/强度" | 同一"模块A写表X → 模块B读表X"的关系，数据流以**数据实体视角**记（围绕表X组织），强关联以**模块视角**记（围绕A↔B耦合组织）。二者可并存，口径不同，不视为重复 |
| 专题记忆 | 模块级路标 | 记模块整体职责/能力/入口 | 数据流看模块内数据实体流向，专题记忆看模块整体，粒度不同 |

## 写入 API

统一用 `ki_bulk_sync_relation` 批量写入（与专题记忆、接口信息、强关联同一 API，按 group 区分）。

| API | 用途 | 关键参数 |
|-----|------|----------|
| `ki_bulk_sync_relation` | 批量写入数据流记忆原子 | `scope`（项目标识）、`items[]`（每条含 `group`/`relation`/`module_info`/`tags`） |

- **scope**：项目标识（与 expert-team 其他 ki 写入一致）
- **group**：`数据流/{功能模块名}`（父目录固定「数据流」，子目录按功能模块名动态创建）
- **relation**：数据实体名（表名 / 消息主题 / 缓存 key / 数据结构名），不含特殊字符
- **tags**：`data`（供查询侧用 `tags="data"` 过滤）
- **module_info**：数据实体流向（见下方字段模板）

## 字段模板（一个数据实体 = 一条 relation）

```
【数据流｜{数据实体名}】
- 实体类型：{表 / 消息主题 / 缓存 / 文件 / 数据结构}
- 结构：{有明确表定义时记表名；无表定义时记数据结构示例，列出 3-5 个最关键的字段（用于检索识别的字段优先）}
- 生产方：{谁写入/产生这个实体，如 模块A.OrderService @ orders/service.py}
- 主要消费方：{谁读取/消费这个实体，如 模块B.PaymentHandler @ payment/handler.py；多个消费方用列表，精筛主要的即可，不穷举}
- 业务用途：{这个实体用来干嘛，一句话}
- 详细流向：见 .module-experts/{专家名}/C4-数据流向与消费.md
```

**字段填充来源**：从专家资产的契约层（C4-数据流向与消费.md）提炼；禁止编造；任一字段为空写「无」。

## 写入要点

- **粒度到表/数据结构，不逐字段**：字段可能十几二十个，逐字段记录会爆炸且难维护，记录到"表/数据结构"级别即可；字段级细节由 C4 承载
- **无表定义记结构示例**：消息、缓存 key、文件等无"表"概念的实体，记一个数据结构示例（3-5 个关键字段），让 AI 知道该实体长什么样
- **单实体粒度**：每个数据实体一条 relation，不合并多实体
- **tag 固定 `data`**：与接口信息的 `api`、强关联的 `relation` 区分，查询侧可用 `tags="data"` 精确过滤
- **路标式不复制 C4**：只存实体级生产/消费/用途入口，详细消费逻辑指向 C4，避免双源漂移
- **消费方精筛不穷举**：消费方是六类记忆里最易变化的（加消费者/改读取逻辑很常见），只记"主要消费方"，避免穷举导致记忆快速过时；消费方变化以 C4 为准，发现不一致时以代码/C4 为准

## 降级

ki 不可用时跳过写数据流记忆，不阻塞专家落盘（与专题记忆/接口信息/强关联的降级约定一致）。
