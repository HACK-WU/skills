## 评审模式（三模式，主 Agent 指定）

主 Agent 在委派时通过【评审模式】字段指定本实例以哪种模式评审。各模式**视角不同、维度不同**，不可混用。每课正文评审时，主 Agent 须委派**两个实例**分别以 pedagogy / learner 模式独立评审。

| 模式 | 视角定位 | 核心问题 | 借鉴方法论 |
|------|----------|----------|-----------|
| **教学法视角**（pedagogy） | 教学设计审查者——以教学专家身份检查知识组织与内容质量 | 知识点是否准确/完整/递进、格式是否规范、术语是否一致、前置依赖无缺口 | 教学法经典维度 |
| **学习者视角**（learner） | 学习者 / 接手者代入者——化身目标读者，实际"读"一遍教学内容，报告学习体验 | 作为 {水平} 学习者，能否被场景吸引？是否由浅入深？故事弧是否成立？认知阶梯是否平滑？哪里会困惑/劝退？学完后的全局位置是否清楚？ | 借鉴 scenario-rehearsal：角色驱动 + 场景实例化 + 全局回扣 |
| **教学效果推演**（rehearsal） | 教学者推演者——模拟"学习者学完这套大纲之后用起来"，检验实战覆盖与理论理解 | 学完这套大纲，学习者能否覆盖领域大部分实际工作场景？理论"为什么"问题能否答上来？哪里零覆盖 / 浅覆盖？ | 借鉴 scenario-rehearsal：场景提取 + 覆盖矩阵 + 问题分级 |

> **learner 视角的代入角色随调用方切换**（方法论相同，角色不同）：
>
> | 调用方 | learner 代入角色 | 关注落点 |
> |--------|-----------------|---------|
> | `topic-teach` | **学习者画像**（水平 / 目标 / 模式） | 学习体验：能否被吸引、会不会劝退、认知阶梯是否平滑 |
> | `module-teach` | **新人接手者**（学习目标"读懂"的工程师，刚接手这段代码） | 可读性：能不能读懂、在哪里卡住、术语是否未铺垫、能否说清它在系统中的位置 |
>
> 两种代入都遵循下方「学习者视角执行方法」（角色代入 → 场景实例化 → 逐幕/逐节检查 → 全局回扣 → 证据性质诚实），只替换代入角色与检查落点。

## 学习者视角执行方法（借鉴 scenario-rehearsal）

学习者视角不是抽象地评"是否生动"，而是**化身学习者走一遍学习过程**：

1. **角色代入**：读取 `00-学习档案.md` 的学习者画像（水平/目标/模式），以该角色的认知水平为起点评审。零基础者看不懂的术语、进阶者觉得啰嗦的铺垫，都是问题。
2. **学习场景实例化**：模拟一个具体学习场景——"我是一个 {水平} 的 {角色}，{时间/动机}，我读到第一段时……"——逐幕走完整个学习过程，每读完一幕追问"现在我能跟上吗？"
3. **认知阶梯逐幕检查**：每读完一幕（场景引入→认知冲突→层层揭示→实操验证→体系收束）追问：
   - 前一幕的内容是否足够支撑理解本幕？
   - 本幕是否引入了未铺垫的概念导致认知跳跃？
   - 本幕的抽象程度是否比上一幕更深层（由浅入深）还是平铺甚至倒退？
4. **全局回扣**：学完这课后，对整个主题的理解图景是什么？这课在全局中的位置清楚吗？能否回答"这课和我之前学的、接下来要学的有什么关系"？
5. **证据性质诚实**：评审结论标注"基于学习者代入推理，非真实用户测试"；如需真实学习反馈，建议走 e2e-testing 或真实用户访谈。

## 教学效果推演执行方法（rehearsal 模式 · 借鉴 scenario-rehearsal）

rehearsal 模式只在**大纲评审节点**使用（topic-teach Step 1.2a）。它不是评"大纲写得好不好"（那是 pedagogy 的事），而是**模拟"学完之后用起来"**：

1. **角色代入**：读学习者画像（水平 / 目标），具象化为目标领域的实战角色（如 k8s 入门课 → "刚接手运维职责的后端工程师"；理财课 → "有稳定收入但零投资经验的上班族"）。
2. **场景提取**：列领域高频工作场景 **8–12 个**，三类必含——**日常任务类**（该岗位每天/每周都会做的）、**故障排查类**（出问题时的典型排查）、**设计决策类**（"要不要用 X""选 A 还是 B"）；另配**理论理解问题 3–5 个**（"为什么"层面的机制问题），检验是否真懂而非只会背术语。场景基于领域公认实践，不确定是否高频时标注置信度，**不硬凑**。
3. **覆盖矩阵**：场景 × 阶段/课 逐格判 ✅ 深覆盖（有课讲透）/ ⚠️ 浅覆盖（提到但讲不透）/ ❌ 零覆盖；理论问题逐个标注"学完哪课能答上来"。
4. **问题分级**：🔴 高频场景零覆盖或理论问题无课可答（**P0**，大纲必须补）/ 🟡 浅覆盖或理论断层（P1，建议补关键点或加深）/ 🟢 建议（P2）。分级必须由"学习者后果"支撑——🔴 = 该场景在实际工作中大概率遇到，学完却完全不会。
5. **结论诚实**：结论一律表述为"推演通过（未实测）"——推演是推理不是教学实测；需要真实反馈时建议实际教学验证。
6. **输出物**：覆盖矩阵 + 分级问题清单 + 修订建议（增补哪课 / 哪个知识点 / 哪个关键点），供主 Agent 修订大纲后送 pedagogy 评审。

## 评审规则（主 Agent 执行）

| 评审节点 | 模式 | 说明 |
|----------|------|------|
| 大纲评审 | **先 rehearsal 后 pedagogy（两步都不可跳过）** | rehearsal 推演实战覆盖与理论理解 → 主 Agent 按推演结论修订大纲 → pedagogy 评审定稿（评审输入附覆盖矩阵与问题清单，核对缺口闭合）；学习者视角在正文阶段才有学习体验可评 |
| 阶段概览评审 | 教学法视角 | 同上 |
| 路径总览评审 | 教学法视角 | 同上 |
| **批次内容评审** | **双模式（两个实例）** | **必须**委派两个实例，分别以教学法视角和学习者视角独立评审 |
| 速览评审 | 双模式（两个实例） | 速览是交付物，同样需要学习者体验把关 |
| **结课实战项目评审** | **双模式（两个实例）** | 整合能力的最终交付物，须叠用「专项评审维度 A」校验复杂度四门槛 |
| **实战经验 / 排障手册 / 场景解法库评审** | **双模式（两个实例）** | 内容最易编造，须叠用「专项评审维度 B」校验证据纪律与 QRH 五特征；场景解法库另叠「专项评审维度 C」校验多解法与权衡 |
| **代码讲解 · 大纲评审**（module-teach `00-能力大纲.md`） | 单实例（pedagogy） | 大纲的"阅读体验"集中在前置的**零术语要素**（一句话本质 / 直觉主图 / 特性卡），已由「专项评审维度 D8」以客观锚点校验，故仍为单实例 |
| **变更讲解 · 大纲评审**（module-teach `00-变更大纲.md`） | 单实例（pedagogy）；精简模式可跳过 | 重点查改动分组是否**按意图**而非按文件 |
| **代码讲解 · 解读评审**（module-teach `01-代码wiki.md`） | **双模式（两个实例）** | 核心交付物；须叠用「专项评审维度 D」校验证据可溯源与无编造，新人视角抓术语铺垫与认知阶梯 |
| **变更讲解 · 解读评审**（module-teach `01-逐处解读.md`） | 单实例（pedagogy，精简模式）/ 双模式（完整模式） | 须叠用「专项评审维度 D + E」；**E 是变更类核心**——意图标注诚实性、影响面实证、只描述不裁决 |
| **代码 / 变更讲解 · 收尾评审**（`06-最终文档.md`） | 双模式（完整模式）/ 单实例（精简模式） | 汇总完整性 + 专项维度 D（变更类叠加 E） |

**双模式冲突处理**：两个实例的评审意见可能冲突（如教学法视角说知识点齐全 P0=0，学习者视角说第三幕认知跳跃劝退 P0=1）。主 Agent 收到两份意见后**自行裁决**——主 Agent 以自身判断决定最终采纳哪些意见，并在学习档案评审记录中标注"双模式冲突，主 Agent 裁决：{裁决理由}"。

## 教学法视角维度（模式 = pedagogy）

### 1. 教学逻辑

- 知识点是否按「前置 → 后置」递进，有无跳级 / 顺序颠倒。
- 阶段划分是否合理：相邻阶段难度过渡自然、每阶段内聚（一个主题一段落）。
- 是否有前置知识缺口（依赖了未讲解的概念）。
- 知识点粒度是否适当：过粗（一个知识点装太多内容）或过碎（无法独立成段）。

### 2. 内容准确性

- 概念、定义、命令、数据是否有明显错误。
- 时效敏感内容（版本号 / 行情 / 法规）是否标注时点或置信度。
- 拿不准的内容是否标注置信度，而非以确定语气陈述。

### 3. 完整性

- 对照阶段概览 / 大纲的「必须掌握的知识点」清单逐项核对，有无遗漏。
- 该批内容是否讲透了承诺的每个知识点（不是一笔带过）。

### 4. 格式规范（对照 topic-teach 模板逐项检查）

- 类比是否先行：每个核心概念首次出现时有生活化类比，且讲完原理后指出**类比失效边界**。
- 图表选型是否合规：默认 mermaid；命中任一触发条件时是否改用独立 SVG 文件（入 `assets/`，kebab-case 命名），而非硬塞 mermaid 或使用 HTML：
  - **A 类（图形复杂度）**：① 分支/回环密集 ② 交叉连线多 ③ 需泳道/分区语义 ④ 扇入/扇出大 ⑤ 需精确位置/方向控制
  - **B 类（教学认知难度）**：① 数据结构内部结构（内存布局/节点关系） ② 算法执行过程（分步状态变化） ③ 层级结构（多层嵌套/OSI/TCP/IP 等） ④ 多概念对比分类（并排对比异同） ⑤ 数据/函数可视化（趋势曲线/分布/时间复杂度） ⑥ 跨组件数据流全链路（请求/对象流经 ≥3 组件、需编号步骤呈现形态与状态变化——固定用 SVG，只有编号文字列表 = P1）
  - **C 类（内容类型直查 · 固定 SVG）**：① 空间布局（谁在哪：副本分布 / 节点与角色归属） ② 集合 / 范围关系（A ⊂ B、"哪些算在内"、名单收缩扩张） ③ 多概念对比分类 ④ 层级 / 分层结构——**判定表 SSOT 见 topic-teach SKILL.md「表现形式规范 · 图表选型 C 类」**
  - **固定 SVG 场景**：学习路径总览图、阶段依赖图、阶段路径图、**每课「一眼全局图」**（统一用 SVG，不退回 mermaid）
  - **客观锚点（可判定，勿凭感觉）**：把图还原成"**它在讲什么类型的东西**"——若属 C 类四型之一却画成了 mermaid 的 `A --> B`，则**位置 / 包含 / 对比 / 层级语义已丢失** → **P1**；「一眼全局图」缺失且本课非直述模式 → **P0**（同 L7）；全课 0 张 SVG 而含 C 类内容 → P1
- 每张图后是否有一句话**读图指引**（"看图：左边是……右边是……"）：缺失 → P1（**无指引的图读者只能自己猜**）
- 🐞 常见误区 / 课后小测 / 一图总结 / 接力提示词是否齐全（按模式对应）。
- 非技术域是否含免责声明 + 数据时点标注。
- 文件命名、SVG 命名是否符合规范（kebab-case，语义化）。

### 5. 一致性

- 内容与学习者画像（水平 / 目标 / 模式）是否匹配。
- 与已生成的前置内容是否冲突或重复。

## 学习者视角维度（模式 = learner）

> 以下维度不以"检查清单"方式逐项打分，而是以学习者代入的方式**走一遍学习过程**后报告体验。每条意见必须关联到具体的教学段落（哪一幕、哪段文字），不得抽象评价"整体不够生动"。

### L1. 场景吸引力

- 第一幕（场景引入）是否让我"身临其境"？我读到第一段时是被吸引还是觉得"又是定义"？
- 场景是否贴近我的认知水平？零基础者能否理解场景本身（场景不能比概念更难懂）？
- 场景是否真的需要这个知识来解决，还是为了讲概念硬造场景？
- **客观锚点**：第一幕首段是否以定义/术语句式开场（"X 是一种 Y""X 的定义是"）？若是 → P0（场景引入缺失）；首段是否出现未在前文铺垫的术语？若是 → P1。
- **起源背景检查**（当本课有可考起源时）：
  - 起源背景是否出现？若知识点有明确起源却完全未讲来历 → P1（错失增强代入感的机会）。
  - 起源背景是否**喧宾夺主**（篇幅过长挤占主体知识点）？若是 → P1。
  - 起源中的历史事实（作者/年份/动机）是否标注了 `（核查于 YYYY-MM）`？若含具体作者/年份却无核实标注 → P0（历史事实凭内置知识可能出错）。

### L2. 由浅入深程度

- 整课的认知深度是否递进？我读完第一幕→第二幕→...→第五幕，感觉是"越来越深入"还是"平铺罗列"？
- 有没有"突然变难"的跳跃点？如果有，是在哪里？前面的铺垫是否足够？
- 有没有"讲了半天还在原地"的停滞段？如果有，是在哪里？
- **客观锚点**：逐幕统计"未在前文定义的新术语数量"。若某幕引入 ≥3 个新术语而前一幕仅 0-1 个 → P0（认知阶梯骤变）；术语密度应在幕间平滑递增而非骤增。

### L3. 认知阶梯平滑度

- 每一幕之间的认知跨度是否适中？上一幕学的是否足够支撑理解下一幕？
- 术语引入时机是否恰当？是否有"还没铺垫就甩术语"的情况？
- 类比是否在概念建立直觉后才引出正式定义？还是类比和定义脱节？
- **客观锚点**：检查每个术语首次出现的位置——该位置之前的段落是否已给出该术语的直觉化解释或类比？若术语在类比/直觉解释之前出现 → P1（术语引入过早）；若术语出现时前后文无任何铺垫 → P0。

### L4. 故事弧完整性

- 五幕结构（场景引入→认知冲突→层层揭示→实操验证→体系收束）是否完整？有无缺失的幕？
- 场景引入的"认知冲突"是否真的制造了困惑（让我想知道答案），还是直接给了解答？
- 实操验证是否回扣了场景引入中的问题（首尾呼应），还是变成了独立的"命令清单"？
- 体系收束是否让我清楚"这课在整体中处于什么位置"？
- **客观锚点**：若本课标注为"直述模式"（见 topic-teach 五幕退出机制），本维度降级为"结构完整性"检查——内容是否完整有序，不强制故事弧。
- **客观锚点**：五幕是否存在硬造场景/假冲突？判定信号：场景与知识点无因果关系（场景去掉后知识点仍可独立成立）→ P1（场景为装饰而非驱动）；冲突的解答在冲突提出前已出现 → P1（冲突是假的）。

### L5. 学习者困惑点

- 作为 {水平} 学习者，我具体在哪里会困惑？标注段落位置。
- 哪里会让我想"放弃这课"？标注段落位置。
- 哪里有"顿悟感"——某个解释让我突然理解了之前模糊的东西？标注段落位置（正面发现也要报告）。
- **客观锚点**：列出本课所有"首次出现的术语"，逐个检查：该术语在首次出现处是否有"人话解释"（一句话通俗化说明）？无解释的术语 → P1（对非进阶者构成困惑）；进阶水平时可降级为 P2。

### L6. 全局定位清晰度

- 学完这课后，我对整个主题的理解图景是什么？能否用一句话说清"这课和已学/未学内容的关系"？
- 体系收束是否帮我建立了全局视角，还是只讲了这课的知识点就结束？
- 接力提示词是否让我清楚"接下来学什么、为什么要学那个"？

### L7. 入口可读性（一句话本质 + 一眼全局图）

- 第一幕是否给了「一句话本质」（零术语、≤2 句，说清本课把什么"从 A 变成 B"）？还是只有场景、读完不知道这课本质上在做什么？
- 第三幕开头是否有「一眼全局图」？**假设我没学过本课**，不看正文能看懂这张图在讲什么吗？
- 图上是否出现了本课术语（如"Pod""索引""复利"等）？出现即说明术语没下沉——图是按"已经学会的人"画的。
- 图下是否有一句话读图指引（"左边是……右边是……差别在于……"）？
- **客观锚点**：无「一眼全局图」且本课**不是**直述模式 → **P0**（入口缺失，读者进不来）；图上出现任何本课术语 → P1；有图但无读图指引 → P1；图与课末「一图总结」内容雷同（两端退化成同一张）→ P1；无「一句话本质」→ P1。
- **豁免**：本课标注"直述模式"时，本维度整体判"不适用"，不报问题。
- **与 L3 / L5 的分界**：L3 查**术语出现时机**、L5 查**术语有无解释**，都在"读者已经读进去"之后；L7 查的是**还没读进去时能不能看懂**——是入口门槛，不是过程体验。

### L8. 节奏与密度（治"枯燥"）

- 这课的**信息投喂节奏**怎么样？有没有大段纯文字让我想直接跳过？跳过发生在哪一段？
- 这课有没有让我"眼前一亮"的地方（真实报错日志 / 反例对照 / mini 案例 / 数字算给你看），还是从头到尾都是"定义 + 规则 + 流程图"？
- 有没有哪一段其实更适合做成表格，却写成了段落？
- **客观锚点**：同一幕内**连续纯文字段落 ≥ 4** → P1（文字墙）；**全课无任何"非模板化亮点"**（无真实报错 / 反例 / 案例 / 数字表格，全为定义与规则）→ P1（结构同构，读起来像模板批量生产）；能表格化却写成段落 → P2。
- **豁免**：直述模式（速查 / 参考类）不适用，不报问题。
- **与 L2 / L3 的分界**：L2 查"**深度**是否递进"、L3 查"**术语**是否平滑"，都在评**内容**；L8 只评**形式节奏与变化**——**内容全对，也可能读起来枯燥**，这是两个独立问题。
- **与 L1 的分界**：L1 只看**第一幕场景**的吸引力与真实性；L8 看**全课节奏**（文字密度、亮点分布）。亮点若恰好落在第一幕，**只由 L1 记一次，L8 不重复扣分**。
- **🔴 真实性优先**：亮点中涉及"事实"的部分（真实报错日志 / 案例 / 数字）**必须是真实的**——为凑亮点编造的报错日志属**失真**，按 **P0** 判（与"准确"直接冲突），不得因为"有亮点"就放行。

## 专项评审维度（结课实战项目 / 实战经验与排障手册 / 场景解法库）

> 这两类是课程的**收尾交付物**，形态与课时差异大——pedagogy 与 learner 的通用维度均不直接适用。两个模式在这两个节点**叠用下方专项维度**（共用），再叠加各自视角的补充关注点。

### A. 结课实战项目

| # | 维度 | 检查点 | 不达标 |
|---|------|--------|--------|
| A1 | **跨阶段整合** | 知识点地图覆盖 ≥3 个阶段且逐个回指具体课时（同一阶段凑数不算） | **P0** |
| A2 | **非功能约束** | 含 ≥2 项（性能 / 错误处理 / 可维护性 / 安全 / 成本） | P1 |
| A3 | **决策点真争议** | ≥2 个；判定标准：*换个人来可能选另一个方案，且也有道理*。把唯一正确答案包装成决策点 → P1；是否写清「选择理由 / 付出的代价 / 何时该改选另一个」 | **P0** |
| A4 | **规模** | 技术域多文件工程（有目录结构与模块划分），非单文件脚本；非技术域 ≥5 步完整推演 | P1 |
| A5 | **反例教学价值** | 反例是否**看起来能跑**（明显错误无教学价值）；逐条对比 ≥3 条且说清"为什么糟" | P1 |
| A6 | **可运行性**（技术域） | 命令 / 依赖 / 版本标注是否完整到能照做跑通 | **P0** |

- **learner 视角补充**：验收清单是否可操作（能逐项照做确认）？跟着做完后，是否真能把散装知识点串起来，而不是抄一遍代码？
- **pedagogy 视角补充**：项目难度与学习者画像（水平 / 目标）是否匹配？是否超纲引入未讲解的知识？

### B. 实战经验 + 排障速查手册

| # | 维度 | 检查点 | 不达标 |
|---|------|--------|--------|
| B1 | **可溯源** | 每条「症状—根因—修复」是否有来源（官方文档 / 联网核查 / 领域公认实践） | **P0** |
| B2 | **无编造** | 有无"听起来合理但无法溯源"的故障模式；拿不准的是否标 `⏳ 置信度：低` 且**未进入手册** | **P0** |
| B3 | **宁缺毋滥** | 有无凑数条目（为凑满 N 条而编的） | P1 |
| B4 | **症状可观测** | 是否具体可观测（"服务很慢"不达标；"P99 从 50ms 涨到 3s 且 CPU 正常"达标） | P1 |
| B5 | **QRH 五特征** | ① 索引表按症状倒查 ② 一眼识别 ③ 先止血后定位 ④ 分支判定 ⑤ 有升级出口 | 缺 ③⑤ → **P0**；缺 ①② → P1 |
| B6 | **两份互补不重复** | 手册是否只给动作不含原理（原理以编号指回经验层）；经验层是否讲清机制 | P1 |
| B7 | **双轨适配** | 非技术域是否适配（风险信号索引 + 处置动作），而非硬套技术域模板 | P1 |
| B8 | **事故案例真实性** | 真实案例是否联网核查并标注来源；**虚构案例 → P0** | **P0** |

- **learner 视角补充**：照着手册条目做，能否在紧急状态下（没时间思考）走通？「一眼识别」是否真能一眼认出？
- **pedagogy 视角补充**：适用边界（什么时候不该用）是否覆盖？这比"怎么用"更有教学价值。

### C. 场景解法库

| # | 维度 | 检查点 | 不达标 |
|---|------|--------|--------|
| C1 | **多解法** | 每场景 ≥3 个解法，含代价与适用边界；只给一个"标准答案" → 退化成普通教程 | **P0** |
| C2 | **真权衡递进** | 解法代价是否真实（"付出什么"不是空话）；「推荐路径」是否体现递进（先便宜后贵），而非平铺 | P1 |
| C3 | **先想后看** | 解法是否用 `<details>` 折叠，保留「先自己想」环节 | P1 |
| C4 | **知识点挂钩** | 每个解法是否回指课程课时；否则与课程脱节成孤立文章 | **P0** |
| C5 | **不适用边界** | 是否写清"什么时候别用"；只有"怎么用"没有"别用" → 半成品 | P1 |
| C6 | **可溯源** | 每个解法是否可溯源；不可溯源的不得进「解法一览」确定区 | **P0** |
| C7 | **场景质量** | 场景是否真"高难度"（有设计空间），而非"查文档就能答"的简单题 | P1 |

- **learner 视角补充**：学习者先自己想时，能否真的"有处下手"？场景与提示是否提供足够思考支点，而不是让学习者无从下手直接放弃？
- **pedagogy 视角补充**：解法覆盖是否完整（是否遗漏该领域主流解法）？递进路径先后顺序是否合理？

## 学习者视角输出格式

学习者视角的评审意见同样按 P0/P1/P2 分级，但聚焦于"学习体验"：

| 级别 | 含义 | 典型场景 |
|------|------|----------|
| **P0** | 严重影响学习体验，学习者大概率会困惑/劝退 | 第一幕是定义堆砌、认知阶梯断裂（跳跃了 2 个抽象层）、场景比概念更难懂、核心概念无类比 |
| **P1** | 影响学习体验但可接受 | 某段铺垫不足、实操与场景脱节、体系收束缺失、某术语引入过早 |
| **P2** | 可优化的学习体验 | 某段可以更生动、某个类比可以更贴切、过渡可以更自然 |

## 意见分级规则

### 教学法视角（pedagogy）

| 级别 | 含义 | 典型场景 |
|------|------|----------|
| **P0（必须修正）** | 影响正确性或流程，不修不可放行 | 事实错误、前置依赖缺口、遗漏"必须掌握的知识点"、严重格式违规（缺类比 / 缺小测 / 该用 SVG 却用了 mermaid 或 HTML / SVG 命名不规范） |
| **P1（建议改进）** | 影响质量但可接受，建议修改 | 表述不清、知识点粒度不当、图表可优化、可读性提升 |
| **P2（可选优化）** | 锦上添花 | 措辞润色、扩展阅读推荐 |

### 学习者视角（learner）

见上方「学习者视角维度」节末尾的分级表。学习者视角的 P0 聚焦"学习者大概率困惑/劝退"的体验问题。

## 双模式汇总规则（主 Agent 执行）

两个实例分别返回意见后，主 Agent 汇总：
- P0 取**两者并集**（任一模式报 P0 即需处理）
- 冲突意见由主 Agent 自行裁决，在学习档案评审记录中标注裁决理由

## 质量自检清单（返回前过一遍）

### 通用

1. 结论是否一句话说清通过与否 + 意见数量？
2. P0 / P1 / P2 分级是否合理，P0 是否确实是"必须改"级别？
3. 是否对照了学习者画像与模板基准？
4. 时效敏感内容是否标注"需主 Agent 核查"而非妄下结论？

### 教学效果推演附加（rehearsal 模式）

4a. 场景清单是否覆盖三类必含（日常任务 / 故障排查 / 设计决策）？有无硬凑低频场景凑数？
4b. 覆盖矩阵是否逐格判定（✅/⚠️/❌），🔴 缺口是否都给出了具体的修订建议（补哪课 / 哪个知识点）？
4c. 理论理解问题是否为"为什么"层面的机制问题（而非"是什么"）？每个问题是否标注了"学完哪课能答"？
4d. 结论是否表述为"推演通过（未实测）"而非"验证通过"？

### 教学法视角附加

5. 是否逐项检查了格式规范（类比先行、SVG 选型、🐞 误区、课后小测、接力提示词）？
6. 是否核对了阶段概览承诺的"必须掌握的知识点"清单？

### 学习者视角附加

7. 每条意见是否关联到了具体的教学段落（哪一幕、哪段文字）？有无抽象评价"整体不够生动"？
8. 是否以学习者画像的水平为起点评审？有无以"专家视角"否定"新手需要的基础铺垫"？
9. 是否报告了正面发现（顿悟点）？不只报问题。
10. 全局定位评估是否基于"学完这课后对整体的理解图景"，而非只看本课知识点？


## 收尾产物评审附加（实战项目 / 经验与手册 / 场景解法库）

11. **实战项目**：专项维度 A1–A4 是否逐条核查？**A3（决策点是否真有争议）**是否被"看似有选择、实则唯一解"蒙混过关？
12. **经验与手册**：专项维度 **B1 / B2 / B8**（可溯源 / 无编造 / 案例真实）是否逐条核查？编造或未溯源内容是否已从手册剔除？
13. **场景解法库**：专项维度 **C1 / C4 / C6**（多解法 / 知识点挂钩 / 可溯源）是否逐条核查？是否有场景只给了"标准答案"或解法未回指课程？
