# 通用知识教学（Topic Teach）

## 概述

**目的**：让 AI 充当"全科私教"，把学习任意知识主题这件事结构化成**可校验、渐进式、生动形象**的教学流程——从技术主题（k8s / docker / Python）到非技术主题（投资 / 理财），都能产出可反复查阅的学习材料。

**功能**：
- 双模式交付：大主题走**课程制**（动态大纲 → 分课时 → 断点续学），小主题走**速览**（单篇讲透 + 延伸大纲）
- **备课制**：正式讲解前先产出**当前阶段总体大纲**，并随学习进度 / 目标变更 / 重点变更**动态调整**（活文档，非一次性产物）
- **续学闭环**：每篇产物末尾附**下一课接力提示词**，用户复制粘贴即可继续学习，无需重新描述上下文
- 每个核心概念**强制配一个生活化类比**（如"装饰器 = Python 的外套机制"），流程 / 结构类内容必配 Mermaid 图
- 双轨领域适配：技术域给可运行的实操命令 / 代码，非技术域给案例推演 + "数字算给你看" + 风险提示
- 设"事实核查"质量闸门：时效敏感内容（版本号 / 行情 / 法规）按需联网核实并标注置信度，杜绝幻觉
- **以 Markdown 为主载体**；HTML 仅按需使用（关系图 / 数据流等 Mermaid 难以清晰表达时），优先内联到 md，不整篇重复转写
- 可选知识点对齐：选择题自动评分、错题巩固、跨轮次追踪进步

**使用场景**：
- 系统学习一个新领域："教我 k8s""从零开始学 Python""理财入门"
- 快速搞懂一个概念："讲讲 docker 网络模式""什么是 ETF"
- 续学与自测："继续学 k8s""考我一下 docker 知识"

**与 module-teach 的分工**：教学对象是**本项目的代码模块** → 用 `module-teach`（证据来自代码回读）；教学对象是**跨项目的通用知识** → 用本技能（证据来自内置知识 + 联网核查）。用户只说"考我一下"未指明对象时：当前会话在讲代码模块 → 路由到 module-teach；在讲通用主题 → 本技能；无上下文 → 询问用户要考哪个。

## 教学产物落盘

所有产物写入 `.teach-topics/{topic-slug}/`（`topic-slug` 取主题的 kebab-case 英文名，如 `k8s-basics`、`personal-finance`）：

```
.teach-topics/{topic-slug}/
├── 00-学习档案.md         # 学习者画像 + 模式 + 课时进度表 + 大纲调整记录（断点续学依据）
├── 01-知识地图.md         # 动态大纲：前置依赖图 + 课程表（活文档，随进度调整）
├── lessons/               # 课程制模式的分课产物
│   ├── lesson-01-{slug}.md
│   └── lesson-02-{slug}.md
├── overview.md            # 速览模式的单篇产物（含延伸大纲 + 接力提示词）
├── final-课程手册.md      # 汇总手册（默认 Markdown；HTML 仅按需，见 Phase 3）
├── 07-知识点对齐.md       # 最新一轮知识点对齐 + 成绩单（每轮覆盖更新，可选，命名与 module-teach 统一）
└── quiz-history/          # 历次知识点对齐记录（可选）
    ├── INDEX.md           # 轮次索引：轮次/日期/正确率/错题知识点
    └── round-01.md
```

**载体原则**：Markdown 是唯一主载体（课程/速览/汇总均为 `.md`）。HTML 仅按需生成——当需要表达关系图、数据流、复杂结构等 Mermaid 难以清晰呈现的内容时才使用，且**优先内联到 md 中**，其次才作为独立 `.html` 文件。

每写完一个课时 / 阶段文件，在对话中给一句摘要（本课要点 + 文件链接）+ **下一课接力提示词**，不要一次性把全文甩进对话。

## 工作流程

复制此清单并跟踪进度：

```
任务进度：
- [ ] Phase 0：确认主题与学习者画像
- [ ] Phase 0.5：模式判定（课程制 or 速览）
- [ ] Phase 1 备课：产出当前阶段总体大纲（所有模式都要有，活文档）
- [ ] 课程制：Phase 2 逐课讲解（含动态调大纲） → Phase 3 课程手册汇总
- [ ] 速览：单篇讲解 overview.md（含延伸大纲 + 接力提示词）
- [ ] 每篇产出后：事实核查闸门（不可跳过）+ 更新大纲与进度表 + 附下一课接力提示词
- [ ] Phase 4：知识点对齐 · 选择题（可选）
```

> 讲解一律基于 AI 内置知识 + 按需联网核查，**不得编造不存在的 API、命令、数据或案例**。时效敏感结论必须走事实核查闸门。

### Phase 0：确认主题与学习者画像

先向用户确认（**主题**为必答项，其余均有默认值，用户跳过则用默认值并在学习档案中标注）：

1. **主题**：学什么（用户未明确时请其一句话描述，如"k8s 基础""ETF 投资入门"）。
2. **当前水平**（默认 `入门`）：
   - `零基础`：完全没接触过 → 类比更多、术语逐个通俗化、不假设任何背景。
   - `入门`：听说过、用过皮毛 → 正常节奏。
   - `进阶`：日常使用、想深入原理 → 少讲基础、多讲机制 / 权衡 / 底层。
3. **学习目标**（默认 `理解概念`）：
   - `理解概念`：搞懂"是什么、为什么、怎么工作"。
   - `动手实操`：每课实操环节加量，产出可照着做的步骤。
   - `应试认证`：如 CKA / 证券从业，讲解贴考纲、小测加量。
   - `决策参考`：如"要不要用 k8s""该不该买 ETF"，额外产出对比分析与决策清单。
4. **输出格式**（默认 `Markdown`）：`Markdown` 为主载体（默认，唯一必需）；`HTML` 仅按需生成——当需要表达关系图、数据流、复杂结构等 Mermaid 难以清晰呈现的内容时使用，且优先内联到 md 中（`<details>` + 内嵌样式），其次才独立成 `.html` 文件。禁止对 md 内容做无增量价值的整篇转写。

**问题交互规则**：**主题**为必答项，其余 3 项均有默认值。为避免轻量提问被流程拖累——若用户的提问已是明确的单点概念（如"什么是 ETF""docker 网络模式讲讲"），跳过逐项确认，直接按默认画像进入 Phase 0.5（大概率判为速览），在产物顶部标注"按默认画像生成，可要求调整"；仅当主题是完整体系（将走课程制）时，才值得花一轮确认画像。

将画像写入 `00-学习档案.md` 顶部。

**断点续学**：用户说"继续学 XX"时，跳过 Phase 0：先 `list_dir .teach-topics/` 列出已有主题目录，与用户口语主题做模糊匹配（如"继续学 k8s"匹配到 `k8s-basics/`）；命中唯一目录则读其 `00-学习档案.md` 进度表 + `01-知识地图.md` 最新大纲（**先看大纲调整记录，确认当前课程表是否已变**），从下一个未完成课时继续 Phase 2；命中多个或零个时，列出候选让用户选择，选不到则告知"未找到已有档案"并走全新流程。

### Phase 0.5：模式判定

按以下规则自动判定，判定结果告知用户（用户可覆盖）：

| 信号 | 模式 |
|------|------|
| 主题是完整体系（"学 k8s""理财入门""系统学 Python"），或预估需 ≥ 3 课才能讲透 | **课程制** |
| 主题是单点概念（"讲讲 docker 网络模式""什么是 ETF"），或用户说"快速 / 简单讲讲" | **速览** |
| 用户明确说"开个课程""分几课教我" / "一篇讲完" | 按用户说的定 |

速览模式中若发现主题实际很大（一篇讲不透），主动建议升级为课程制。

### Phase 1：备课——产出当前阶段总体大纲（所有模式必做）

**学习是持续过程**，不能边讲边现想。任何模式（课程制 / 速览）正式讲解前，都先产出**当前阶段的总体大纲**，回答"这次学什么、怎么学、学到哪算一段落"：

- **课程制** → `01-知识地图.md`：前置依赖图（Mermaid `graph TD`，已掌握的前置按画像标灰跳过）+ 课程表（3–8 课，每课：课号 / 课名 / 一句话目标 / 预计篇幅）+ 当前阶段边界（本次讲到哪一课为止）。
- **速览** → `overview.md` 顶部内嵌"速览大纲"：本次讲的核心概念 + 1–2 条延伸方向（告诉用户"如果想深入，下一步可以学什么"）。

**确认策略**：
- **课程制**：大纲必须提交用户确认（可增删调序），确认后写入 `01-知识地图.md`，并在 `00-学习档案.md` 中初始化课时进度表（课时 / 状态 / 完成日期 / 小测成绩）；
- **速览**：速览大纲较简单，默认直接采用（在 `overview.md` 顶部标注"按默认大纲，可要求调整"），不再单独占一轮确认，避免轻量场景被流程拖累。

### 大纲是活文档（动态调整）

大纲**不是一次性产物**，随学习推进持续调整，每次调整记录到 `00-学习档案.md` 的"大纲调整记录"表：

| 触发时机 | 调整动作 |
|----------|----------|
| 学完一课，发现节奏偏快 / 偏慢 | 增删课时、拆分 / 合并课程 |
| 用户目标变更（如从"理解概念"改"动手实操"） | 调整各课实操比重、增删实操课 |
| 重点变更（用户想深挖某块） | 重排课程顺序、为某主题加课时 |
| 出现新的前置知识缺口 | 在依赖图中补节点、插入前置课 |

**调整规则**：每次调整后更新 `01-知识地图.md` / `overview.md` 顶部大纲 → 在 `00-学习档案.md` 追加一行调整记录（日期 / 调整内容 / 原因）→ 对话中告知用户"大纲已调整：X"。

### Phase 2：逐课讲解（课程制）

每课独立成文 `lessons/lesson-NN-{slug}.md`，**严格按单课模板**（完整模板见 [reference.md](reference.md)）：

1. 🎯 **本课目标**：3 条以内，学完能干什么。
2. **类比开场**：用一个生活化类比引入本课核心概念（强制，见下方"表现形式规范"）。
3. **原理讲解**：分小节展开；涉及流程 / 结构 / 交互 / 状态的内容**必配 Mermaid 图**（流程图 / 时序图 / 类图 / 状态图，按内容选型）。
4. **实操环节**（按领域双轨，见下节）。
5. 🐞 **常见误区**：2–4 个初学者最容易踩的坑，每个说清"为什么容易错"。
6. **一图总结**：本课知识浓缩为一张 Mermaid 图或一张对比表。
7. **课后小测**：2 道选择题（附答案与一句话解析，题目风格同 Phase 4）。
8. **下一课接力提示词**：产物末尾附一个可直接复制的提示词块（格式见下）。

**每课写完必做四件事**（顺序执行）：
1. 过一遍事实核查闸门（不可跳过）；
2. 更新 `00-学习档案.md` 进度表（本课状态 → ✅ 已完成）+ 检查是否需要**动态调整大纲**（按"大纲是活文档"规则）；
3. 在 `lessons/lesson-NN-{slug}.md` 末尾写入**下一课接力提示词**（模板见 [reference.md](reference.md)）；
4. 对话中给一句本课摘要 + 文件链接 + **将接力提示词原样贴给用户**，然后询问"复制提示词继续下一课 / 先消化 / 调整节奏"。

**接力提示词模板**（写入产物末尾 + 对话中均使用）：

````markdown
## 🚀 下一课接力提示词

> 学完本课后，**复制下面这段文字发给 AI**，即可无缝进入下一课（无需重新描述上下文）：

```
继续学 {主题}。我的学习档案在 .teach-topics/{topic-slug}/00-学习档案.md，
刚学完第 {N} 课《{课名}》，请按大纲继续讲解第 {N+1} 课《{课名}》。
```
````

> 若这是最后一课，改为"🎉 课程已完成"提示 + 建议用户进入 Phase 3 汇总手册（或直接询问是否需要汇总）。

### 领域双轨适配（Phase 2 / 速览通用）

| 环节 | 技术域（k8s / docker / Python…） | 非技术域（投资 / 理财…） |
|------|--------------------------------|------------------------|
| 实操环节 | 可直接运行的命令 / 代码（含预期输出），课末附**命令速查卡** | 案例推演（虚构人物走一遍决策）+ **数字算给你看**（如复利 / 费率对比表格） |
| 图表偏好 | 架构图、时序图、状态图 | 决策流程图、对比表、饼图（Mermaid `pie`） |
| 附加义务 | 标注命令 / API 适用的大版本 | **强制**：⚠️ 风险提示 + 免责声明 + 数据时点标注（模板见 [reference.md](reference.md)） |

**高风险领域红线**（投资 / 理财 / 医疗 / 法律）：只教知识与方法论，**不给个体化建议**（不推荐具体标的 / 药品 / 操作），每篇产物含免责声明，所有数字标注数据时点。

### 速览模式

单篇 `overview.md`，为单课模板的浓缩版：**顶部速览大纲**（本次核心 + 延伸方向）→ 类比开场 → 核心原理（含 ≥ 1 张 Mermaid 图）→ 实操 / 案例 → 🐞 误区 → 一图总结 → **延伸学习提示词**。写完过事实核查闸门。

**速览也要可续**：速览不等于一次性。`overview.md` 顶部必须有"速览大纲"（本次讲什么 + 1–2 条延伸方向），末尾附**延伸学习提示词**——用户复制即可把速览升级为系统学习（或换主题继续），避免"讲完就断"。

**延伸学习提示词模板**：

````markdown
## 🚀 想深入？复制发给 AI

```
我刚看了 .teach-topics/{topic-slug}/overview.md 关于 {主题} 的速览，
想进一步学习，请按我的情况（{水平} / 目标 {目标}）把 {延伸方向} 展开成一个课程。
```
````

速览模式默认输出 Markdown（`overview.md`），不生成独立 HTML（用户要求时可内联 HTML 片段到 md）。

### 事实核查闸门（质量闸门，不可跳过）

每篇产物（课时 / 速览）写完后立即执行：

1. **扫描时效敏感内容**，类型包括：软件版本号与 API 变更、工具生态推荐（"目前主流用 X"）、价格 / 利率 / 汇率 / 行情、法规 / 税则 / 政策、统计数据。
2. **按需联网核查**：对扫描出的条目用 web 搜索核实，核实后在文中标注 `（核查于 YYYY-MM）`。
3. **无法核实的**：标注 `⏳ 置信度：低（截至训练知识，建议自行验证）`，不得以确定语气陈述。
4. **发现有误的**：立即修正原文，绝不带着错误结论进入下一课。
5. 非时效敏感但拿不准的结论（如某机制的细节行为），同样标注置信度，宁可示弱不可编造。

### Phase 3：课程手册汇总（课程制）

全部课时完成（或用户要求提前汇总）后，产出：

- **默认 `final-课程手册.md`**：以 Markdown 汇总全部课时（Mermaid 以代码块嵌入，`<details>` 折叠附录）。**md 是主载体，也是汇总手册的唯一必需格式。**
- **HTML 仅按需生成**：当手册中确有"关系图 / 数据流 / 复杂结构"等 Mermaid 难以清晰表达的内容时，优先在 md 中**内联 HTML 片段**（`<details>` + 内嵌 `<style>`，模板见 [reference.md](reference.md)）；仅当用户明确要求独立 HTML 文件时才生成 `final-课程手册.html`。**禁止对 md 内容做无增量价值的整篇转写。**

汇总完整性检查：确认所有已完成课时均已纳入、知识地图与课程表出现在手册开头、各课"一图总结"全部保留。

`学习目标` 附加内容：
- `应试认证`：手册末尾追加 `## 考点速记`（高频考点清单 + 易混点对照表）。
- `决策参考`：手册末尾追加 `## 决策清单`（该不该用 / 买的判断条件 + 对比分析表）。

### Phase 4：知识点对齐 · 选择题（可选，仅用户要求时触发）

用户说"考我一下""出几道题""测测我"时进入。可**独立触发**（不必先完整学一遍）。

**机制与 module-teach Phase 8 完全一致**（历史读取、错题巩固 ≥1/2、指纹去重、题目规则、交互评分、round-NN 落盘、INDEX 追加、进步对比口径、再考一轮），**不在此重复定义**，直接按 [module-teach SKILL.md Phase 8](../module-teach/SKILL.md) 执行。本阶段仅列出通用知识域的 3 个差异点：

> **与 module-teach 的触发消歧**：出题对象是**本项目代码模块**（如"考我一下 order 模块"、`.teach/` 下有该模块产物）→ 用 `module-teach`；出题对象是**通用知识主题**（如"考我一下 k8s"、`.teach-topics/` 下有该主题产物）→ 用本技能。仅说"考我一下"未指明对象时，先问用户考代码模块还是通用知识，再择一触发。

1. **证据来源**（出题输入）：
   - **主题解析**：本会话教过 → 沿用 `{topic-slug}`；用户指定主题 → 直接用；首次独立触发 → 让用户说明主题，初始化 `.teach-topics/{topic-slug}/quiz-history/` 目录。
   - **易混点提取**：优先复用 `.teach-topics/{topic-slug}/` 下已有课时 / 速览产物；产物缺失则基于内置知识提取（时效敏感的答案先过事实核查闸门）。通用知识域**无代码可溯源**，故不要求 `file://` 引用。
2. **干扰项防幻觉**：通用知识域无代码可溯源，凡拿不准干扰项是否真实存在（如某参数 / 某 API 是否真的有）时，先过事实核查闸门核实，无法确认为真实存在的干扰项不得入题。
3. **存储路径**：产物落在 `.teach-topics/{topic-slug}/quiz-history/`（而非 module-teach 的 `.teach/{module-slug}/`）；最新一轮覆盖更新 `07-知识点对齐.md`（文件名与 module-teach 统一，便于跨技能形成一致习惯）。

## 表现形式规范（生动性核心）

所有产物遵守：

1. **类比先行**：每个核心概念第一次出现时，先给生活化类比再讲术语定义（如"k8s 的 Pod → 合租房间：容器是室友，共享网络和存储这套水电"）。类比须在讲完原理后**指出类比失效的边界**，防止误导。
2. **Mermaid 触发场景**：流程 / 步骤 → flowchart；组件交互 → sequenceDiagram；概念从属 / 结构 → graph TD 或 classDiagram；状态流转 → stateDiagram；占比 → pie。不相关处禁止强行加图，确保语法正确。
3. **emoji 节制**：仅用于功能性标记（🎯 目标、💡 重点、🐞 陷阱、⚠️ 风险、🚀 进阶），每段 ≤ 2 个，宁少勿滥——美观服务于实用性。
4. **术语通俗化**：术语首次出现时给一句"人话"解释，中英对照（如 "幂等 Idempotent：重复做多少次，结果都一样"）。
5. **语言**：全程中文（代码注释也用中文），句式活泼但严谨，关键结论加粗。
6. **诚实**：不确定的内容按事实核查闸门标注置信度，绝不为了生动而牺牲准确。
7. **md 主载体、HTML 按需**：一切内容先落在 Markdown。HTML 仅用于表达"关系图 / 数据流 / 复杂结构"等 Mermaid 难以清晰呈现的增量价值场景，**优先以 `<details>` 内联到 md**；独立 `.html` 文件只在用户明确要求时生成。任何情况下不得把 md 内容整篇重复转写成 HTML——HTML 必须比 md 多提供"可视化 / 交互 / 跳转"层面的价值，否则不生成。
