# 代码优化类 推演策略

## 概述

**目的**：不改变外部行为，提升性能/可读性/可维护性，验证行为等价性、性能提升、复杂度评估和意外场景概率

**功能**：
- 验证优化前后外部行为是否完全一致
- 评估性能提升的可信度和度量方法
- 检测复杂度是否真的降低而非转移
- 推演优化可能引发的意外场景和性能退化

**使用场景**：
- 当推演对象涉及代码优化、重构、性能提升时
- 当需要评估优化的行为等价性和性能提升时
- 当需要推演优化可能引发的意外场景时

## 精选验证维度（从通用维度表精选）

| 维度 | 本 profile 重点关注点 |
|------|----------------------|
| 行为等价 | 优化前后外部行为是否完全一致（接口/输出/副作用） |
| 性能提升 | 声称的性能提升是否有度量数据？度量方法是否可信？ |
| 复杂度 | 认知复杂度是否真的降低？是否只是换了一种复杂？ |

## 加压点（在通用维度上额外深挖）

- **行为等价性证明**：优化前后行为是否真的完全一致？有无隐蔽的行为变化？
- **性能度量可信度**：声称的性能提升是否有数据支撑？度量方法是否科学？
- **复杂度转移**：是否只是将复杂度从一个地方转移到另一个地方？
- **维护成本**：优化后的代码是否真的更易维护？还是引入了新的理解门槛？
- **回退风险**：优化是否容易回退？是否有回退机制？
- **意外场景概率评估**：优化后是否可能在某些特殊场景下出现性能退化？

## 典型异常/边界清单

- 性能退化而非提升
- 行为变化导致功能异常
- 复杂度转移而非降低
- 维护成本反而增加
- 优化引入新的 bug
- 优化后代码可读性下降

## 意外场景推演

在推演过程中，重点关注以下可能意想不到但有一定概率出现的场景：

1. **性能退化场景**：优化在某些特定数据或场景下可能导致性能退化
2. **行为变化**：优化可能引入微妙的行为变化，影响现有功能
3. **资源消耗变化**：优化可能改变内存、CPU、网络等资源消耗模式
4. **并发行为变化**：优化可能改变并发场景下的行为特性
5. **兼容性影响**：优化可能影响与其他系统的集成
