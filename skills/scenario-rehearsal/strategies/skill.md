# Skill 推演策略

> 适用特征：推演对象是 Agent Skill（SKILL.md 文件）
> 启用信号：输入包含 SKILL.md 文件，或用户明确要求推演 skill

## 验证维度（skill 质量全集）

| 维度 | 验证问题 | 严重度 |
|------|---------|:------:|
| **触发准确性** | skill 的 description 是否准确描述了触发场景？AI 能否根据 description 正确判断何时应用此 skill？ | 🔴 |
| **指令完整性** | skill 的指令是否完整、清晰、可执行？是否包含必要的步骤、工具使用说明、边界条件处理？ | 🔴 |
| **示例质量** | skill 的示例是否具体、有帮助？是否覆盖了典型使用场景？示例是否可直接复用？ | 🟡 |
| **工作流合理性** | skill 的工作流是否合理、可执行？步骤之间是否有逻辑依赖？是否有冗余或缺失的步骤？ | 🟡 |
| **资源完整性** | skill 引用的资源文件（reference.md、examples.md、scripts/）是否都存在？引用路径是否正确？ | 🟡 |
| **AI 说明层** | skill 是否包含完整的 AI 说明层（目的、功能、使用场景）？说明层是否简洁、准确？ | 🟡 |
| **结构规范性** | skill 是否符合标准结构（YAML 前置元数据、AI 说明层、Markdown 正文）？文件命名是否规范？ | 🟢 |

## 加压点（深挖方向）

1. **触发歧义**：skill 的 description 是否可能与其他 skill 产生冲突？是否覆盖了所有预期的触发场景？
2. **指令模糊性**：skill 的指令是否存在歧义？是否依赖隐含假设？是否明确说明了边界条件和异常处理？
3. **示例覆盖度**：skill 的示例是否覆盖了主要使用场景？是否包含边界情况和异常场景的示例？
4. **工作流完整性**：skill 的工作流是否涵盖了完整的任务生命周期？是否有明确的输入/输出定义？
5. **依赖关系**：skill 是否依赖其他 skill 或外部工具？依赖关系是否明确说明？
6. **可维护性**：skill 的结构是否易于维护和扩展？是否有清晰的章节划分？

## 典型缺口（skill 推演高频问题）

- description 过于模糊或过于具体，导致触发不准确
- 指令缺少必要的步骤说明，依赖 AI 自行推断
- 示例过于简单，无法展示 skill 的实际使用场景
- 工作流缺少异常处理和边界条件说明
- 资源文件引用路径错误或文件缺失
- AI 说明层不完整或与 description 重复
- 结构不规范，缺少必要的章节（如概述、指令、示例）

## mermaid 提示

- 工作流推演 `flowchart TD`：节点=skill 工作流步骤，标注验证结果
- 触发场景 `sequenceDiagram`：用户输入→AI 判断→skill 应用 时序
- 问题分布 `pie`：各维度问题占比

## 问题分类（skill 特有）

| 分类 | 说明 | 处理建议 |
|------|------|---------|
| **触发问题** | skill 的 description 无法准确触发 | 修改 description，增加触发术语 |
| **指令问题** | skill 的指令不完整或模糊 | 补充指令步骤，明确边界条件 |
| **示例问题** | skill 的示例不具体或不完整 | 补充具体示例，覆盖主要场景 |
| **工作流问题** | skill 的工作流不合理或缺失 | 重新设计工作流，补充必要步骤 |
| **资源问题** | skill 引用的资源不存在或路径错误 | 修正路径或创建缺失的资源文件 |
| **结构问题** | skill 不符合标准结构 | 调整结构，符合规范 |
