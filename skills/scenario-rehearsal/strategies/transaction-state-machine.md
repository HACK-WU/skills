# 事务/状态机类 推演策略

> 适用特征：有状态流转、跨步事务、需一致性/补偿保证
> 启用信号：状态机/状态流转/订单/支付/审批流/事务/补偿/对账

## 精选验证维度

| 维度 | 本 profile 重点关注点 |
|------|----------------------|
| 决策可行性 | 状态机设计是否覆盖所有业务跳转；事务边界划分是否合理 |
| 异常覆盖 | 部分失败/超时/中断的回滚或补偿策略 |
| 幂等性 | 重复支付/重复下单/重复回调是否幂等 |
| 数据完整性 | 状态字段约束；对账一致性 |

## 加压点

- **非法状态跳转**：是否存在绕过状态机的路径（直接改库/并发跳转）
- **部分失败与补偿**：跨服务事务某步失败，补偿是否可逆、是否幂等、是否有超时兜底
- **超时未决状态**：支付/订单长时间未回调，状态如何推进（主动查询？定时兜底？）
- **对账一致性**：资金/库存对账能否发现差异，差异如何处理
- **并发状态变更**：两个请求同时推进状态，是否用乐观锁/状态前置条件保护

## 典型异常/边界清单

- 重复支付/重复下单
- 状态卡死（无法推进也无法回滚）
- 补偿失败导致数据不一致
- 对账差异无处理流程
- 并发状态变更导致非法跳转

## mermaid 提示

- `stateDiagram-v2`：状态机全貌，标注非法跳转风险点
- `sequenceDiagram`：跨服务事务时序，标注补偿/回滚分支
