# project-atlas 参考手册

> SKILL.md 讲"按什么顺序做"，本文件讲"每一步怎么判断"。所有体积/覆盖率数字均为本仓库实测（kisearch，2 视图 7 节点试跑），不是估算。

## 一、视图策划（阶段 1.1 的选题方法）

### 1.1 挑选判据

一个视图成立的条件是**读者会反复问同一个问题**。三条硬判据：

| 判据 | 通过 | 不通过 |
|---|---|---|
| 一个问题 | "一次导入经过哪些环节" | "系统架构"（太宽，什么都能塞） |
| 图上节点可数 | 6–13 个组件（实测 6 图分布：6/6/7/7/10/13） | 30+ 组件（读者看不清，应先拆分类） |
| 能配解读 | 至少 3 条"怎么读" | 只能写一句"这是架构图" |

**不要按目录画图**：代码里有 12 个目录 ≠ 该出 12 张图。按"读者的问题"选题，一个分类通常 1–3 张。

### 1.2 默认四类模板

| 分类 | 视图 | 图种 | 问题模板 |
|---|---|---|---|
| 架构总览 | 运行时架构 | `architecture` | 这个系统由什么组成，谁和谁相连？ |
| 核心链路 | 每个主流程一张 | `sequence` / `workflow` | 一次 {操作} 到底经过哪些环节？ |
| 后台进程 | 调度 / 索引 / 备份 | `architecture` | 哪些东西在我没操作时也在跑？ |
| 配置与环境 | 配置项地图 | `tree` | 想改行为，该动哪一个配置段？ |
| 数据流转（按需） | 某模块数据进出 | `dataflow` | 数据从哪来、到哪去、谁消费？ |

**按项目类型裁剪**：

| 项目类型 | 优先 | 省略 |
|---|---|---|
| 后端服务 | 架构总览 + 核心链路 + 后台进程 + 配置 | 数据流转（并入架构图） |
| 前端应用 | 组件树 + 请求链路 + 状态流 | 后台进程、配置（通常无） |
| CLI / 库 | 架构总览 + 主命令链路 | 后台进程、配置地图 |
| 单体大仓 | 先出一张总览，其余用 `scope: module` 分模块另出 | 一页装 20 张图 |

### 1.3 典型示例（kisearch）

```
架构总览（1）  运行时架构 ── 三种入口汇到 daemon，kb/ 才是原始数据
核心链路（3）  一次搜索 / 数据源同步与导入 / 为什么删了还能搜到
后台进程（1）  调度器 + 索引优化 + 备份，同落在 zvec/fts/kb
配置与环境（1）config.json 的 llm / embedding / mcp / scopes 四段
```

6 张图 / 4 个分类 / 49 个节点，其中 19 个可挂代码（38.8%）——**覆盖率不用追求 100%**，剩下的画成概念节点反而更诚实。

## 一·五、分批并行（大项目）

### 并行判据

| 条件 | 阈值 | 不满足时 |
|---|---|---|
| 视图数 | ≥ 6 | 串行——少于 6 张，协调成本大于收益 |
| 可独立摸清的模块 | ≥ 3 | 串行——分不出块就没法分派 |
| 子 agent 数 | `min(模块数, 4)` | — |

**只并行阶段 0（摸底）和阶段 2（出图）**。阶段 3–6 全依赖前置产物，拆开只会制造等待。

### 子 agent 的输入输出契约

**摸底 agent**

| 项 | 内容 |
|---|---|
| 输入 | 模块名 + 入口猜测 + 仓库路径 |
| 输出 | 事实卡 JSON（`module` / `entry` / `symbols` / `deps` / `flows` / `risks`） |
| 禁止 | 写任何文件（只回文本） |

**出图 agent**

| 项 | 内容 |
|---|---|
| 输入 | ① 自己的模块事实卡 ② `.atlas/dict.json`（**只读**）③ 样板页的产出 |
| 输出 | 只写自己那页的 `nav/<分类>/<页面>.json` + `views/{pid}-{n}.svg` |
| 禁止 | 写 `atlas.config.json`（单文件并发覆盖）、写 `.atlas/dict.json`（词典由主 agent 独占）、写 `snippets.json`（脚本产物）、写别人的页面文件、使用词典外的节点 id |

### 合并流程（主 agent）

```
① 收齐 nav/ 下所有页面文件
② 词典校验：出现 id ∉ 词典 → 打回该 agent 重做（附越界清单）
③ 回填词典的 pages：每个 id 出现在哪几页（主 agent 独占写，agent 不碰）
④ collect_snippets.py（一次采集全部）
⑤ check_atlas.py（三方对齐 / 契约 / 衔接关系）
⑥ 不合格项按页归因，只回给对应 agent
```

**按页归因**是关键：check 报 `import/图 1 缺图源` 时，只有出这页的 agent 需要改，不要全员返工。

### 冲突处理

| 情况 | 处理 |
|---|---|
| 两个 agent 给同一组件起了不同名 | 以词典为准，改方返工 |
| 两个 agent 都声称同一条跨模块链路 | 按入口归属（发起方模块），另一个删掉只留引用 |
| 某页需要词典外的新组件 | 申请入典 → 主 agent 加进字典 → 通知相关 agent 重跑 |
| 词典里改了 id 或合并了同义项 | **受影响页全部重出图**（该 id 在 `pages` 里指向哪些页，那些页返工）——改词典不是纯本地操作 |
| 图源要跨页复用（同一 SVG 被两页引用） | 先串行出图，再分派挂配置 |

### 不适用并行的场景

- **单页多图**：同页所有 figure 在一个 json 文件里，拆开必冲突——**分片单位是页，不是图**
- **增量修改**：只改一两页时，并行反而多一轮协调
- **图源强耦合**：几张图共用同一份布局基准，先串行做出来再分派

> 任务派发的执行机制见 `task-dispatch`；切给跨会话并行的切片法见 `delivery-slicing`（"目录互斥、契约只读"，本 skill 的词典就是那份契约）。

## 二、配置字段细则

### 2.1 顶层字段（站点：标题 / 大纲 / 层级）

| 字段 | 必填 | 约束 | 常见错误 |
|---|---|---|---|
| `title` | ✅ | 页面主标题（hero 的 h1） | 写成路径 |
| `subtitle` | - | hero 上方的小字说明 | 写成长句导致 h1 折行 |
| `intro` | - | 首页导语 | 写成长段落 |
| `notice` | - | 首页提示条（可解释交互规则） | 写成营销语 |
| `baseline` | ✅ | 生成时 commit | 写分支名 |
| `generated_at` | ✅ | `YYYY-MM-DD` | 与 commit 时间混淆 |
| `views_dir` | - | 图源目录，默认 `views` | 写绝对路径 |
| `pages` | ✅ | 每页配置对象，键名即 `nav[].page` | 写成数组 |
| `nav[]` | ✅ | `id` / `name` / `q`，加 `children[]` 或 `page` | 两者都缺 → 该分类无页可点 |
| `nav[].children[]` | - | 子节点数组，**可继续嵌套任意深度** | 子节点既无 `children` 又无 `page` |

> `nav` 是任意深度的树：节点有 `children` 即分组，可继续嵌套；没有 `children` 的必须有 `page`。
> 侧栏缩进随深度自动增加（每层 12px），面包屑显示完整路径。

**折叠规则**（深目录的必备）：

| 规则 | 说明 |
|---|---|
| 默认折叠深度 | **第 3 层及更深的分组默认折叠**（`DEFAULT_COLLAPSE_DEPTH = 2`），1–2 层始终展开 |
| 当前路径自动展开 | 打开某页时，它路径上的分组全部展开；用户手动折叠的同级分组不受影响 |
| 手动切换 | 点分组标题展开/折叠，箭头 `▾` / `▸` 指示状态；只重绘侧栏，不重载图 |
| 当前页在折叠支里 | 被折叠的分组若包含当前页，标题与箭头转为强调色（`has-cur`），提示"页在这一支里"，不自动展开（尊重用户折叠） |
| 状态生命周期 | 仅当前会话内存有效，刷新后回到默认（不落 localStorage，避免"状态漂移"） |

### 2.2 `pages[id]`（每页：图源 / 解读 / 代码）

| 字段 | 必填 | 约束 | 常见错误 |
|---|---|---|---|
| `title` | ✅ | 页面标题 | 与 nav 名重复 |
| `summary` | ✅ | 一段话说明这页讲什么 | 复制 `points` 首条 |
| `docs` | ✅ | 相关文件路径 | 写目录 |
| `figures[]` | - | 一页多图。不写则把页级 `type`/`svg`/`points` 当单图 | 漏 `id` 或 id 重复 |
| `figures[].id` | ✅（多图时） | 本页唯一——跨图关联与图源 key 都靠它 | 用序号 `1`/`2`，改序即失配 |
| `figures[].name` / `q` | - | 图名 / 这张图回答什么问题（多图建议都给） | 两张图 `q` 写成同一个问题 |
| `figures[].svg` | - | 默认第 1 张 `views/{pid}.svg`、其后 `views/{pid}-{n}.svg` | 指向 archify 原文件名 |
| `figures[].points` | ✅ | **每张图** ≥3 条 `[标题, 说明]` | 只给第一张写解读 |
| `figures[].interactive` | - | 交互版 HTML 外链（`pack_atlas.py` 会一并收拢） | 文件不存在（check 会 warning） |
| `type` / `svg` / `points` / `interactive` | - | **单图简写**，等价于只有一个 `figures[0]`。两者都写时以 `figures` 为准 | 同时写两套且内容不一致 |
| `code[]` | - | **页级一维**：同一 id 在多张图之间共用一段代码 | 漏了 → 整页不可点 |
| `code[].id` | ✅ | 等于**本页任一**图源的 `data-node-id` | 用序号或中文 |
| `code[].file` / `lines` | 三选一 | `lines: [起, 止]`，1-based 闭区间 | 与 `concept` / `external` 同时出现 |
| `code[].why` | ✅（有代码时） | 一句"为什么看这里" | 写"核心逻辑"这类空话 |
| `code[].concept` | 三选一 | `true` = 概念节点（**仍可点**，给"无源码 + 相关文件"） | 给概念节点硬编行号 |
| `code[].external` | 三选一 | `true` = 外部服务：需 `owner` + `contract`；`returnsTo` 落回本页内部节点，或 `oneWay: true` | 编一个不存在的外部服务 |
| `links[]` | - | 衔接关系（见 2.4）：`from`/`to` 必须是本页 `code[]` 里的 id | 指向不存在的节点 |
| `site.externals` | - | 外部服务字典（按 id），页面只写引用 | 同一服务在多页各填一份 |

**节点 id 用语义 slug**（`daemon` / `domain` / `kb`），不要用 `node-1`：三方对齐校验、后续增量、人工核对全靠它。

### 2.3 三方对齐（唯一必须记住的约束）

```
atlas.config.json  nav[].page  ──指向──▶  pages 里的键
pages[].code[].id            ──必须等于──▶  本页任一 figures[].svg 里的 data-node-id
pages[].code[].file          ──采集──▶  snippets 的 key（同 id）
pages[].links[].from / to    ──必须存在──▶  本页 code[] 里的 id
pages[].code[].external      ──补齐──▶  site.externals 里同 id 的契约字段
```

任一处对不上，`check_atlas.py` 都会报出来（见第五节）。多图时"节点对齐"按**页级并集**判定——一个 id 只要在任意一张图里出现就算对齐，因为它可能本来只在第 2 张图上。

### 2.4 一页多图与外部节点

**一页多图的唯一理由是「必须同屏对照」**——通常是两种坐标打架：空间归属（architecture）说不清时序，时序（sequence）说不清归属。

| 场景 | 做法 |
|---|---|
| 两个问题、各问一件事 | 拆成两页（nav 本来就支持分组） |
| 同一功能的两个视角，读者要交叉参照 | 一页多图 |
| 一张图 8 个节点以内就说得清 | 不要多图 |

**四条硬约定**：

1. `figures[].id` 本页内唯一——跨图关联与图源 key（`pid::figId`）都靠它
2. 每图 ≥3 条解读；**代码表整页合并**（同一组件不要在图 1 图 2 下面各列一遍）
3. 每图独立失败态：一张图 404 只在该图位置报路径与原因，不拖垮同页其他图
4. 第 1 张图的 template key 沿用 `pid`（兼容旧 `tpl_pattern`），其后为 `pid::figId`

**跨图同 id 共享一份代码**：`code[]` 是页级一维，`snippets[pid][nodeId]` 也是一维，这是有意的——同一个组件在不同视角下就是同一个东西。**不支持"按图覆盖行号"**（片段表一维、抽屉按 id 查找，覆盖会静默失效）；确实需要两段代码就用两个 id（`zvec-write` / `zvec-read`），代价是图上要分开命名。

**外部节点**（`external: true`）三个字段：

| 字段 | 必填 | 作用 |
|---|---|---|
| `owner` | ✅ | 谁负责。缺了读者不知道该找谁 |
| `contract` | ✅ | 怎么交互（协议 / topic / 幂等语义） |
| `returnsTo` | ✅，或 `oneWay: true` | 回程落在本页哪个**内部**节点 |

- `returnsTo` 指向另一个外部服务 = 假闭环（出去又出去，没回来），`check_atlas.py` 会拦
- 只发不收的链路（日志上报、埋点）标 `oneWay: true`——显式声明比编一个假回程好
- 契约写在 `site.externals` 字典，页面只留引用；否则同一服务在 N 页各填一份，改一处忘一处
- **外部信息没有唯一真源**：代码变了能重跑脚本，外部服务改名/下线不会通知你。这是整套图集里唯一必须人工定期复核的部分——所以只到契约粒度，不画它内部的多跳

**衔接关系**（`links[]`）——"闭环"还差一层：两头靠**什么**对上。

`data_id` 这类标识符是**边**的属性，不是节点的属性。所以它在图上看不出来（箭头只表示"有连接"），必须结构化：

| 字段 | 说明 |
|---|---|
| `from` / `to` | 本页 `code[]` 里的 id；悬空即报错 |
| `carries` | 传的是什么；`identifier` 必填（标识符得有名字） |
| `kind` | `identifier` / `event` / `status` / `none` |
| `shape` | 形态（`string(32)`、`uuid`），便于对接 |
| `storedAt` | 标识符存在哪——**最容易漏的一格** |
| `cardinality` | `1:1` / `1:N`（一次批量导入返回 N 个 id） |

**判据：只有「能被别人拿去做下一次查询或定位」的返回值才是衔接键。**

| 场景 | 返回 | 算不算 |
|---|---|---|
| 写 MySQL | 成功 / 失败 | ❌ 是本次操作的结果，不是下次操作的入口 |
| 写日志 / 埋点 | 无返回 | ❌ 单向，没有下游需要定位它 |
| 写 ETL 平台 | `data_id` | ✅ 后续查询 / 对账 / 删数据都靠它定位同一条记录 |

`status` / `none` 的边**记录但不展示**（表格里折叠成一行）——不是漏掉，是需要时能查。

**一个标识符有四个时刻，少一步链就断**：

```
① 生成   ETL 写入成功 → 返回 data_id
   ▼
② 传递   回调请求体带着它回来
   ▼
③ 消费   用它查详情 / 做对账 / 写下一跳
   ▼
④ 持久化 存在哪？ scope_meta.remote_id        ← 最容易漏
```

第 ④ 步只活在内存里，进程重启后这条记录就永久对不上——**图上看还是闭环，实际已经断了**。这就是 `storedAt` 缺失要告警的原因。

**三种承载，按需组合**：

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **图下表格** | `links[]` 自动渲染（无需额外配置） | 全部衔接键：可穷举、可校验、可导出 |
| **图上边标签** | 图源给边加 `data-link="from->to"`，框架按 `links[]` 在中点叠加 | 主链路 1–3 个，一眼看到"这条线传的是 data_id" |
| **单独一张图** | `figures[]` 加一张 `dataflow`（节点 3–5 个、每条边都有键名） | 要看"id 怎么流转、在哪分叉、存哪" |

**边标签的实现**：`<path data-link="etl->callback" d="...">` → 框架用 `getPointAtLength(len/2)` 取中点，叠加 `<text>` + 圆角背景。identifier 实底绿标、event 淡色、`status`/`none` 不标。**没有 `data-link` 的边不标**，所以老图源零改动。

两条已知边界：

- `data-link` 必须写在 **`<path>` / `<line>` / `<polyline>`** 上——写在 `<g>` 上算不出路径长度，会静默跳过（图上没标签、表格仍完整）
- 标签固定放在线的中点上方 22px；**竖直边**上会略显拥挤，横平竖直的图最合适

> 为什么不能全自动：SVG 的边只有 `d="M220 63 H325"`，几何上解析不出"谁连到谁"。`data-link` 就是给边补的语义 id——和给节点补 `data-node-id` 是同一件事。缺这个属性的边，表格里仍有记录，只是图上不标。

**同一条键的多段流转合并成一行**：`data_id` 走 `etl → callback → store → query` 时，表格显示成一行完整路径（`mergeIdLinks` / `merge_id_links`），不是三行重复；`storedAt` 只要任一段写了就够。

**图上要不要标**：主链路 1–3 个可以标，多了会糊——全部交给表格。真要表达"id 怎么流转、在哪分叉"，就补那张 `dataflow` 图（`figures[]` 的正当用法，不需要新机制）。

> 口径同步：`framework/index.html` 的 `figsOf` / `resolveCode` / `externalOf` / `linksOf` 与 `scripts/atlas_io.py` 的 `figures_of` / `resolve_code` / `externals_of` / `links_of` 必须一致，改一处必须改另一处（否则出现"浏览器能看、导出坏"）。

## 二·五、目录树模式（与单文件等价）

**层级 = 目录嵌套深度，不设上限**：子目录就是子分组，可以一直往下。

```
atlas/
├── site.json                        全局字段（title / branch / baseline / generated_at / views_dir）
├── nav/
│   ├── 01-架构总览/                  目录名只用于排序，不进入任何 id
│   │   ├── _group.json              { "id": "arch", "name": "架构总览", "q": "…" }
│   │   └── overview.json            文件名（去 .json）= 页面 id = snippets 的键
│   ├── 02-核心链路/
│   │   ├── _group.json
│   │   ├── 01-检索/                  ← 子目录 = 子分组，可再嵌套
│   │   │   ├── _group.json
│   │   │   └── search.json
│   │   └── 02-导入/
│   │       ├── _group.json
│   │       └── 01-入口/
│   │           ├── _group.json
│   │           └── import.json
│   └── 03-服务与测试/
│       ├── _group.json              { …, "page": "stack" }   ← 有 page = 分类即页面
│       └── stack.json
└── views/
```

| 规则 | 说明 |
|---|---|
| **子目录 = 子分组** | 递归扫描，深度不限；侧栏每层缩进 12px，面包屑显示完整路径 |
| 目录内的 `*.json` | 该分组的页面；文件名（去 `.json`）= 页面 id |
| `_group.json.page` | 填了才把该目录压平成"分类即页面"（侧栏不缩进子项）。**不填则保持"分组 + 页面"两层** |
| `_group.json.order` | 可选，显式指定子节点顺序；缺省按文件名排序；指向不存在的节点直接报错 |
| `_group.json.id` | 分组 id（缺省取目录名去掉数字前缀） |
| `_` 前缀文件 | 一律跳过（`_group.json` 之外可放 `_draft.json` 之类草稿） |

> 目录里只有一个页面时**不会**被自动压平——层级由目录结构决定，不做隐式优化。

**合成时机**：`build_atlas.py <目录> <out.html>` 读完目录树后，会在目录根写出 `atlas.config.json`。运行时框架只认这个合成文件——所以**改目录后必须跑一次 build**（只改 `site.json` 或单文件 config 时可跳过）。

**迁移**：单文件 → 目录树只需按 `nav` 逐项建目录、按 `pages` 键拆文件；`pages[].title` 等字段原样搬进 `<id>.json`。

## 三、交互规范

三条硬约束来自实测缺陷，**不得放宽**：

### 3.1 只有挂了片段的节点可点

- 装配时由 `build_atlas.py` 只给命中的节点加 `data-coded="1"`
- 壳模板的 `cursor:pointer` / hover 光晕 / 焦点环全部挂在 `[data-coded]` 上
- 概念节点保持默认光标，点击无反应（实测：`overview/llm` 点击后面板不打开）

> 经验修正：第一版曾要求"没代码的节点不可点"，实测后改为**所有节点可点**——读者的预期是"点一下总该有反馈"，死节点反而更像 bug。折中做法是：有代码的给代码块，没代码的给"该节点无直接源码 + 相关文件 + 如何补配置"，并用 `data-coded` / `data-bare` 区分视觉强度。

### 3.2 抽屉只由三种操作关闭

`×` / `ESC` / 切换视图。**不注册 document 级点击关闭**。

> 实测反例：demo 在 `document` 上监听 click，点图空白即收起（`codepanel` 从 on 变空）。用户正对照代码看图，手一抖就关掉，还得重新找到节点。

### 3.3 窄屏走底部抽屉

`@media(max-width:1000px)`：抽屉改为 `width:100%; height:62vh; bottom:0`，圆角在上沿。

> 实测反例：demo 的 `min(560px,92vw)` 在 900px 视口占 62%，把图本身盖掉一半——而图正是判断依据。断点必须卡在 1000px，不是 608px（`92vw` 生效点）。

### 3.4 其它已定细节

| 项 | 取值 | 理由 |
|---|---|---|
| 侧栏宽 | 248px，`position:sticky` | 长图滚动时保持导航 |
| 卡片最小宽 | 320px，`auto-fill` | 1320 宽下三列，900 下两列，手机上单列 |
| 代码面板宽 | `min(560px, 92vw)`（桌面） | 刚好容纳 80 列代码不横向滚动 |
| 行号列 | 58px 固定 | 5 位行号不溢出 |
| SVG 挂载 | `<template>` + Shadow DOM | SVG 自带 `<style>`，直接内联会污染整页配色 |
| 离线 | `file://` 显示静态图 + 明示"HTTP 打开才可点" | 不用 fetch（`file://` 会被拦），数据全内联 |

## 四、体积与字体去重

### 4.1 实测数据（archify 产物）

| 形态 | 单图 | 6 图合计 | 说明 |
|---|---|---|---|
| archify HTML | ~800 KB | ~4.8 MB | 含完整 viewer，**不要内联** |
| archify SVG | 330 KB | 1.98 MB | 拿它做内联源 |
| SVG 去 `@font-face` 后 | 235 KB | 1.41 MB | 字体搬到壳层，单图总量不变 |
| 装配后单文件（2 视图试跑） | — | 0.56 MB | 含壳 + 数据 + 片段 |

**字体占比**：手写 SVG 实测 6 块 / 90 KB / 27%；archify 真实产物 6 块 / 90 KB / 51.9%（文件 173 KB）。去重的真实收益：字体是搬去壳层而非消失，单图体积不变，N 张图才省 (N−1) × 90 KB（6 图约 450 KB）。实测只放 1 张 archify 图时日志显示「消除 0 份重复」——不是失败，是没有可消除的重复。

### 4.2 预算换算

| 视图数 | 预估单文件 | 结论 |
|---|---|---|
| 2 | 0.56 MB（实测） | ✅ |
| 6 | ~1.5 MB | ✅ 推荐 |
| 8 | ~1.9 MB | ✅ 上限 |
| 12 | ~2.8 MB | ⚠️ 临界（3 MB 目标） |
| 20 | ~4.7 MB | ❌ 超目标，改拆模块 |

> 去重原理：`@font-face` 是**文档级注册**，Shadow DOM 内元素可直接使用 document 定义的字体。所以把壳层的 `@font-face` 保留、SVG 内的删除，渲染结果一致。

## 五、校验项与常见失败

`check_atlas.py` 的判定与修法：

| 输出 | 含义 | 修法 |
|---|---|---|
| `孤儿片段（snippets 有、pages 无）` | 节点从 pages 里删了，片段还在 | 重跑采集 |
| `悬空可点（标了 data-coded 但无片段）` | 产物里有可点态、片段表里却没有 | 重跑阶段 3–4（不要手改 HTML） |
| `代码条目在图里找不到同名节点` | `code[].id` 与 SVG 的 `data-node-id` 不一致 | 改 pages 或图源的 id |
| `未进入交付物（index.html 里找不到该视图的 <template>）` | nav 引用了它，但装配时没读到图源 | 重跑 build，检查 `pages/{id}.json` 的 `svg` 路径 |
| `interactive 指向不存在的文件`（warning） | 交互版外链已失效 | 补文件或删掉 `interactive` 字段 |
| `缺图源 views/x.svg` | 命名不一致（archify 产物带图种后缀） | 按 `views/{id}.svg` 重命名 |
| `行号越界：声明 2127-2142，文件共 2100 行` | 代码改动后行号失准 | 更新 `pages/*.json`，重跑采集 |
| `区间过大（N 行 > 上限 80）` | 把整个函数塞进来 | 收窄到关键段，或另起一条 |
| `存在外链资源` | 引入 CDN 字体/脚本 | 内联或删除 |
| `壳模板占位符未替换` | 装配中途失败 | 重跑 build，检查模板路径 |
| `解读不足 3 条` | 视图只画不解释 | 补 `points` |
| `缺 why（为什么看这段代码）` | 只有文件行号，读者不知道值不值得点 | 补一句 why（采集脚本会拦下） |
| `页面配置缺失（pages/ghost.json）` | `nav` 引用了没有配置文件的 page | 补 `pages/ghost.json` 或从 nav 删掉 |
| `nav 节点同时有 page 和 children` | 二者互斥；前端会忽略 page（页面静默丢失） | 把该页作为 children 第一项 |
| `nav 最深 N 层`（warning） | 超过 4 层，侧栏缩进会挤到换行 | 收敛层级，或改折叠树 |

**exit code**：`check_atlas.py` → `0` 通过 / `1` 有 error / `2` 体积超硬上限；`build_atlas.py` → `0` 成功 / `1` 有需修正项（文件已写出）/ `2` 体积超限（清理临时文件、不替换正式产物）。

## 七、与 archify 的接线

> 下面前两步在项目根执行，第 3 步三个脚本按 `<project-atlas skill 目录>/scripts/` 定位（skill 可被安装到任意位置，不要用仓库相对路径）。

```bash
# 1. 生成图源（JSON IR）→ HTML —— 命令与脚本位置以 archify 自己为准
#    先 use_skill("archify")，按其文档执行 deliver；不要假设固定安装目录
node <archify skill 目录>/bin/archify.mjs deliver architecture views/overview.json views/overview.html --quality showcase

# 2. 导 SVG（显式调用 skill，未装则用 archify 自带导出）
#    产物放到 .atlas/views/{view-id}.svg，并按约定重命名

# 3. 采集片段 → 装配 → 校验
python3 <project-atlas skill 目录>/scripts/collect_snippets.py atlas.config.json snippets.json --repo-root .
python3 <project-atlas skill 目录>/scripts/build_atlas.py atlas.config.json dist/atlas.html   # 仅分发时导出
python3 <project-atlas skill 目录>/scripts/check_atlas.py .
```

**降级矩阵**：

| 缺失项 | 降级动作 | 影响 |
|---|---|---|
| 可用 skill 里没有 `archify` | 复用已有 `*.svg`；无则手写 SVG | 声明降级，图种受限 |
| SVG 导出不可用 | 用 archify HTML 内嵌 iframe | 体积 ×2.5（800 KB/图），预算重算 |
| git 不可用 | `commit` 留空，面板不显示 commit | 快照无法定位版本 |
| 浏览器不可用 | 只跑静态校验，标注未实测 | 交互与观感未验证 |

## 八、补充反模式

- ❌ **把 `views[].svg` 写成 archify 原文件名**：`check_atlas.py` 会报缺图源；约定就是 `views/{id}.svg`
- ❌ **概念节点硬编行号凑覆盖率**：读者点开看到无关代码，比空着更糟
- ❌ **为省体积删 `points`**：体积大头是 SVG 不是文案，删解读等于把图退化成"看不懂的方框"
- ❌ **在 900px 视口下调抽屉宽度到 50% 继续用**：图被压掉的损失大于面板舒适度收益
- ❌ **改生成物**：导出的 HTML 下次重建即覆盖；要改就改 `atlas.config.json` / 图源 / 框架文件
- ❌ **为加一页去改脚本**：可点态与页面渲染都由配置驱动，改脚本说明钩子设计错了
