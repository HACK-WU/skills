# 产品经理（product-manager）示例

四个模式的完整示例：M1 一次成型需求定义 / M2 产品体验走查 / M3 缺失功能推演 / M4 界面视觉走查（L3 手动上传降级），外加示例 5：代码直读核验（不跑服务直接判定符合性）、示例 6：M4 走查 → 自动接力 ui-designer、示例 7：走查发现 Bug → 接力 debug 定位后停。

---

## 示例 1：M1 一次成型 —— 用户提一个功能想法

**用户输入**：「我想加个导出功能，把报表导出成 Excel。」

**档位判定**：单点功能、1 个角色、无外部依赖 → 一次成型档。

**AI 行为**：自主推理 → 内联负向场景 → 出报告 → **只问一次**（关键假设确认）。

```markdown
# PM 报告：报表导出

> 证据声明：🟡 静态可证 · 未实测（产品未运行）· 现状读代码确认

## 1. 执行摘要
- 真实需求是「把报表数据带走做二次加工」，导出 Excel 只是方案之一（🟡）
- 核心风险不在"能不能导出"，而在**大数据量导出的等待与失败恢复**（🟡）
- 建议优先做异步导出 + 进度可查，而非同步下载（🟡）

## 2. 现状与范围
- 边界：报表列表页与详情页的导出入口
- 现状来源：读代码确认（无导出相关代码，`report/` 下仅有查询接口）
- 未覆盖：导出文件的权限控制（待确认）

## 3.0 影响面（M1 必填）
| 受影响功能/方 | 影响类型 | 影响程度 | 证据 | 建议处理 | 需用户拍板 |
|--------------|---------|---------|------|---------|-----------|
| 报表页面的列配置 | 数据/展示 | 降级 | 🟡 列配置与导出字段各有一份映射 | 本次一并改（REQ-04） | 否 |
| 导出权限 | 权限 | 破坏 | 🟢 当前无任何导出鉴权，任何人可导出全量 | 本次一并改（REQ-05） | 否 |
| 定时报表邮件任务 | 流程 | 无感 | ⚪ 未发现（需确认） | 需确认是否存在 | 是 |
| 对外 API /v1/reports | 外部契约 | 无感 | 🟢 纯新增能力，不改现有契约 | 无需处理 | 否 |

> ⚪ = 未发现；不得默认"无影响"，已列入待确认。

## 3. 需求清单
| ID | 需求 | 预期效果 | 优先级 | 验收标准 |
|----|------|---------|--------|---------|
| REQ-01 | 报表导出 Excel | 点击后拿到与页面一致的 Excel | P0 | 导出数据与页面筛选条件一致 |
| REQ-02 | 异步导出 + 进度 | 大数据量时不卡死页面，可查进度 | P0 | 10 万行导出页面不阻塞，进度可见 |
| REQ-03 | 导出失败可重试 | 失败后能看到原因并重试 | P1 | 失败有原因说明，一键重试 |
| REQ-04 | 导出字段与页面列配置统一 | 页面加列后导出自动跟随，不再两处维护 | P1 | 加一列后导出含该列，无需改代码 |
| REQ-05 | 导出权限管控 | 无权限者看不到导出入口、接口亦拒绝 | P0 | 越权调用导出接口返回 403 |

> REQ-04 / REQ-05 **来自影响面**——影响项必须变成需求条目，只写在说明里必然漏做。

## 3.2 负向需求
| ID | 场景 | 类型 | 预期程序行为 |
|----|------|------|-------------|
| NEG-01 | 点了导出没反应以为没生效 | 状态异常 | 立即置为"准备中"，禁用按钮防重复点 |
| NEG-02 | 导出中关闭页面 | 中途放弃 | 后台继续，回来能查到历史导出 |
| NEG-03 | 无数据 / 筛选结果为空 | 数据异常 | 提示"当前条件下无数据可导出"，不生成空文件 |
| NEG-04 | 导出超时（大数据量） | 状态异常 | 转异步并通知，不让用户干等 |

## 4. 优先级排序
| 优先级 | 条目 | Kano | 价值 | 成本 | 证据 | 排序理由 |
|--------|------|------|------|------|------|---------|
| P0 | REQ-01 导出 | 必备 | 高 | 中 | 🟡 | 无此能力用户只能手工抄 |
| P0 | REQ-02 异步+进度 | 必备 | 高 | 中 | 🟡 | 同步导出大数据量必然超时，属必备 |
| P0 | REQ-05 导出权限管控 | 必备 | 高 | 中 | 🟢 | 无鉴权即越权导出全量数据，属必备 |
| P1 | REQ-03 失败重试 | 期望 | 中 | 低 | 🟡 | 提升容错，成本低 |
| P1 | REQ-04 字段配置统一 | 期望 | 中 | 中 | 🟡 | 防两处维护漂移，非阻塞 |

## 5. 待确认清单
（本次无待确认项——所有结论均有代码或静态证据支撑；H-01～H-03 见下节假设表）

## 6. 关键假设（唯一确认点）
| ID | 假设 | 错了会怎样 | 验证方法 |
|----|------|-----------|---------|
| H-01 | 导出量级在万行以上 | 若仅百行，同步导出即可，REQ-02 降级 | 询问用户典型数据量 |
| H-02 | 导出内容与页面筛选一致 | 若需独立配置导出字段，需求翻倍 | 确认导出范围 |
| H-03 | 无需按角色限制导出权限 | 若需限制，要加权限设计 | 确认是否存在敏感数据 |

> 请重点确认 H-01～H-03，其余我已按最可能情况填好。
```

## 示例 6：M4 走查 → 自动接力 ui-designer

**用户输入**：「看看这个仪表盘页面怎么样。」（有浏览器工具，能自主截图）

**AI 行为**：能力探测 L1 → 截图走查 → 判定为**视觉方案级问题**（不是实现偏差）→ 报告出完**自动接力** `ui-designer`。

```markdown
# PM 报告：仪表盘页面

> 证据声明：🟢 截图实测（L1 自主截图 6 态：默认 / 空 / 加载 / 错误 / 长文本 / 窄屏）

## 1. 执行摘要
- 核心问题不是配色或间距，而是**信息层级缺失**：8 个指标平铺同权重，看不出哪个要优先看（🟢）
- 主操作入口（新建看板）与筛选按钮同级、藏在工具区（🟢）
- 现有 token 体系（间距 8/16/24、圆角 8）实现基本遵循，仅 U-03 一处偏差（🟢）

## 3.1 发现清单
| ID | 现象 | 证据 | 性质 |
|----|------|------|------|
| U-01 | 8 个指标同权重平铺，无主次 | 🟢 screenshot-1 | **方案级**：需重排层级 |
| U-02 | 主操作与次级工具同级 | 🟢 screenshot-1 | **方案级**：信息架构 |
```
