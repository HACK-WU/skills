## 一、预检脚本模板（6 项拒收门）

**落点与生成者**：`.delivery/premerge-check.sh`（**脚手架统一目录**，一行 `.gitignore` 即可覆盖；见 `delivery-slicing`「测试与脚手架的归属」）。

- **生成者**：`delivery-slicing` **阶段 4 打包时**按本模板实例化到项目 `scripts/`（它是砖头包的外层产物之一）
- **消费者**：各窗口用 `--slice {SR-XX}` 自跑（作为该片完成定义的一部分）+ 本 skill 阶段 1 全量复跑
- 不生成它 → **拒收门退化为空承诺**（各窗口无脚本可跑，问题全部堆到拼接期）

**机械可判的部分不要靠人看**。

```bash
#!/usr/bin/env bash
# .delivery/premerge-check.sh [--slice SR-01]   # 带 --slice 供窗口自跑（只查自己那一片）
set -euo pipefail

CONF=".delivery/premerge.conf"
MOCK_DIR=".delivery/mocks/"
SINGLE=""
[[ "${1:-}" == "--slice" ]] && SINGLE="${2:-}"

# 桩残留扫描模式：★ 单一来源 = design-to-code 生成的 .delivery/stub-pattern（三处共用，防漂移）
# 【切勿默认扫 NotImplemented】抽象基类 / 协议声明等语言惯用法也用它 → 大面积误报 → 狼来了
STUB_PATTERN="${STUB_PATTERN:-$(cat .delivery/stub-pattern 2>/dev/null || echo 'STUB:')}"
# 生产路径扫描范围：★ 不要写 ':!*test*' —— 它会把 src/latest/ 这类路径一并排除（实测漏扫，见 reference 六）
SRC_GLOBS=('*.py' '*.ts' '*.go' '*.js'
           ':!tests/*' ':!test/*' ':!*_test.*' ':!*_spec.*' ':!*.test.*' ':!.delivery/*')

# ── 配置：从各包 ownership.md 的机器可读块【生成】，禁止手抄 ──────────
# 手抄 = 制造第三份真相（ownership.md / 脚本配置 / 实际代码），不同步则预检结论失真
gen_conf() {
  python3 - <<'PY' > "$CONF"
import glob, os, re
rows = []
for d in sorted(glob.glob("sub-requirements/SR-*/")):
    name = os.path.basename(d.rstrip("/"))
    p = os.path.join(d, "ownership.md")
    if not os.path.exists(p):
        print(f"# WARN {name}: 缺 ownership.md"); continue
    m = re.search(r"```yaml\n(.*?)```", open(p, encoding="utf-8").read(), re.S)
    if not m:
        print(f"# WARN {name}: 缺机器可读块"); continue
    b = m.group(1)
    def scal(k):
        # 取到 # 为止——yaml 行尾注释必须排除，否则值里会带注释文字
        mm = re.search(rf"^{k}:\s*([^#\n]+)", b, re.M)
        return mm.group(1).strip() if mm else ""
    def lst(k):
        # ★ 键名行允许行尾注释（如 `interface:  # 说明`）——必须用 [^\n]* 吃掉；
        #   原写法 `\s*\n` 匹配不了 `#`，会让整项【静默解析为空】→ 该检查形同不存在
        mm = re.search(rf"^{k}:[^\n]*\n((?:\s*-\s*[^#\n]+\n?)+)", b, re.M)
        return ",".join(x.strip() for x in re.findall(r"-\s*([^#\n]+)", mm.group(1))) if mm else ""
    # ★ 两个基线都读：code_base（门①② 用）与 contract_base（门⑤ 用）
    #   分批时二者不是同一个 commit，只读一个必致门① 或门⑤ 误报
    rows.append("|".join([name, scal("code_base"), scal("contract_base"), scal("branch"),
                          lst("exclusive"), lst("interface")]))
print("\n".join(rows))
PY
}
gen_conf
echo "配置来源：sub-requirements/*/ownership.md（生成，未手抄）"

[[ -s "$CONF" ]] || { echo "❌ 无可用砖头包（检查 sub-requirements/ 与机器可读块）"; exit 1; }

# ★ 解析自检：关键字段为空 = 解析失败，必须【显式报错】——
#   解析器对格式敏感，失败时静默返回空串；若不拦，结果是"少检查一项"却报通过（最危险）
while IFS='|' read -r chk_n chk_cb chk_kb chk_br chk_ow chk_pk; do
  [[ -z "$chk_n" || "$chk_n" == \#* ]] && continue
  if [[ -z "$chk_cb" || -z "$chk_kb" || -z "$chk_ow" ]]; then
    echo "❌ 解析失败：$chk_n 的 code_base / contract_base / exclusive 出现空值"
    echo "   → 检查 sub-requirements/$chk_n/ownership.md 机器可读块（键名行注释 / 缩进 / 列表符号）"
    exit 1
  fi
done < "$CONF"

fail=0; report=(); all_rows=()

# ★ 先【完整】读一遍配置构建 all_rows，再进入逐片检查。
#   否则 ③ 依赖方向存在顺序缺陷：循环中累积的 all_rows 只含"已处理过的包"，
#   前序包看不到后序包 → "A 引用了 B" 中靠前的 A 永远检不出（实测漏报）
while IFS='|' read -r pre_n pre_cb pre_kb pre_br pre_ow pre_pk; do
  [[ -z "$pre_n" || "$pre_n" == \#* ]] && continue
  all_rows+=("$pre_n|$pre_cb|$pre_kb|$pre_br|$pre_ow|$pre_pk")
done < "$CONF"

while IFS='|' read -r name C_BASE K_BASE branch owned pkgs; do
  [[ -z "$name" || "$name" == \#* ]] && continue
  # all_rows 已在循环前完整预读（勿在此重复追加，否则 ③ 会对同一对重复检查）
  [[ -n "$SINGLE" && "$SINGLE" != "$name" ]] && continue
  echo "── ${name}（$branch ｜ code_base=$C_BASE ｜ contract_base=${K_BASE}）"

  if ! git rev-parse --verify "$branch" >/dev/null 2>&1; then
    report+=("$name|①越界|SKIP|分支不存在"); continue
  fi

  # ★ 基线有效性校验（缺了它 → 门①② 会同时假绿）：
  #   base 无效时 `git diff "${C_BASE}..${branch}"` 直接失败，而
  #     门① 走【进程替换】—— 退出码不传播，while 读到空输入 → PASS
  #     门② 若用 `|| true` —— 错误被吞 → PASS
  #   两门无声失效。必须在最前面卡住（实测：base=deadbeef 时两门均 PASS）
  base_bad=""
  for b in "$C_BASE" "$K_BASE"; do
    git rev-parse --verify "$b" >/dev/null 2>&1 || base_bad="$base_bad $b"
  done
  if [[ -n "$base_bad" ]]; then
    report+=("$name|⓪基线|FAIL|基线 commit 无效：${base_bad}（检查 ownership.md 的 code_base / contract_base；分批时第 N 批 = 上一批合入后）")
    fail=1; continue
  fi

  # ① 越界：改动必须全落在独占写前缀内（从 code_base 算起）
  # ★ 排除 sub-requirements/ 与 .delivery/：前者是流程产物、且窗口本就要更新【自己包的 slice.md】
  #   状态标记（不排除则每次误报）；后者是脚手架。排除≠放任：改包内 contract/ 由门② 抓
  #   （完整理由见 delivery-slicing 阶段 3.2c）
  while read -r f; do
    [[ -z "$f" ]] && continue
    ok=0; IFS=',' read -ra prefixes <<< "$owned"
    for p in "${prefixes[@]}"; do [[ "$f" == "$p"* ]] && ok=1; done
    [[ $ok -eq 1 ]] || { report+=("$name|①越界|FAIL|$f"); fail=1; }
  done < <(git diff --name-only "${C_BASE}..${branch}" \
           | grep -vE '^(sub-requirements/|\.delivery/)' || true)

  # ② 契约未改：包内契约快照 + interface 文件必须零 diff（从 code_base 算起）
  # ★ 路径：契约快照落在【砖头包内】sub-requirements/{SR-XX}/contract/，
  #   而 `-- contract/` 是仓库根相对路径 —— git **不匹配任意层级的同名目录**（实测零命中），
  #   写错 = 该半边形同不存在（窗口改了契约快照也检不出）
  check_paths=("sub-requirements/$name/contract/")
  IFS=',' read -ra ifaces <<< "$pkgs"
  for i in "${ifaces[@]}"; do [[ -n "$i" ]] && check_paths+=("$i"); done

  changed=""
  for sp in "${check_paths[@]}"; do
    # ★ 区分退出码：git diff 对"路径不存在/无改动"返回 0（空输出）；>0 才是真错误
    #   写成 `2>/dev/null || true` 会把"出错"变成"干净" → 假绿（同 ⑥ 门，勿回退）
    if out=$(git diff --name-only "${C_BASE}..${branch}" -- "$sp" 2>&1); then
      [[ -n "$out" ]] && changed+="$out"$'\n'
    else
      rc=$?
      report+=("$name|②契约未改|SCAN-ERROR|${sp}（git 退出码 ${rc}）：$out"); fail=1
    fi
  done
  [[ -n "$changed" ]] && { report+=("$name|②契约未改|FAIL|$changed"); fail=1; }

  # ③ 依赖方向：新砖头之间不得真实 import（优先用静态分析工具，此处为无工具时的近似）
  for row in "${all_rows[@]}"; do
    IFS='|' read -r other_name _ _ _ other_owned _ <<< "$row"
    [[ "$other_name" == "$name" ]] && continue
    IFS=',' read -ra other_prefixes <<< "$other_owned"
    for op in "${other_prefixes[@]}"; do
      [[ -z "$op" ]] && continue
      # 排除测试目录与注释行，降低误报
      # ★ 用 SRC_GLOBS 而非 ':!*test*'——后者会把 src/latest/ 这类生产路径一并排除（漏扫）
      # ★ 与 ⑥ 同构：区分 git grep 退出码，避免"出错"被当成"无依赖"（假绿）
      if raw=$(git grep -n -F "$op" "$branch" -- "${SRC_GLOBS[@]}" 2>&1); then
        hits=$(printf '%s\n' "$raw" | grep -v -E ':[0-9]+:\s*(#|//|\*)' || true)
      else
        rc=$?; hits=""
        [[ $rc -eq 1 ]] || { report+=("$name|③依赖方向|SCAN-ERROR|git 退出码 $rc：$raw"); fail=1; }
      fi
      [[ -n "$hits" ]] && { report+=("$name|③依赖方向|FAIL|引用 $other_name 的 ${op}（需人工复核）"); fail=1; }
    done
  done

  # ④ mock 残留：.delivery/mocks/ 之外的代码不得引用 mock
  hits=$(git grep -n -E "from .*${MOCK_DIR%/}|import .*${MOCK_DIR%/}|require\(.*${MOCK_DIR%/}" "$branch" \
         -- '*.py' '*.ts' '*.go' '*.js' 2>/dev/null | grep -v "^.*:${MOCK_DIR}" || true)
  [[ -n "$hits" ]] && { report+=("$name|④mock残留|FAIL|$hits"); fail=1; }

  # ⑤ 契约基线：包内 contract/BASE 应与【契约基线】一致（用 K_BASE，不是代码基线）
  pkg_base=$(git show "$branch:sub-requirements/$name/contract/BASE" 2>/dev/null || echo "MISSING")
  [[ "$pkg_base" != "$K_BASE" ]] && { report+=("$name|⑤契约基线|FAIL|包内 $pkg_base ≠ 契约基线 $K_BASE"); fail=1; }

  # ⑥ 桩残留：生产路径不得留桩（**独立扫描，不依赖测试是否覆盖到**）
  # ★ 必须区分 git grep 退出码：0=有匹配 / 1=无匹配 / >1=出错
  #   写成 `2>/dev/null || true` 会把"出错"变成"无匹配" → 假绿（实测：git 返回 128 被静默吞掉）
  if hits=$(git grep -n -E "$STUB_PATTERN" "$branch" -- "${SRC_GLOBS[@]}" 2>&1); then
    report+=("$name|⑥桩残留|FAIL|$hits"); fail=1
  else
    rc=$?
    [[ $rc -eq 1 ]] || { report+=("$name|⑥桩残留|SCAN-ERROR|git 退出码 ${rc}：$hits"); fail=1; }
  fi

  [[ -z "$SINGLE" ]] && echo "   done"
done < "$CONF"

echo
echo "════ 预检结果 ════"
if [[ ${#report[@]} -eq 0 ]]; then
  echo "✅ 全部门通过${SINGLE:+（仅查 ${SINGLE}）}"
else
  printf '%s\n' "${report[@]}" | awk -F'|' '{printf "%-8s %-12s %-5s %s\n",$1,$2,$3,$4}'
  echo "⚠️ ③ 依赖方向为近似结果，命中项须人工复核后再判拒收"
fi
exit $fail
```

**两个要点**：

1. **配置是生成的，不是手写的**（`gen_conf`）。`ownership.md` 里的机器可读块是唯一真源；脚本只读不抄。
2. **`③ 依赖方向` 优先用静态分析工具**（`import-linter` / `dependency-cruiser` / ArchUnit）构造真实依赖图，上面的 grep 只是无工具时的近似——**它会误报**（注释、测试文件、字符串常量撞名），命中项须人工复核后放行。
3. **`--slice SR-01` 供窗口自跑**：作为该片"完成定义"的一部分（见 SKILL.md 阶段 0 第 0 项），把拒收门前置到窗口手里。

**合流顺序**（依赖 DAG 层）从 `sub-requirements/INDEX.md` 的批次表读取，不在此脚本内硬编码。有多个 mock 来源需核销时，读 `sub-requirements/MOCK_LEDGER.md`。

## 二、拒收门判定细则

### ① 越界

| 情况 | 判定 | 处理 |
|------|------|------|
| 改动落在独占写内 | ✅ | — |
| 改动落在只读区 | ❌ 拒收 | 该片回退，不代为修改 |
| 改动落在禁碰区 | ❌ 拒收 | 同上，并确认是否为需求变更导致 |
| 新增文件落在他人目录 | ❌ 拒收 | 无 git 场景靠人工核对新增文件落点 |

**注意**：`ownership.md` 声明的独占写若本身有误（如漏了一个文件），**不在拼接期放宽**——回 `delivery-slicing` 重切该片。**改上游适配现状 = 双源漂移**。

### ② 契约未改

| 情况 | 判定 | 处理 |
|------|------|------|
| `contract/` 零 diff | ✅ | — |
| 改了契约快照内容 | ❌ 拒收 | 报告 + 回 `design-craft` 评估（影响面可能波及多片） |
| 改了接口桩签名/实现 | ❌ 拒收 | 同上 |
| 只新增了包内自有文件（未动快照） | ✅ | 属正常产出 |

### ③ 依赖方向

| 情况 | 判定 | 处理 |
|------|------|------|
| 与允许矩阵一致（`✗` 处无边） | ✅ | — |
| `✗` 处出现真实 import | ❌ 拒收 | 该片改为通过契约桩 / mock 交互后重交 |
| 通过 mock 间接依赖对手（`mock*` 标注） | ✅ | 但拼接后须确认 mock 已替换 |
| 出现反向依赖或环 | ❌ 拒收 | 属架构问题，回 `design-craft` |

### ④ mock 残留

| 位置 | 判定 |
|------|------|
| `.delivery/mocks/` 内部互相引用 | ✅ |
| 测试代码引用 mock | ✅（测试替身本就该引） |
| **生产代码路径引用 mock** | ❌ 拒收，必须替换为真实实现 |
| 配置/开关默认指向 mock | ❌ 拒收（更隐蔽，运行时才炸） |

### ⑤ 契约基线

| 情况 | 判定 | 处理 |
|------|------|------|
| 各片`contract_base` 一致 = 主干当前骨架 commit | ✅ | — |
| 某片契约基线落后（骨架修订后未重新对齐） | ❌ 拒收 | 该片重新对齐 + 对最新契约重跑测试后再拼 |
| 包内无基线记录 | ❌ 拒收 | 砖头包不完整，回 `delivery-slicing` 补齐 |

> **只比 `contract_base`，不比 `code_base`**：分批时后者逐批不同（第 N 批 = 上批合入后），拿它比对会把"正常的批次推进"误判成"基线不一致"。若发现某片 `code_base` 落在旧冻结点上，那是 **`delivery-slicing` 阶段 3.2b 的出包错误**（该批基线取错），不是该片的错——按 ① 越界误报处理并退回重出该批包。

### ⑥ 桩残留

| 情况 | 判定 | 处理 |
|------|------|------|
| 生产路径无桩标记 | ✅ | — |
| 某接口仍抛 `NotImplemented`（本次应实现） | ❌ 拒收 | **退回该片补齐实现**，不代为实现 |
| 该接口本次确实不实现（悬空桩） | ❌ 拒收 | 回 `design-craft` 评估是否从契约移除——**不许留悬空桩上线** |
| 桩标记出现在抽象方法 / 协议声明（语言惯用法） | ✅ | 前提是 `STUB_PATTERN` 用**自定义桩标记**（`STUB:{SR-XX}:{方法名}`）而非 `NotImplemented` —— 后者会把语言惯用法一并扫进来，**误报刷屏后真残留反而被忽略** |

**为什么必须独立扫、不能只看测试结果**：

> 契约测试只覆盖「有测例的接口」；漏实现的恰是**没被覆盖到**的那些。**测试全绿也查不出桩残留。**

**因此**：⑥ 是**纯机械扫描**（`grep` 级），不读测试结论。扫描模式由 `design-to-code` 生成桩时统一注入（见其并行路线差异表），预检脚本通过 `STUB_PATTERN` 复用**同一模式**——两处模式不一致 = 漏扫。

**语言无 `NotImplemented` 机制时**（Go 无内置、JS 易被绕过）：由 `design-to-code` 在桩体注入统一标记（如 `STUB:SR-01:exportXlsx`），扫该标记。比"靠约定不写实现"可靠得多。

## 三、合流操作细则

### 有 git

```bash
# 按层合流，每合一片立刻编译
git checkout main
git merge --no-ff feat/sr-01 -m "merge(SR-01): 导出 CSV"
make build || { echo "SR-01 合入后编译失败，停止"; exit 1; }

git merge --no-ff feat/sr-02 -m "merge(SR-02): 导入 CSV"
make build || exit 1
```

| 要求 | 说明 |
|------|------|
| 用 `--no-ff` | 保留每片的合并节点，便于逐片 revert |
| **不用 squash** | squash 会丢失逐片可追溯性，回滚时无法精准退一片 |
| 每片合完编译 | 主干常绿 |
| 记录合入 commit | 回滚与报告都需要 |

### 无 git

```text
1. 按层顺序搬运文件（记录：源路径 → 目标路径 → 哈希）
2. 搬运后逐片校验哈希一致（确认搬运无损坏/漏搬）
3. 每片搬完编译一次
4. 回滚 = 按记录反向搬运 + 哈希还原
```

**风险提示**：无 git 时越界检查、基线比对都退化为人工核对（见 `delivery-slicing` 的"无 git 时的越界检查降级"），**可靠性显著下降**，建议在报告中标明。

### 部分批次拼接（按层交付）

不必等所有批次做完才拼——第 N 层全部完成后即可先拼一层，好处是**提前暴露问题**（越早拼越便宜）并提前交付部分价值。

```text
前置：查允许依赖矩阵，确认第 N 层砖头对未完成层【无真实依赖】（mock* 可接受）

第 1 层完成 → 拼第 1 层 → 装配验证 + 语义验收（针对已并入部分）
                          ↓
第 2 层完成 → 再拼第 2 层 → 重跑契约测试（对真实实现）+ 增量语义验收
```

| 要求 | 说明 |
|------|------|
| 依赖判据 | 该层任一砖头对未完成层有**真实依赖**（非 `mock*`）→ 不能部分拼接（合进来也跑不通） |
| 报告标注 | 显式写"**部分拼接（第 N 层）**"+ 未并入的片与原因 |
| 后续拼接 | 后续层并入时**必须重跑全量契约测试**（不能只跑新并入部分——先并入的片可能受后并入方影响） |
| 交付口径 | 部分拼接的结果**不能当作完整交付**，须在交接时说明 |

### 合并冲突的处理

目录互斥生效时，合并冲突**本不该出现**。一旦出现，说明预检有漏：

| 冲突现象 | 含义 | 处理 |
|---------|------|------|
| 两片改了同一文件 | ① 越界门漏判（同一文件被两片碰） | 停下来回查 `ownership`，确认是切片错误还是预检漏判 |
| 同一文件不同区域冲突 | 同上（例外条款未生效或区域判断错） | 人工三方合并 + 记入报告 |
| 契约文件冲突 | ② 门漏判 | **不合并**，回 `design-craft` 处理 |

> **冲突出现本身就是一条发现**：说明前面某一环失效了。不要只解决冲突了事，要回查根因。

## 四、语义审查清单（完整版）

### A. 契约 10 项逐条对照

对每个跨砖头契约打印出来逐项打勾，不要凭印象：

```text
契约：{接口名}
☐ 1  前置条件一致
☐ 2  后置条件一致（排序 / 分页 / 去重 / 含头不含尾）
☐ 3  空值策略一致（null vs 空数组；"无数据" vs "未计算"）
☐ 4  错误语义一致（抛 vs 返回；错误码集合）
☐ 5  单位与精度一致（分/元、小数位）
☐ 6  时间语义一致（UTC/本地、秒/毫秒）
☐ 7  幂等性一致（重复调用是否产生副作用）
☐ 8  并发安全一致（是否需调用方加锁）
☐ 9  事务边界一致（副作用何时对他人可见）
☐ 10 副作用一致（是否发消息 / 写日志 / 调外部）
```

**高频事故前三名**：单位与精度、时间语义、空值策略——这三项逐条**用具体值验证**（不要只读代码）。

### B. 数据守恒质疑

| 问 | 检查动作 |
|----|---------|
| 流向 | 列出该数据的**全部消费方**（grep 调用点 / 订阅方 / 报表 / 同步任务），确认没有不在 diff 可见范围内的消费方 |
| 数量 | 逐跳对比修改前后的结果集规模：过滤条件、去重逻辑、JOIN、异常吞批是否改变了条数 |
| 内容 | 指出关键字段在消费方的用途，确认序列化层没静默丢字段（精度、时区、枚举映射） |
| 异常归宿 | 逐个异常处理点说明数据最终归宿：重试 / 死信 / 补偿 / 上抛 / **静默丢弃**。静默丢弃即缺陷 |
| 贯通（新增数据） | 某片新增的字段/事件/接口，**逐跳走完链路**（入口 → 校验 → 服务 → 存储 → 返回/发送），标出断链跳 |
| 反向消费 | 某片新增的产出有没有生产方 / 消费方？还是死字段 |

**判定规则**：任一问命中变化 → 逐消费方做**效果等价性判定**：

| 结论 | 处理 |
|------|------|
| 🟰 效果一致 | 质疑不成立，记录 |
| 🟡 影响可忽略 | **要求业务方确认可容忍**（审查者不得自行判定可忽略） |
| 🔴 影响重大（报表失真 / 告警漏报误报 / 资金偏差 / 不可逆丢失） | **阻断交付** |

### C. 负向场景（mock 覆盖不到）

| 场景 | 验证方式 |
|------|---------|
| 依赖方失败 | 构造真实失败（断开依赖 / 注入错误） |
| 超时 | 注入延迟，验证超时与降级 |
| 部分成功 | 构造"部分成功"响应，验证幂等补偿 |
| 空 / 脏数据 | 构造空集合、极值、超长字段 |
| 重复调用 | 同一请求发两次，验证幂等 |
| 并发调用 | 两片同时触发同一资源，验证锁/竞态 |

### D. 端到端与非功能

| 项 | 要求 |
|----|------|
| 关键路径 e2e | 从入口到终态走通**跨砖头的完整链路**（不是各片局部测试的拼凑） |
| 性能 | 跨砖头调用是否引入明显退化（单片看都正常，加起来慢） |
| 事务与副作用时机 | 跨砖头的副作用顺序是否符合契约（如通知在数据落库后） |
| 资源 | 连接数 / 线程 / 内存是否因跨片调用叠加而超预期 |

```markdown
# mock 台账

| # | mock 名称 | 提供方（骨架） | 使用方 | 替换为 | 替换责任人 | 状态 |
|---|-----------|---------------|--------|--------|-----------|------|
| 1 | 汇率查询 mock | 骨架 commit a1b2c3d | SR-03 | SR-05 的真实实现 `rate/service.py::query()` | 用户 | 待替换 |
| 2 | 通知发送 mock | 骨架 | SR-04 | SR-07 的真实实现 | 用户 | 待替换 |

## 异常路径覆盖（骨架已提供的 mock 能力）

| mock | 可配置的异常 |
|------|-------------|
| 汇率查询 | 失败 / 超时 / 返回空 / 返回脏数据 |

- 替换后重跑该片的负向场景（异常路径需用真实实现验证）
- 全部核销后扫描生产代码路径确认零残留（预检门 ④）
```

### mock 替换的边界：是「接线」，不是「实现」

跨分支场景下依赖方拿不到对方代码，**替换只能在拼接期做**——所以这是合法动作。但边界必须守住：

| ✅ 允许 | ❌ 禁止 |
|--------|--------|
| 把 mock 引用换成真实实现的调用 | 因为接口对不上**就地调整契约或包装适配** |
| 更新注入/装配点（DI、工厂、开关） | 因为签名不一致**修改对方实现** |
| 移除 mock 专属配置与开关 | 保留 mock 作为"降级开关"带上线 |
| 替换后重跑契约测试与负向场景 | 只替换不重跑（等于没验） |

**判定**：替换后契约测试失败 → **拒收该片，不就地适配**。失败说明"契约与真实实现对不上"，属骨架或实现问题，须回对应环节处理。

**替换即转正（归属变更）**：替换后 `tests/data-flow/` 的内容从"骨架期 mock 版"变成"**对真实实现版**"——它**就此转为产品资产，随交付提交**（进 CI）。同时：

- `.delivery/mocks/` 里的骨架期替身**保持忽略**、不进版本控制（它是危险品，留着可能被生产代码误引）
- 替换后须复核**生产代码路径无 mock 残留**（拒收门④）
- 完整的提交 / 忽略约定见 `delivery-slicing`「测试与脚手架的归属」

> **预期心理准备**：凡有片靠 mock 完成，其与对方的真实对接**在拼接期第一次发生**——所以契约测试重跑失败是**预期**而非异常，且失败率直接反映当初 mock 可行性判据（1–5）是否判松了。

## 六、逐片回滚流程

```text
某片不合格
  │
  ├─ 1. 判定不合格的层级
  │       ├─ 预检门（阶段 1）→ 从未合入，直接拒收，无需回滚
  │       ├─ 装配验证（阶段 3）→ 已合入，需回滚
  │       └─ 语义验收（阶段 4）→ 已合入，需回滚
  │
  ├─ 2. 执行回滚
  │       ├─ 有 git：git revert -m 1 {合入commit}（或丢弃其分支重做）
  │       └─ 无 git：按合流记录反向搬运 + 哈希还原
  │
  ├─ 3. 立刻编译 → 主干必须恢复常绿
  │       编译不过 → 说明回滚不干净，逐步排查（不要继续往下走）
  │
  ├─ 4. 依赖检查（查允许矩阵 + 实际 import 图）
  │       ├─ 无片依赖它 → 其余片照常验收
  │       └─ 有片依赖它 → 依赖方一并回滚，或改为对 mock 验证（须在报告注明降级）
  │
  ├─ 5. 记入报告
  │       回滚了哪片 / 原因 / 是否连带回滚 / 后续建议（重做 / 拆小 / 串行补 / 回设计）
  │
  └─ 6. 告知用户
          静默回滚 = 没发生；用户不知道就会以为已经拼好了
```

**回滚后的处置选项**（给用户选）：

| 选项 | 适用 |
|------|------|
| 该片重做（错误指令更明确后重开窗口） | 问题在实现，契约本身没问题 |
| 该片与依赖方**合并成一片**重做 | 两者耦合比预想紧，切开不划算 |
| 改为**串行**补做 | 该片与多片都有微妙交互，并行本就是错的 |
| 回 `design-craft` **修契约** | 冲突暴露了骨架缺口（契约定义不足） |

## 七、常见拼接故障定位表

| 现象 | 可疑原因 | 定位手法 |
|------|---------|---------|
| 编译过但接口调用对不上 | 契约基线不一致（某片未重新对齐） | 比对各片 `contract/BASE` 与骨架当前 commit |
| 编译过但数据不对（数量级错） | 单位/精度假设不一致（分 vs 元） | 契约 10 项第 5 项，用具体值验证 |
| 编译过但时间错 8 小时 / 差 1000 倍 | 时间语义不一致（UTC/本地、秒/毫秒） | 契约 10 项第 6 项 |
| 空数据被当异常 / 异常被当空数据 | 空值策略不一致 | 契约 10 项第 3 项 |
| 某功能静默不生效 | 挂载点未接通，或挂载顺序错 | 挂载点测试（应为绿）+ 分发日志 |
| 重复执行产生重复副作用 | 幂等性假设不一致 | 重复调用测试 |
| 数据到达下游时变少 | 过滤 / 去重 / JOIN 改动 / 异常吞批 | 数据守恒"数量"问，逐跳对比条数 |
| 新增字段没生效 | 贯通断链（某一跳没接住） | 贯通问：逐跳走链路标断点 |
| 生产环境仍走 mock | mock 残留（含配置开关指向 mock） | 预检门 ④ + 运行时日志 |
| **预检全绿但线上调用抛 `NotImplemented`** | 桩残留扫描失效，三种成因：① `STUB_PATTERN` 各处不一致 ② 排除模式用 `*test*` → 漏掉 `src/latest/` 这类路径 ③ `2>/dev/null \|\| true` 把 git 报错吞成"无匹配"（**假绿**） | 手工跑 `git grep -nE "$STUB_PATTERN" -- "${SRC_GLOBS[@]}"` 看**退出码**：1 = 真干净，>1 = 出错 |
| 桩残留报一大堆、但全是抽象基类方法 | `STUB_PATTERN` 用了 `NotImplemented`（语言惯用法被误扫） | 改用自定义桩标记 + 单一来源 `.delivery/stub-pattern` |
| 门②「契约未改」该报却不报 | 机器可读块解析失败：键名行带行尾注释而解析器不支持 → `interface` 静默解析为空 → 该项形同不存在 | `premerge-check.sh` 已内置解析自检（空值即报错）；仍不报则手工 `cat .delivery/premerge.conf` 核对 |
| 单片测都正常、合起来慢 | 跨砖头调用叠加 / 重复调用 | 端到端性能对比；看是否有本可合并的重复调用 |
| 消息先于数据到达 | 事务边界假设不一致 | 契约 10 项第 9 项 |

## 九、反模式速查

| 反模式 | 为什么错 |
|--------|---------|
| **手抄 `ownership.md` 到脚本配置** | 制造第三份真相，不同步时预检结论直接失真 |
| **预检只在拼接期跑、不下发窗口** | 越界到拼接期才首次发现，是切片流程的失败 |
| **依赖检查误报就直接拒收** | 注释/测试文件撞名必然误报；应先排除后人工复核 |
| **编译失败就地"改到能过"** | 掩盖真问题、分支与主干不一致；默认先撤回再定位 |
| **mock 替换时顺势改契约** | 替换是接线不是实现；改了契约即为漂移 |
| **把「降级验证」当完成** | 验的是形状不是真实对接，等于假绿充当凭证 |
| **语义验收裁剪不留痕** | 报告写"可能存在未知风险"等于没写 |
| 把拼接当文件搬运 | 文件回来 ≠ 功能对了；验证与验收才是本体 |
| 跳过拒收门直接合流 | 问题推到验收期，那时更难定位是哪片 |
| 用各窗口"对 mock 全绿"作凭证 | 假绿 |
| 带编译错误继续合下一片 | 后续片无法验证，错误归因失真 |
| 就地改契约让问题消失 | 契约是唯一真源；且代价是砖头返工 |
| 就地改 ownership / 允许矩阵 | 改上游适配现状 = 双源漂移 |
