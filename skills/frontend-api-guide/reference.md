### 阶段 3：调用序列

#### 场景 1：新用户注册

```text
🔄 调用序列：新用户注册
━━━━━━━━━━━━━━━━

【角色】普通用户
【触发条件】用户填写邮箱和密码，点击"注册"

【调用步骤】

步骤 1：用户填写邮箱，点击"发送验证码"
  → 调用接口：POST /auth/send-code
  → 触发时机：用户点击"发送验证码"按钮
  → 需要传递：用户的邮箱地址
  → 会返回：验证码过期时间（秒）
  → 成功后：按钮变为"已发送（60s）"，开始倒计时
  → 失败时：
    - 发送过于频繁 → 提示"发送过于频繁，请稍后重试"
    - 邮箱已注册 → 提示"该邮箱已注册，请直接登录"

步骤 2：用户输入验证码，前端验证
  → 调用接口：POST /auth/verify
  → 触发时机：用户输入 6 位验证码后自动提交
  → 需要传递：用户的邮箱地址、验证码
  → 会返回：验证是否成功
  → 成功后：启用注册按钮
  → 失败时：
    - 验证码错误 → 提示"验证码错误"，清空输入框
    - 验证码已过期 → 提示"验证码已过期，请重新发送"

步骤 3：用户点击"注册"
  → 调用接口：POST /auth/register
  → 触发时机：用户点击"注册"按钮
  → 需要传递：邮箱地址、密码、姓名
  → 会返回：登录令牌、用户信息（ID、姓名、邮箱）
  → 成功后：存储登录令牌，跳转首页
  → 失败时：
    - 邮箱已注册 → 提示"该邮箱已注册，请直接登录"
    - 密码强度不足 → 提示"密码需包含 8 位以上，含字母和数字"

【调用流程图】

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant A as API

    U->>F: 填写邮箱，点击"发送验证码"
    F->>A: POST /auth/send-code
    A-->>F: 200 验证码过期时间
    F-->>U: 按钮变为"已发送（60s）"

    U->>F: 输入验证码
    F->>A: POST /auth/verify
    A-->>F: 200 验证成功
    F-->>U: 启用"注册"按钮

    U->>F: 点击"注册"
    F->>A: POST /auth/register
    A-->>F: 200 登录令牌和用户信息
    F-->>U: 跳转首页
```
```

### 阶段 5：错误处理速查表

```text
⚠️ 错误处理速查表
━━━━━━━━━━━━━━━━

【通用错误处理】

| HTTP 状态码 | 前端行为 |
|:----------:|---------|
| 401 | 清除本地登录令牌，跳转登录页 |
| 429 | 提示"操作过于频繁，请稍后重试" |
| 500 | 提示"服务器繁忙，请稍后重试" |

【业务错误处理】

| 接口 | 错误类型 | 前端行为 |
|-----|----------|---------|
| 发送验证码 | 邮箱已注册 | 提示"该邮箱已注册" + "去登录"链接 |
| 发送验证码 | 发送过于频繁 | 按钮禁用 60 秒 + 提示"发送过于频繁" |
| 验证邮箱 | 验证码错误 | 提示"验证码错误" + 清空输入框 |
| 验证邮箱 | 验证码已过期 | 提示"验证码已过期" + 显示"重新发送" |
| 用户注册 | 邮箱已注册 | 提示"该邮箱已注册" + "去登录"链接 |
| 用户注册 | 密码强度不足 | 表单标红 + 提示密码要求 |
```

## UI 映射模式参考

### 模式 1：列表渲染

```text
| UI 区域 | 元素 | 对应数据 | 数据处理 | 空状态 |
|---------|------|---------|---------|--------|
| 订单列表 | 订单号 | 响应中的订单编号 | 直接显示 | "暂无订单" |
| 订单列表 | 金额 | 响应中的订单金额 | 格式化：¥{金额} | - |
| 订单列表 | 状态 | 响应中的订单状态 | 枚举映射 | - |
```

### 模式 2：条件渲染

```text
| UI 条件 | 显示元素 | 对应数据 |
|---------|---------|---------|
| 用户等级 >= 2 | VIP 标识 | 响应的用户等级编号 |

| 订单状态为"已发货" | "确认收货"按钮 | 响应的订单状态 |
