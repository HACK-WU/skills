# 数据与状态变更类 影响策略

## 概述

**目的**：数据层改动的影响**不可回滚地落盘**，且消费方往往跨模块、跨服务、跨离线任务。本策略聚焦三件事：数据守恒（少了/多了）、存量口径（老数据怎么办）、读写匹配（改了写没改读）。

**使用场景**：DDL、字段增删改、枚举值调整、状态机流转、缓存键设计、配置默认值变更。

## 增量必查（四维之外额外必查）

| # | 必查项 | 必查问句 | 未通过时 |
|---|--------|----------|----------|
| 1 | **数据守恒三问** | 流向变了吗？数量变了吗（丢/重/多）？内容还是原样吗？ | 任一变 → 追全部消费方 |
| 2 | **读写匹配** | 改了写入端的字段，读取端（查询/报表/导出/搜索索引/下游同步）都改了吗？ | 列出未同步的读取方，升级 🔴 |
| 3 | **存量数据口径** | 历史数据在新字段/新枚举/新状态下取什么值？默认值合法吗？是否需要回填？ | 未定义 → 🔴（上线即脏数据） |
| 4 | **空值与可空性** | 新增列可空吗？代码是否假定非空？唯一索引遇 NULL 的行为确认了吗？ | 逐条确认 |
| 5 | **迁移与回滚** | 迁移脚本可重复执行（幂等）吗？大表锁多久？失败怎么回滚？回滚后新数据怎么办？ | 不可回滚 → 标 P0 |
| 6 | **缓存与索引一致性** | 缓存键是否变化？变更后旧缓存会命中错误数据吗？搜索/物化视图/统计表需要重建吗？ | 列失效策略 |
| 7 | **状态机合法性** | 新状态是否在所有流转路径上被处理？旧状态的历史记录是否仍能被读取/展示？ | 列未处理分支 |

**第 1 项按数据链画双轨**：正常轨（生产 → 消费）+ 异常轨（catch 后跳过 / 重试 / 补偿），异常轨静默丢数据是最常见的守恒破坏。

## 维度优先级调整

| 维度 | 默认 | 本策略 | 理由 |
|------|------|--------|------|
| 数据流（3.3） | 🟡 | **🔴 必给结论，且必须追到终端消费方** | 本策略的核心 |
| 调用链（3.1） | 🔴 | 🔴 | 读该表的模块/服务/离线任务全部要列 |
| 执行场景（3.4） | 🟡 | **🔴** | 并发写、重复执行、迁移中断都在场景维度暴露 |
| 条件路径（3.2） | 🟡 | 🟡 | 枚举/状态下升级 |

## 必测清单

- [ ] 迁移脚本空库执行 + 有数据执行 + 重复执行（幂等）
- [ ] 存量数据回填后的口径抽查（新字段非空率、枚举分布）
- [ ] 写入 → 各读取端（页面/报表/导出/下游同步）的端到端验证
- [ ] 并发写入与唯一约束冲突
- [ ] 缓存失效后的一致性验证
- [ ] 回滚演练（脚本 + 已写入新格式数据的处理）

## 不做什么

| 不做 | 交给 |
|------|------|
| 数据模型设计、ER 图、数据流图 | `data-flow-model` |
| 索引的建立与维护（建 / 更新 `.fe-index`） | `backend-index`；本 skill 只**按 3.0 查已有索引**做本次改动的影响推理，不维护索引 |
| 数据迁移脚本的编写与执行 | 交开发者 / `debug`（本 skill 只给影响与校验清单） |
| 性能影响（大表 DDL 锁表时长）的系统评估 | `performance-analysis`（本 skill 只提示风险，不量化） |
