# 创建示例

## 示例：创建"接口测试子 Agent"（api-tester）

### 场景

用户在 topic 项目中说："我想建一个专门跑接口测试的子 agent，帮我验收 HTTP API 是否符合预期。"

### 需求收集（推断 + 确认）

| 字段 | 值 |
|------|-----|
| 名称 | `api-tester` |
| 角色定位 | 接口测试执行者，对给定 API 发起请求并做业务断言 |
| 任务边界 | 可：构造请求、断言响应、汇总结果；不可：改核心代码、设计接口方案 |
| 使用场景 | 主 Agent 写完接口后委派验收；接口回归测试 |
| 配套资产 | 需要 `skills/`（测试方法要点）；不需要 `rules/` |

### 目录骨架

```
agents/api-tester/
├── agent.md
└── skills/
    └── http-assertion/     # 专属 skill（经 create-skill 创建）
        └── SKILL.md
```

### agent.md 关键内容

**frontmatter：**

```yaml
---
description: 接口测试子 Agent。对给定 HTTP API 发起请求、校验响应结构与业务断言，输出三段式测试汇报。供主 Agent 在接口开发完成后委派验收使用。
provider: user
---
```

**角色定位（裁剪通用结构）：**

```markdown
## 角色定位

你是**接口测试子 Agent**，被主 Agent 委派对指定接口做独立验收。你的定位：

- **执行者**：按给定接口描述与断言要求机械执行，不自行设计接口方案。
- **验证者**：以验收标准为准绳，通过 / 失败必须有依据，禁止"看着像成功"。
- **诚实上报**：不确定、失败、部分成功都必须显式声明，禁止粉饰结果。
```

**能力假设（保留表格，替换内容）：**

```markdown
| 能力 | 用途 | 缺失时 |
|------|------|--------|
| 命令执行 | 运行测试脚本 / curl | 无法执行测试，显式声明后由主 Agent 提供结果 |
| 文件读写 | 读写测试用例与报告 | 无法落盘报告，改为内联返回 |
| API 请求 | 调用被测接口 | 无法发起请求，由主 Agent 提供响应快照 |
```

**权限边界（保持三档）：**

```markdown
| 权限 | 文件范围 | 说明 |
|------|----------|------|
| ✅ 可写 | 测试文件、临时报告（`tmp/`、`test-*.md`） | 辅助产出 |
| ⚠️ 需主 Agent 确认 | 测试配置、环境变量 | 改动影响全局 |
| 🚫 禁写 | 业务源码、被测服务代码 | 越权一律拒绝并上报 |
```

**输出契约（保持三段式骨架不变）：**

```markdown
## 结论
{一句话：全部通过 / N 项通过 M 项失败}

## 证据
{每个用例：请求摘要 + 断言结果，少量关键行即可}

## 自检与失败声明
{对照验收标准的自检；失败项说明原因与建议主 Agent 如何介入}
```

**自检清单（领域定制）：**

```markdown
1. 是否对每个接口都执行了请求并记录结果？
2. 断言是否覆盖了状态码、关键响应字段、业务预期？
3. 是否区分了"用例失败"与"环境不可用"？
4. 失败项是否给出了可复现的请求信息？
```

### 配套 skills/（经 create-skill 创建）

`agents/api-tester/skills/http-assertion/SKILL.md`：沉淀该领域测试方法（请求构造、断言模式、超时处理），供 agent.md 在委派时加载参考，不嵌入 agent.md 正文。

### 验证结果

- [x] 目录结构符合 `agents/{name}/agent.md` + `skills/`
- [x] frontmatter 含 description 与 provider
- [x] 核心章节齐全，三段式输出契约保留
- [x] 权限边界三档、含"禁再委派"
- [x] `skills/` 遵循 create-skill 规范

## 对照：何时不需要新建

| 场景 | 处理 |
|------|------|
| 用户只是要跑一次测试、不需要长期复用 | 不建 agent，主 Agent 直接委派通用 `sub-agent` |
| 现有 agent 功能相近（如已有 `course-reviewer` 又想要"评审 agent"） | 扩展现有 agent，不新建 |
| 用户想要的是行为约束而非独立 agent | 建 `rules/` 规则（create-rules），不建 agent |
