# 专题记忆查询策略参考

ki-memory-lookup 的「专题记忆」查询策略细则。主流程见 SKILL.md。写入方为 `ki-memory-write`（专题记忆策略，由 expert-team 调用）。

## 定位

专题记忆 = 专家资产的**路标 + 快查卡**（由 expert-team 落盘后写入）。查询它用于知晓"有此专家 + 关键入口 + 去哪找详细"，**不替代加载专家资产本体**。

## 检索 API

| API | 用途 | 关键参数 |
|-----|------|----------|
| `ki_search` | 语义检索专题记忆 | `scope`（项目标识）、`query`（业务域词 + 常见问题词，与 INDEX 关键词呼应） |

- **scope**：项目标识，与写入时一致

## 检索方式

- 用**自然语言描述问题本质**（如"告警不触发怎么处理"、"登录模块在哪定义"），不要只搜单个单词
- query 带上业务域词 + 常见问题词（即专题记忆模板中的「检索触发词」字段内容）

## 利用结果

- **命中** → 知晓"有此专家 + 关键入口"（资产路径、一句话职责、核心能力、高频坑、关键代码位置、数据落地）
- **跳转前校验**：校验目标专家路径（`.module-experts/{名}/`）真实存在
  - 路径有效 → 据此跳回 expert-lookup 加载对应专家资产（若记忆已含答案且无需深挖，可直接参考记忆，不强制加载专家）
  - 路径失效 → 记忆已过时（僵尸记忆），不做误导性跳转，回退正常查找，并按需清理/更新该记忆
- **存量专家无记忆**（旧资产未落盘记忆）→ 首次命中时提示可用 expert-team 补建专题记忆（可选，不阻塞）

## 与专家资产的关系

- 专题记忆**只存路标不存专家本体**，避免双源漂移
- 与专家资产（契约层 C0~C4 + implementation/）互补：记忆=资产存在感 + 关键入口；资产=完整知识本体
- 与强关联（跨模块耦合）互补：专题记忆看模块**内**知识路标，强关联看模块**间**耦合
