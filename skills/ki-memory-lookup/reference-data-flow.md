# 数据流记忆查询策略参考

ki-memory-lookup 的「数据流记忆」查询策略细则。主流程见 SKILL.md。写入方为 `ki-memory-write`（数据流策略，由 expert-team 调用）。

## 定位

数据流记忆 = 数据实体粒度的可检索原子（实体 → 生产方/消费方/业务用途）。查询它用于"查某张表/某个字段/某条消息是哪个模块写的、被谁读、干什么用"，命中即得数据流向，不必重新翻代码。

## 检索 API

| API | 用途 | 关键参数 |
|-----|------|----------|
| `ki_search` | 语义检索数据流记忆 | `scope`（项目标识）、`query`（数据实体名 / 业务用途 / 生产消费方）、`tags`（固定 `data`） |
| `ki_query_group` | 按模块整组检索某分组的全部数据实体 | `scope`、`groups`（group 路径，如 `数据流/支付系统`） |

- **scope**：项目标识，与写入时一致

## 检索方式

- **按数据实体检索**：`ki_search(query="{表名/消息主题/缓存key} 谁写谁读")`，如 `ki_search(query="订单表 谁写谁读")`
- **按业务用途检索**：`ki_search(query="{功能描述} 数据")`，如 `ki_search(query="订单状态变更 数据")`
- **按模块整组检索**：`ki_query_group(groups="数据流/{功能模块名}")`，查某模块的所有数据实体流向
- **tags 过滤**（固定）：`ki_search` 一律用 **`tags="data"`** 过滤（数据流记忆写入时统一带 `data` tag），收窄范围提高准确度；**若过滤后命中过少/为空**（如历史存量数据未带该 tag），回退为去掉 tags 过滤的语义检索，避免漏召回

## 检索示例

```text
ki_search
  scope:  my-project
  query:  订单表 谁写谁读
  tags:   data
  limit:  10
```

## 利用结果

- **命中** → 得数据流向：实体类型 / 结构（表名或结构示例）/ 生产方 / 主要消费方 / 业务用途，直接据此定位代码或了解数据流向
- **详细消费逻辑** → 指向 C4（`.module-experts/{专家名}/C4-数据流向与消费.md`）
- **未命中 / ki 不可用** → 静默跳过，不阻塞主流程，回退正常读代码

## 与其它记忆的关系

- 数据流记忆看模块**内**的数据实体流向；专题记忆看模块**整体**路标；接口信息看模块**内**子功能接口；强关联看模块**间**耦合——四者粒度互补，各自独立 tag 检索
- **口径边界**：接口信息记"接口契约"（怎么调），数据流记"接口产生的数据落到哪"（数据去了哪）；同一"模块A写表X→模块B读表X"关系，数据流以数据实体视角记、强关联以模块视角记，可并存不重复
