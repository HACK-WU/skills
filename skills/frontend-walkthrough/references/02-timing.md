> **何时读**：页面存在异步依赖时（阶段 1.5 的 A 腿必读）；族 1 是十族里唯一必须配矩阵推演的。
> 族 2–10 的细则见 [INDEX.md](INDEX.md) 的族速查表与 [03](03-families-state-form.md) / [04](04-families-security-routing.md) / [05](05-families-runtime.md) 三个包。

## 缺陷推演细则（阶段 1.5）

> 目标：找出"页面看着正常、但用户一操作就坏"处。两套方法并用：**A 腿沿时间轴摆时序**（问"在这条时序上用户还能做什么、做完会发生什么"），**B 腿按缺陷族问"哪种真实输入或状态下就坏"**。
> 与 `scenario-rehearsal` 代码模式同源（场景实例化 + 纸上执行 + 降级护栏），区别：本处只做**前端页面级**推演（时序矩阵 + 十类缺陷族），且每条假设必须回阶段 2 实操复现。

## 三张清单怎么从代码里抠

| 清单 | 找什么（代码信号） | 为什么重要 |
|---|---|---|
| **异步源** | 请求封装（`axios` / `fetch` / `api/*` / `useQuery` / `useSWR` / `useRequest`）、`setInterval` / 轮询 / `refetchInterval`、`WebSocket` / `EventSource`、`localStorage` / `IndexedDB`、`watch` 路由 query 触发的请求 | 决定"哪些时刻数据是残缺 / 过期的" |
| **可写动作** | `onSubmit` / `@submit`、`onClick` / `@click` 里触发的 POST / PUT / PATCH / DELETE、上传、导出、批量、状态开关 | 决定"哪些操作有不可逆后果" |
| **状态落点** | 组件 state（`useState` / `ref` / `reactive`）、全局 store（`commit` / `dispatch` / `set`）、URL 参数（`router.push`）、本地存储 | 决定"残留 / 串台"能活多久、跨不跨页面 |

> **起点不是页面，而是动作**：对每个可写动作问一句"它用的数据从哪来、写完写到哪去"。答案在接口 → 存在"未就绪窗口"；答案在 store → 存在"残留窗口"。

## A 腿：交叉矩阵模板（异步态 × 动作）

行 = 异步态，列 = 动作，只填"可能真坏"的格（编号对应假设 ID）：

```text
| 异步态 \ 动作 | 点保存 | 改筛选 | 切详情 | 连点导出 |
|--------------|--------|--------|--------|----------|
| 请求中（数据未返回） | A1 |  -  |  -  |   -   |
| 请求失败           | A2 |  -  |  -  |   -   |
| 返回乱序（后发先至） | -  | A3 | A4 |   -   |
| 200 但业务错误码    | A5 |  -  |  -  |   -   |
| 会话过期 401       | A6 |  -  | A6 |   -   |
```

`-` 表示经判断无风险或不可达，**须能说出理由**，不得为填满矩阵而编造。同一假设可覆盖多格（复用编号，如上表 A6 同时命中"点保存"与"切详情"）。


## 族 1｜时序与并发（A 腿矩阵，四个追问角度）

1a. 竞态与顺序
- 快速改筛选 / 搜索 / 翻页 / 切 tab，后发请求先返回 → 旧结果盖掉新结果（无 `AbortController`、无请求序号校验）
- 切页 / 关弹窗后旧请求回来仍写 state（`useEffect` 无 cleanup / 无 abort）
- 异步函数内读到旧闭包变量（`for` + `await`、事件监听里读旧 state、`setTimeout` 里的快照）
- 轮询与手动刷新并发 → 同一列表两份数据交替覆盖
- 异步校验（用户名 / 编码唯一）乱序返回，旧校验结果覆盖新结果
- 多标签页 / 多端并发：A 页已删除或改过该记录，B 页仍用旧数据提交 → 覆盖或"复活"已删数据

1b. 就绪拦截
- 数据未返回时"保存 / 提交"可点，表单用初始空值提交 → **覆盖原数据**（最高频、后果最重）
- `useState(props.data)` 只初始化一次，props 后到不再同步 → 永远是空表单
- 列表为空 / 加载失败时"全选 / 批量 / 导出"仍可点
- 详情未加载完，删除按钮已可点 → 用了旧 id / 空 id
- 权限判断只在入口路由做，按钮层未判断（靠后端兜底，前端已跳错流程）

1c. 失败收尾
- `catch` 里没把 loading 置 false、无 `finally` → 永久转圈
- 乐观更新（先改 UI 再发请求）失败不回滚 → 界面显示成功、实际没生效
- 失败后保留半截数据仍可提交（部分字段成功、部分失败）
- `Promise.all` 一个失败整体进 catch，已成功请求的结果既不回滚也不提示
- 请求无超时设置 → 永久 pending，用户只能刷新
- 拦截器统一 toast 后 `return` 了值 / resolve 了 promise，**调用方仍走成功分支** → 拿 `undefined` 继续执行

1d. 重复执行
- 提交按钮无 loading / 不禁用 → 双击产生两条数据
- 成功后不跳转、不清表单 → 用户自然再点一次
- 重试按钮无节流 → 点 N 次发 N 次
- 浏览器返回（bfcache）后页面仍是提交前状态，用户再提交一次
- 上传 / 导出重复触发，前端无任务去重 key


## 各框架高频信号（快速定位风险面）

| 栈 | 高发信号 |
|---|---|
| React | `useEffect` 依赖缺失 / 无 cleanup、闭包旧 state、卸载后 `setState`、`key={index}`（删除后状态串位）、`useState(props.x)` 只初始化一次、`useMemo` 依赖不全 |
| Vue 2/3 | `watch` 未 `immediate` / `deep`、`beforeDestroy` / `onUnmounted` 未清 timer 与监听、`keep-alive` 未在 `activated` 刷新、直接改 props、`v-for` key 用 index |
| 小程序 / 移动端 | 页面栈返回未在 `onShow` 刷新、`onUnload` 未清定时器、`setData` 异步导致读到旧值 |
| 通用 | 请求层无超时 / 无取消 / 无重试上限、拦截器统一兜底但调用方不知情、`async` 事件处理未 `try/catch` |

## 复现手段（A 档照做，B/C 档写进复现步骤交用户）

| 要造的异步态 | A 档做法 | B / C 档 |
|---|---|---|
| 请求中 / 慢 | DevTools 限速（Slow 3G）、代理加延迟 | 写进复现步骤交用户执行 |
| 失败 | 断网、Block request URL、mock 500 | 同上；代码层只能 `🟡` |
| 超时 | 指向不响应的地址 / 代理丢弃请求 | 同上 |
| 乱序返回 | 拦截器按 URL 加延迟，让先发请求回得更晚 | 多数环境造不出 → 保留假设 |
| 200 但业务错误 | mock `{ code: 500, msg: ... }` | 同上 |
| 401 中途 | 清 token / 改过期时间，在操作中途触发 | 请用户在另一标签页登出 |
| 空 / 缺字段 | mock 精简响应体（去掉 `list`、字段置 `null`） | 代码层可证 `🟡` |
| 连点 | 连续快速点击 / 脚本触发多次 click | 请用户手动连点 |

非时序族怎么造（同两列）：

| 族 | A 档做法 | B / C 档 |
|---|---|---|
| 5 形态 / 计算 | 改 mock：缺字段、`null`、`0`、超长串、emoji、时区偏移、极大数 | 代码层可证 `🟡` |
| 4 输入 | 全角、首尾空格、超长、emoji、负数、极大值、粘贴富文本、IME 逐字输入 | 列出输入清单请用户照输 |
| 6 权限 | 低权限账号、手改 URL / query、直接调接口、Tab 聚焦隐藏控件 | 请用户用受限账号试 |
| 9 兼容 | 视口 375 / 768、浏览器缩放 125%~200%、Safari 或 iOS 真机 | 请用户提供对应截图 |
| 8 集成 | Block SDK 域名、baseURL 指错、模拟旧 chunk（改名或清缓存后停在旧页） | 说明预期现象请用户复现 |

## 判定与证据（三轨，别一律 `🟡`）

| 轨 | 适用 | 等级 |
|---|---|---|
| **写法缺失**：没有权限判断、没有转义、没有 cleanup、没有超时、没有 ErrorBoundary、`catch` 空 | 族 2 / 3 / 6 / 10 多数 | 代码直读 `🟢`（缺失即证据） |
| **时序 / 组合会坏**：未就绪即提交、竞态覆盖、边界输入炸掉、断点破版 | 族 1 / 4 / 5 / 7 / 9 | 推演 `🟡` + `[需运行验证]`，实操复现升 `🟢` |
| **不可静态确定**：三方库内部、后端真实返回、可利用性、真实网络时序 | 全族 | 只列假设，`🔴` 进待确认，写清验证方法 |

- **造不出时序 / 造不出环境** → 保留 `🟡`，写"未复现 + 尝试过什么"，进待确认清单
- **五要素齐全才算发现**：触发条件（数据 / 账号 / 时序 / 输入）→ 操作 → 观察点 → 预期 vs 实际 → 后果与影响谁

## 常见误报（先排除，再报）

| # | 情形 | 为什么不报 | 例外（仍要报） |
|---|---|---|---|
| 1 | 理论上不可达（死分支、被上层校验拦住） | 不可达即无风险 | 能给出真实可达路径（如通过 URL 直进、权限绕过） |
| 2 | 需毫秒级交错、真实用户几乎不可能触发 | 无实际概率 | 常规操作为限速 / 网络抖动下即可触发 |
| 3 | 已有全局兜底（ErrorBoundary、拦截器统一提示、后端幂等 / 唯一键） | 后果已被吸收 | 兜底本身有缺口（只提示不阻断、幂等键未带、提示后仍继续执行） |
| 4 | 框架已自带保护（React 18 卸载后 `setState` 不再告警） | 不是缺陷 | 旧版本、或自定义订阅仍会泄漏 → 报并注明版本 |
| 5 | 测试环境特有（mock 数据缺字段、时钟偏差） | 非产品问题 | 生产数据同样可能缺字段（后端允许为空） → 报 |
| 6 | 后端也会校验 / 兜底的前端缺口 | 绕过不产生真实后果 | 仍是问题：前端假成功、越权可见、错误提示误导用户 → 按体验或安全问题报，并注明后端是否兜住 |
| 7 | 第三方组件 / SDK 内部实现缺陷（不在本仓库代码） | 改不了 | 我方"未做降级 / 未做失败处理"这一层 → 报（只报这一层） |
| 8 | 纯防御性建议（"建议加个防抖""建议补埋点"） | 没有具体触发路径 | 能说清"哪个真实场景下会坏" → 报；否则归体验增强，不进潜在缺陷 |
