# 细则 06｜加载性能体检（阶段 3）

> **何时读**：阶段 3。只回答"有没有问题、在哪"，**不给优化方案**（深入交 performance-analysis）。

## 加载性能体检细则（阶段 3）

### 指标与采集

| 指标 | 含义 | 采集方式 | 粗判读基线 |
|---|---|---|---|
| 首屏时间 / FCP | 首次内容绘制 | Performance API / 性能面板 | > 2s 需关注（视场景） |
| LCP | 最大内容绘制 | 同上 | > 2.5s 需关注 |
| CLS | 布局偏移 | 同上 | > 0.1 需关注 |
| INP | 交互响应 | 同上 | > 200ms 需关注 |
| TTFB | 首字节 | 网络面板 | > 800ms 需关注 |
| 资源瀑布 | 请求串行 / 阻塞关系 | 网络面板 | 首屏关键路径串行 > 3 段需关注 |
| 图片体积 | 单图大小 | 网络面板 | 首屏图 > 500KB 需关注 |
| 包体积 | JS / CSS 体积 | 构建产物 / 构建分析 | 首包 JS > 1MB 需关注 |

> **基线是"需关注"提示线，不是判定不合格**——最终是否算问题要结合场景（内网后台 vs 公网 C 端）。禁止把基线数字当结论硬扣。

### 采集降级链（按顺序尝试）

1. 浏览器工具求值 Performance API / PerformanceObserver（A 档首选）
2. Lighthouse（工具能跑就跑；跑不了请用户跑）
3. 用户提供性能面板截图 / Lighthouse 报告
4. 都没有 → 只报代码层反模式（`🟡`），报告头声明"未实测"

### 记录要求

- **LCP 必须指出是哪个元素**（"首屏大图"而不是"LCP 慢"）
- **CLS 必须指出哪个组件在跳**（图片未设尺寸？字体加载？）
- 涉及接口本身慢的 → 记"疑似后端"并**交接 `performance-analysis`**，不在本 skill 展开
- 每条给**定位方向**即可，不给优化实现方案

### 交接 `performance-analysis` 的输入

```
性能发现：首屏 LCP 3.2s
证据：🟢 实测（Performance API）
定位方向：首屏 banner 图 2.4MB 未压缩 + 列表接口 900ms 串行在图片之后
建议：前端侧图片优化 + 接口侧耗时分析（后者请 performance-analysis 深入）
```
