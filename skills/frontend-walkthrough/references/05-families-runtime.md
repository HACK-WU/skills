# 细则 05｜缺陷族 8–10：集成与依赖 / 环境兼容 / 错误兜底

> **何时读**：阶段 1.5 预筛命中族 8 / 9 / 10（有第三方 SDK、发版频繁、移动端 H5）。
> 族 8 的"发版后旧 chunk 白屏"是线上投诉高频项，后台与运营页必过。

## 族 8｜集成与依赖（自己代码没错，但外部一抖就白屏）

- **发版后旧页面拿不到新 chunk**：`ChunkLoadError`、点菜单白屏（无自动刷新或提示）——线上投诉高频
- 第三方 SDK 失败或超时无降级：埋点、地图、支付、验证码、客服
- 静态资源 CDN 404、混合内容（https 页面引 http）、跨域未配
- 环境与配置：baseURL 指错、测试打到生产、开关未生效
- 埋点重复上报或漏报（影响业务数据）
- 请求封装不一致：有的带 token / 有的不带、有的带 loading、有的吞错
- 依赖冲突与 polyfill 缺失（同一库两个版本、旧浏览器没兜底）

## 族 9｜环境与兼容

- 响应式断点破版：窄屏横向滚动、固定头尾遮挡内容、表格挤压不可读
- 移动端软键盘顶起 / 遮挡输入框、安全区（刘海、底部横条）
- Safari / iOS 差异：日期字符串解析、正则 lookbehind、`100vh`、点击延迟、粘贴限制
- 浏览器缩放与字体放大（用户设 125%）后布局与截断
- 暗色模式对比度、打印样式丢失
- bfcache 前进后退看到旧数据
- 多端一致性：同一功能 Web 与 H5 行为不同

## 族 10｜错误兜底与可观测

- 无 ErrorBoundary / 全局错误监听 → 一个组件报错整页白屏
- 错误码不分类：网络错误、业务错误、校验错误同一句提示
- `catch` 空实现 / 只 `console` / 只 toast 不恢复 → 用户卡在中间态
- 无重试与降级 UI（接口挂了只剩空白）
- 图片加载失败无占位与兜底图
- 静默失败：异步任务失败无任何出口，用户以为成功
- 前端无错误上报 → 线上问题无法定位（只报缺失，不展开方案）

> **边界三条**：① 只收**能在用户操作路径上表现出来**的缺陷（点击 / 输入 / 导航 / 异常时真会坏）；纯代码整洁、命名、可维护性不进（`code-review`）。② 安全只报写法缺口与可见面，**不构造利用链、不做渗透**。③ 加载性能不在本包（族 9 只到"破版 / 不可操作"，性能见 [06-performance.md](06-performance.md)）。
