## 一、前端代码直读检查表（阶段 1）

### 1.1 入口穷举与页面登记

**从哪找页面清单**：

| 技术栈 | 找什么 |
|---|---|
| Vue / React | 路由配置（`router/index`、`createBrowserRouter`）、页面组件目录 |
| Next.js / Nuxt | `pages/` 或 `app/` 目录结构 |
| 小程序 | `app.json` 的 `pages` 数组 |
| 多页应用 | 构建配置的 entry |

**登记表**（防漏，逐项填）：

```
| # | 页面/入口 | 路由 | 类型（列表/详情/表单/看板） | 主要操作 | 是否走查 |
```

**常见漏点**（必须主动排除）：

- 弹窗 / 抽屉型流程（Dialog / Modal / Drawer 里藏着一整套操作）
- 带参详情页（列表点进去才有）
- 登录后才可见的路由（权限路由）
- 冷门页（帮助、条款、404、错误页）—— 错误页恰恰最值得看
- 管理端与用户端两套入口

### 1.2 状态矩阵八态

每页逐态核对"代码里有没有实现"（符合性判定，`🟢`）：

| 状态 | 代码里怎么找 | 常见缺失 |
|---|---|---|
| **默认态** | 组件默认渲染分支 | - |
| **加载态** | `loading` / `isLoading` / `Suspense` / Skeleton | 首屏无 loading；表格有、卡片没有 |
| **空态** | `Empty` / `length === 0` 分支 | 无空态直接白屏；空态无引导文案 |
| **错误态** | `catch` / `error` 分支渲染 | 只 `console.error`、只弹通用 toast、无重试入口；**会话过期（401）**处理缺失（操作到一半跳登录、草稿丢失） |
| **无权限态** | 权限判断分支 / 403 路由 | 直接跳登录、只显示"操作失败" |
| **长文本** | 无 `overflow` / `ellipsis` / `line-clamp` 处理 | 撑破布局、无 Tooltip 看全 |
| **大数据量** | 分页 / 虚拟滚动 / 懒加载 | 一次性渲染全量、无总数提示 |
| **窄屏** | 断点 / 响应式规则 | 无断点、表格横向溢出无提示 |

> **错误态的三种典型缺陷**：① 有 toast 但不说明原因 ② 有原因但不给下一步（重试/返回）③ 网络错误与业务错误提示混淆。

### 1.3 交互实现检查表

| 类别 | 检查项 | 常见问题 |
|---|---|---|
| **表单** | 校验时机、错误定位、必填标识、长度限制提示 | 只能提交后才发现错误；错误在顶部但字段在屏幕外；必填无标识 |
| **提交** | loading 态、防重复提交、成功反馈、失败反馈 | 双击提交两次；loading 期间按钮仍可点；成功只闪一下就消失 |
| **危险操作** | 二次确认、可否撤销、影响范围说明 | 直接删；确认文案不说明影响多少条 |
| **长任务** | 进度反馈、可中断、超时提示 | 一直转圈无进度；无法取消 |
| **列表** | 分页 / 虚拟滚动、批量操作、筛选与翻页状态保持 | 改筛选仍在第 2 页（显示空）；批量无全选 |
| **中断恢复** | 刷新 / 返回后状态保留、草稿 | 填了一半刷新全丢；返回后筛选清空 |
| **默认值与记忆** | 常用值预填、上次选择记住 | 每次都从零选（如日期范围默认空） |
| **可发现性** | 关键功能入口层级、术语 | 功能藏在三级菜单；术语自造词 |

### 1.4 可用性实现检查表

| 项 | 检查点 |
|---|---|
| 键盘可达 | Tab 顺序合理；Esc 关弹窗；Enter 提交；焦点不丢 |
| 语义标签 | `button` vs `div`；`label` 与输入框关联；图片 `alt` |
| 焦点管理 | 弹窗打开焦点进入、关闭焦点回位；路由切换焦点重置 |
| 点击区域 | 可点击元素 ≥ 约 44×44px（移动端）；图标按钮有无热区 |
| 对比度 | 有明确色值时可判（正文与背景对比不足）；仅色值可判才标 `🟢` |
| 表单引导 | placeholder 不能替代 label；错误提示与字段相邻 |

### 1.5 性能反模式速查（代码层信号）

| 反模式 | 代码信号 | 影响 |
|---|---|---|
| 首屏阻塞 | 同步 `<script>`、大 CSS、未 `defer`/`async` | 白屏时间长 |
| 未代码分割 | 路由未 `lazy`、单包全量引入 | 首包过大 |
| 图片未优化 | 无 `loading="lazy"`、无 `srcset`、原图直出 | 流量大、LCP 慢 |
| 请求瀑布 | 组件内串行 `await` 多个接口 | 首屏叠加等待 |
| 重复请求 | 无缓存 / 无去重（同一接口多处调用） | 浪费、闪烁 |
| 长列表未虚拟化 | `v-for` / `map` 全量渲染 | 卡顿、内存高 |
| 输入无防抖 | `onChange` 直接请求 | 请求风暴 |
| 超大依赖 | 全量 `lodash`、`moment`、未按需引入 UI 库 | 包体大 |

## 二、状态矩阵与操作细则（阶段 2）

### 2.1 八态怎么造出来

| 状态 | 制造方法 | 工具不支持时 |
|---|---|---|
| 加载态 | 网络限速 / 节流（DevTools Throttling）、指向慢接口 | 读代码确认分支 + 请用户录屏 |
| 空态 | 新账号 / 清空数据 / 筛选无结果条件 | 请用户提供空态截图 |
| 错误态 | 断网、改错接口 URL、输入非法值、临时 mock 500 | 读代码看 catch 分支（`🟡`） |
| 无权限态 | 低权限账号访问高权限页 | 读权限判断分支 |
| 长文本 | 输入 / 造超长内容（200+ 字符） | 读有无 `ellipsis` 处理 |
| 大数据量 | 造 10000 条（脚本 / 接口批量造数） | 读有无分页 / 虚拟滚动 |
| 窄屏 | 窗口缩到 375px / 移动端模拟 | 读断点规则 |
| 默认态 | 直接打开 | - |

### 2.2 三类路径设计

| 路径 | 设计要点 | 例子 |
|---|---|---|
| **正面** | 正常完成核心任务的最短路径 | 搜索 → 找到 → 打开 → 操作成功 |
| **边界** | 极端输入与数据量 | 0 条 / 10000 条 / 超长文本 / 特殊字符 / 全选 |
| **负面** | 故意做错，看系统怎么应对 | 空提交、重复提交、断网提交、越权访问、中途返回 |

### 2.3 场景轴问句全集（用户视角）

**A. 新用户首次**

- 入口找得到吗？（导航命名是否说人话）
- 知道下一步该干什么吗？（空态 / 首次引导）
- 术语需要看文档才能懂吗？
- 出错了他知道怎么办吗？

**B. 高频老用户**

- 核心任务几步完成？有没有多余确认 / 跳转 / 等待？
- 重复输入多吗？（每次都要重选相同条件）
- 有批量 / 快捷键 / 记忆 / 复制上一条吗？

**C. 误操作**

- 危险操作有确认吗？确认文案说清影响了吗？
- 能撤销 / 恢复吗？
- 错误提示说人话吗？（给原因 + 下一步，不甩错误码）

**D. 中断 / 异常**

- 刷新 / 返回后填的内容还在吗？
- 断网 / 超时时的提示与恢复路径？
- 重复提交会发生什么？（下单两次？）
- 长任务能离开页面再回来吗？

**E. 极端数据**

- 超长文本截断了吗？能看全吗？
- 空值 / `null` / `undefined` / `NaN` 怎么显示？（直接裸露即缺陷）
- 时间 / 金额 / 数字格式化正确吗？（单位、千分位、时区）
- 0 条 / 1 条 / 10000 条分别什么表现？

### 2.4 发现记录模板

```
现象：筛选"已取消"后翻到第 2 页，再改筛选条件，列表空白且无提示
复现：订单页 → 筛选已取消 → 翻第 2 页 → 改筛选为"待付款" → 列表空白
影响：所有用户；任务"按状态查订单"被卡住；高频
证据：🟢 实操截图 3 张 + `OrdersTable.vue:88`（页码 state 未随筛选重置）
方向：筛选变更时重置页码，或空结果给"当前页无数据，回到第 1 页"引导
```

## 三、加载性能体检细则（阶段 3）

### 3.1 指标与采集

| 指标 | 含义 | 采集方式 | 粗判读基线 |
|---|---|---|---|
| 首屏时间 / FCP | 首次内容绘制 | Performance API / 性能面板 | > 2s 需关注（视场景） |
| LCP | 最大内容绘制 | 同上 | > 2.5s 需关注 |
| CLS | 布局偏移 | 同上 | > 0.1 需关注 |
| INP | 交互响应 | 同上 | > 200ms 需关注 |
| TTFB | 首字节 | 网络面板 | > 800ms 需关注 |
| 资源瀑布 | 请求串行 / 阻塞关系 | 网络面板 | 首屏关键路径串行 > 3 段需关注 |
| 图片体积 | 单图大小 | 网络面板 | 首屏图 > 500KB 需关注 |
| 包体积 | JS / CSS 体积 | 构建产物 / 构建分析 | 首包 JS > 1MB 需关注 |

> **基线是"需关注"提示线，不是判定不合格**——最终是否算问题要结合场景（内网后台 vs 公网 C 端）。禁止把基线数字当结论硬扣。

### 3.2 采集降级链（按顺序尝试）

1. 浏览器工具求值 Performance API / PerformanceObserver（A 档首选）
2. Lighthouse（工具能跑就跑；跑不了请用户跑）
3. 用户提供性能面板截图 / Lighthouse 报告
4. 都没有 → 只报代码层反模式（`🟡`），报告头声明"未实测"

### 3.3 记录要求

- **LCP 必须指出是哪个元素**（"首屏大图"而不是"LCP 慢"）
- **CLS 必须指出哪个组件在跳**（图片未设尺寸？字体加载？）
- 涉及接口本身慢的 → 记"疑似后端"并**交接 `performance-analysis`**，不在本 skill 展开
- 每条给**定位方向**即可，不给优化实现方案

### 3.4 交接 `performance-analysis` 的输入

```
性能发现：首屏 LCP 3.2s
证据：🟢 实测（Performance API）
定位方向：首屏 banner 图 2.4MB 未压缩 + 列表接口 900ms 串行在图片之后
建议：前端侧图片优化 + 接口侧耗时分析（后者请 performance-analysis 深入）
```

## 四、双视角研判与"人性化"问句集（阶段 4）

### 4.1 误报过滤清单（先过滤，再分拣）

报道前先过一遍：以下情形**默认不算问题**，除非满足「例外」列的条件。这是防报告注水的闸门。

| # | 情形 | 为什么不算 | 例外（仍要报） |
|---|------|-----------|---------------|
| 1 | 有意取舍：MVP 未做暗色 / i18n / 审计日志 / 批量导入 | 可能是有意省略 | 需求文档明确要求 → 算（标"未实现"） |
| 2 | 第三方组件 / 浏览器默认行为（原生 select 样式、输入法候选框、日期控件） | 非本产品实现 | 造成实际可用性障碍（无法操作 / 无法理解） → 算 |
| 3 | 平台约定差异（Mac / Windows 快捷键、滚动方向） | 遵循平台约定即正确 | 与产品内其他页面不一致 → 算（一致性问题） |
| 4 | 纯美术观感（配色品味、精致度、动效美感） | 属 `product-manager` M4 / `ui-designer` 边界 | 影响可用性（对比度不足、误读、点击区域过小） → 算 |
| 5 | 低频场景的体验劣势（季度操作多两步、极端边缘数据） | 价值 × 成本不划算 | 落在核心高频任务上 → 算 |
| 6 | 已在台账的已知问题（已登记待修 / 已有 issue） | 不是新发现 | 未登记 → 算（标"疑似已登记，请确认"） |
| 7 | 测试环境特有现象（脏数据、时区、缓存、本地网络） | 非产品问题 | 生产可复现 → 算（附复现证据） |
| 8 | 与规格一致的"故意设计"（提交后不可改、审批后锁定） | 设计如此 | 违背用户预期且界面无任何说明 → 算（体验优化） |
| 9 | 个人偏好式主张（"我觉得该用蓝色""感觉不够高级"） | 无证据的偏好 | 有可用性 / 一致性 / 规范证据 → 算 |

**过滤后的处置**：

- 被过滤项 → 写入报告第 5 节「经走查排除」并写明依据（"经确认属有意取舍，非缺陷"）
- 拿不准是否算的 → 进第 6 节「待确认清单」，**不硬判**
- **禁止反向滥用**：不得用本清单把真问题洗白（说"有意取舍"必须给依据，给不出则照报）

### 4.2 归属判定表（先分拣，防越界）

| 走查发现 | 归属 |
|---|---|
| 前端体验缺陷（反馈 / 容错 / 状态 / 路径） | **本清单**（体验优化） |
| 前端实现缺陷（状态缺失 / 错误处理 / 无障碍 / 性能反模式） | **本清单**（实现修复） |
| 前端加载性能问题 | **本清单**（体检级）+ 提供方向 |
| "让现有功能更好用"的补充（批量 / 撤销 / 记忆 / 快捷键 / 中断恢复） | **本清单**（体验增强） |
| 产品级功能缺失（这个功能压根没有：导出 / 审批流 / 消息中心） | 交 `product-manager` M3 |
| 纯代码质量（命名 / 架构 / 设计模式 / 目录结构） | 不进清单；需修走 `code-review` |
| 后端接口 / 链路性能 | 交 `performance-analysis` |
| 纯美术观感（配色品味 / 精致度 / 动效美感） | 交 `product-manager` M4 或 `ui-designer` |
| 功能正确性缺陷（功能坏了） | 交 `debug`（本 skill 只记录现象） |

### 4.3 优先级评分

- **Kano 分类** + **价值 × 成本**：口径与判定问句见 `use_skill("product-manager")` 的 `reference.md` 第一节（未安装则按同口径自主推理）
- **本 skill 的 P0 硬门槛**（比通用口径更严，因为走查发现多为"改进"而非"缺失"）：
  - 核心任务被卡住（无法完成 / 数据看起来丢失 / 可能造成损失），**或**
  - 高频场景 + 低成本修复
  - 不满足却想标 P0 → 必须在排序理由里写明破例原因
- 判定依据不足 → 标 `Kano 待定` 进待确认，**不得默认按"期望"参与排序**

### 4.4 "人性化"可检验问句集

把空泛的"人性化""友好度"翻译成可判定的问句——**每条发现必须能落到其中至少一个问句**：

| 族 | 问句 |
|---|---|
| **省力** | 常用值预填了吗？记住上次选择了吗？能批量吗？有快捷键吗？能复制上一条吗？ |
| **安全感** | 危险操作确认了吗？能撤销吗？填一半会丢吗？会重复提交吗？ |
| **掌控感** | 长任务有进度吗？能中断吗？能恢复吗？知道自己现在在哪一步吗？ |
| **明白** | 文案说人话吗？错误给原因 + 下一步了吗？空态给引导了吗？术语不用查文档吗？ |
| **效率** | 几步完成？几次等待？几次跳转？ |
| **一致** | 同类操作用同一套组件 / 术语 / 反馈口径吗？ |

> 反面教材（禁止写进报告）：❌"交互不够人性化" ❌"用户体验有待提升" ❌"感觉不够友好"。必须写成"**{哪类用户} 在 {什么任务} 下要 {几步/几次重复/无法恢复}**"。

## 五、报告完整模板与落盘

### 5.1 落盘规范

- **默认**：直接输出到对话
- **用户要求落盘**时：写 `.walkthrough/{slug}-{YYYYMMDD}.md`（slug 为走查对象短名，如 `order-list`）
- 项目已有需求目录规范（`req` CLI / `requirement-doc-store` 约定）时从其规范

### 5.2 完整模板

```markdown
# 前端走查报告：{对象}

- **取证档位**：A / B / C
- **能力说明**：{浏览器工具 / 服务地址 / 测试账号 / 限制}
- **证据声明**：本次最高证据等级 {🟢/🟡/🔴}
  - 取证方式：实操实测 / 用户提供画面 / 代码直读 / 静态推演
  - 降级说明：{如"项目未起服务，体验类结论均为静态推断"}

## 1. 执行摘要
- {结论 1}（🟢）
- {结论 2}（🟡）
- {结论 3}（🟢）
- 未实操时首句声明："本次未实操，体验类结论待验证。"

## 2. 范围与覆盖
- 走查对象：{页面 / 入口清单}
- 状态覆盖矩阵：

| 页面 | 默认 | 加载 | 空 | 错误 | 无权限 | 长文本 | 大数据量 | 窄屏 |
|---|---|---|---|---|---|---|---|---|
| 订单列表 | ✅ | ✅ | ✅ | ❌ | - | ✅ | ⚠️ | ✅ |

（✅ 已走查且有证据 / ❌ 缺失 / ⚠️ 未充分或未验证 / - 不适用）

**覆盖率门禁**：每个 ✅ 必须可追溯（截图编号 / 发现编号 / `file:line`），追溯不到一律改标 ⚠️；禁止裸 ✅（"没查"不得写成"无问题"）；证据须**真实且可复核**，编造证据按报告作废处理。
```

## 六、降级细则（B / C 档）

### 6.1 B 档：肉眼检查清单模板（给用户）

```
请按以下清单提供截图或录屏（能多给就多给，缺项我会按可得材料降级）：
1. 首页 / 主界面（默认数据）
2. 核心操作流程的中间态（提交后的等待画面）
3. 空状态（无数据时的界面）
4. 错误 / 失败态（随便造一个错误，如断网后重试）
5. 长文本 / 大数据量（列表满屏时的样子）
6. 窄屏或移动端视图
分辨率：桌面 ≥1440 宽；移动 375 宽。
无法提供第 N 项请说明，我会按可得画面降级。
```

**用户提供画面后**：AI 读图走查 → 该部分证据可升 `🟢`；未覆盖部分保持降级。

### 6.2 C 档：怎么把静态审查做得有价值

**能出结论（`🟢`）**：

- 状态实现缺失（错误态 / 空态 / 无权限分支不存在）
- 交互实现缺陷（无防重复、无 loading、危险操作无确认）
- 无障碍属性缺失（无 label、无 alt、`div` 当按钮）
- 性能反模式（同步阻塞、未懒加载、无防抖、超大依赖）
- 文案问题（代码里的硬编码文案：错误提示是否给原因、术语是否自造）

**不能出结论（→ 待确认，`🔴`）**：

- 反馈是否"可见 / 及时"（有分支 ≠ 渲染出来）
- 布局是否错乱、窄屏是否折行
- 视觉层级、对比度观感
- 真实加载耗时

**报告头写法示例**：

```
取证档位：C（服务未能启动，仅前端代码直读，无任何画面）
证据声明：最高 🟢（实现类判定为代码实证）；体验类结论均为 🔴 推断，仅列于第 6 节待确认清单。
```

### 6.3 档位声明话术（三例）

| 档 | 报告头示例 |
|---|---|
| A | `取证档位：A（agent-browser 实操；服务 http://localhost:3000；含截图 23 张与 2 条性能实测）` |
| B | `取证档位：B（无法截图；静态推演 🟡 + 用户提供 6 张截图，用户画面部分为 🟢）` |
| C | `取证档位：C（无运行环境；仅代码直读，体验类结论待验证）` |

## 七、常见坑

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 只查首页 | 走查结论只覆盖登录后的第一个页面 | 先穷举路由清单再逐页登记 |
| 拿代码当体验判据 | "有 loading 分支 → 反馈没问题" | 分支存在只能 `🟡`；`🟢` 需实操或用户画面 |
| 只点主流程 | 全是 happy path，负面路径没走 | 三类路径（正面/边界/负面）必须都走 |
| 空态没造 | 用有数据的账号走查，看不到空态问题 | 专门用新账号 / 清空数据造空态 |
| 错误态没造 | 一切正常，交报告时"无问题" | 断网 / 非法输入 / mock 500 主动造错 |
| 忽略中断恢复 | 没试过刷新 / 返回 | 每个表单类页面都试一次刷新 |
| 越界进产品规划 | 报告里开始规划"下一版该做什么功能" | 产品级缺失交接 `product-manager` M3 |
| 越界点评代码 | 报告里点评组件命名 / 架构选型 | 交 `code-review`；本清单只收体验相关 |
| 假精确 | "预计提升转化 15%" | 只给价值 / 成本的高中低 |
| 排除项不写 | 用户重复问"XX 查了没" | 第 5 节如实写"经走查排除" |
| 一次性铺开 | 60 个页面一次全报，报告失控 | 分批（每批 ≤8 页/功能域），批间小结 |
| 测试环境用生产数据 | 走查中误删 / 误下单真实数据 | 阶段 0 确认环境与副作用边界 |
