## 一、六件套模板

### 1.1 `ownership.md`（防冲突第一道闸）

```markdown
# 文件所有权 · {SR-XX} {砖头名}

> 代码基线 code_base：{hash}　｜　契约基线 contract_base：{hash}　｜　批次：第 {N} 批

## 机器可读块（下游 integration-merge 预检脚本的**唯一输入来源**，勿改格式）

```yaml
slice: SR-01
branch: feat/sr-01
# ★ 两个基线不可合并（分批场景下不是同一个 commit，合并会让门⑤ 误报）
code_base: a1b2c3d       # 代码基线：拉工作副本、算改动 diff 的起点
                         #   单批 = 骨架冻结点；分批时第 N 批 = 上一批合入（含装配）后的 commit
contract_base: a1b2c3d   # 契约基线：包内 contract/ 快照对应的冻结点
                         #   未发生契约修订时 = 原冻结点（不随批次变）
exclusive:
  - src/order/export/
  - src/order/service.py
interface:            # ★ 门② 的检查目标，语义 = 【零 diff】：它的任何改动都视为契约漂移
                      #   只填【形状 SSOT】（类型 / 常量 / 事件协议的定义文件）
                      #   ❌ 不要填桩文件（路由 / client / store 等）—— 实现体必然要改，
                      #      填进去会让门② 对每一片都【必然误报】（实测：一片被报 5 个文件）
  - src/order/exporter.py
readonly:
  - src/order/models.py
  - contract/
forbidden:
  - src/payment/
  - migrations/
```

> **为什么要有这一块**：预检脚本若手抄一遍独占写路径，就产生了第三份真相（`ownership.md` / 脚本配置 / 实际代码）。此块让脚本**直接读取**，消除不同步风险。

> **为什么代码基线与契约基线必须分开**（分批场景必踩）：
> ```text
> 第 1 批合入后主干变成 h2。第 2 批：
>   代码基线 = h2          （含第 1 批成果，否则编译都过不去）
>   契约基线 = a1b2c3d     （契约没改过，快照仍对应原冻结点）
>
> 若只留一个 base_commit：
>   填 h2 → 门⑤ 拿 h2 比对 contract/BASE（= a1b2c3d）→ 【误报】"基线不一致"
>   填 a1b2c3d → 门① 从冻结点算 diff → 【误报】"第 1 批的改动全是我的越界"
> ```
> 两个基线各管一门：**门① 越界用 `code_base`，门⑤ 契约基线用 `contract_base`**。

## 独占写（仅本窗口可改）

| # | 路径 / 范围 | 类型 | 说明 |
|---|------------|------|------|
| 1 | `src/order/export/**` | 新增 | 整目录新增，本窗口完全拥有 |
| 2 | `src/order/service.py :: exportOrders()` | 修改 | 骨架已预留挂载位，本窗口只填该函数体 |

## 只读（可读，禁止写入）

| # | 路径 | 为什么只读 |
|---|------|-----------|
| 1 | `src/order/models.py` | 数据模型已定稿，变更须回 design-craft |
| 2 | `contract/**` | 契约快照，改 = 漂移，拼接必拒收 |
| 3 | `src/common/**` | 公共代码已冻结 |

## 禁碰（无关区域，防顺手重构）

| # | 路径 | 说明 |
|---|------|------|
| 1 | `src/payment/**` | 与本砖头无关 |
| 2 | `migrations/**` | 归属集成阶段 |

## 越界即停

发现自己需要写以上任何只读 / 禁碰路径 → **停下来**：

1. 不要改
2. 在 `slice.md` 的状态区写阻塞：`阻塞 · 需要 {路径} · 原因：{为什么}`
3. 继续做本窗口其他不受影响的部分
4. 等用户 / 架构师裁决，**不自行扩大范围**

## 共享资源归属

| 资源 | 归属 | 本窗口权限 |
|------|------|-----------|
| `migrations/` | 集成阶段 | 只读，schema 需求走上报 |
| 依赖清单 | 集成阶段 | 只读，需要新包走上报 |
| 路由 / 注册表 | 骨架已预留 | 只填自己那行 |
```

**写法规则**：

| 规则 | 说明 |
|------|------|
| 独占写必须细到**函数 / 行区间**（修改现有文件时） | 只写文件名 = 其余片全部无法并行 |
| 独占写集合**两两不许有交集** | 有交集 = 禁止同批 |
| **同文件不同函数默认也不并行** | 例外须注明理由（文件足够大、区域足够远） |
| 优先"新增"而非"修改" | 新增文件互相零干扰；修改现有文件是风险源 |
| 只读区必须写**为什么只读** | 否则实现者会以为"读一下改一点没关系" |

### 1.2 语义契约 10 项（签名之外，必须填）

契约分两半：**签名**（在桩代码里，被类型系统锁定）+ **语义**（在契约快照里，被测试锁定）。签名之外这 10 项是**集成事故的全部来源**，逐项填，不许写"待定"。

```markdown
# 语义契约 · {接口名}

> 冻结 commit：{hash}　｜　签名见 `contract/{接口文件}`

| # | 项 | 约定 | 对应的事故（如果不填会怎样） |
|---|----|------|---------------------------|
| 1 | 前置条件 | {参数合法性 / 允许的调用时机} | 调用方在未初始化时调用 → 静默错误数据 |
| 2 | 后置条件 | {排序 / 分页 / 去重 / 含头不含尾} | 一方按时间序、一方按 ID 序 → 分页错乱 |
| 3 | 空值策略 | {null vs 空数组；"无数据" vs "未计算"} | 一方判 `null`、一方判 `[]` → 空数据被当异常 |
| 4 | 错误语义 | {什么条件抛什么错误码；不抛 vs 返回错误} | 一方抛、一方返回 → 上层捕获不到 |
| 5 | 单位与精度 | {分 / 元；小数位数} | 一方传分、一方按元 → 金额差 100 倍 |
| 6 | 时间语义 | {UTC / 本地；秒 / 毫秒} | 时区差 8 小时 / 时间戳差 1000 倍 |
| 7 | 幂等性 | {重复调用是否产生副作用} | 重试导致重复扣款 / 重复建单 |
| 8 | 并发安全 | {是否需要调用方加锁；能否并发调用} | 双方都以为独占 → 竞态、双写 |
| 9 | 事务边界 | {是否在事务内；副作用何时对其他方可见} | 事务内发消息 → 消息先于数据落库 |
| 10 | 副作用 | {是否发消息 / 写日志 / 调外部系统} | 双方各发一次消息 → 下游重复处理 |

## 失败语义（配合 mock 的异常路径）

| 场景 | 期望行为 |
|------|---------|
| 依赖方失败 | {抛什么 / 返回什么 / 是否重试} |
| 超时 | {超时时长；超时后的行为} |
| 部分成功 | {如何处理；是否幂等补偿} |
| 返回脏数据 / 极值 | {校验 / 拒绝 / 兜底} |
```

> **这 10 项不是形式主义**——表右列每一行都对应一类真实集成事故，且**没有任何静态手段能防**（编译过、类型对、签名一致）。唯一防线是"写进契约 + 写成契约测试"。

### 1.4 `out-of-scope.md`

```markdown
# 反向边界 · {SR-XX}

## 本砖头不做什么

| # | 不做的事 | 归属 |
|---|---------|------|
| 1 | 不改数据模型 | 骨架已定稿，变更回 design-craft |
| 2 | 不做 PDF 导出 | 属 SR-03 |
| 3 | 不做性能优化 | 拼接后统一评估 |

## 遇到边界问题怎么办（强制流程）

```text
发现自己需要做"本砖头不做什么"里的事
  │
  ├─ 1. 停下手，不要做
  ├─ 2. 判断是否需要阻塞：
  │      ├─ 不影响本砖头继续 → 记一行"待办外溢"，继续
  │      └─ 影响本砖头完成   → 写阻塞
  ├─ 3. 在 slice.md 状态区写：阻塞 · 需要 {什么} · 原因 {为什么}
  └─ 4. 继续做不受影响的部分；等裁决，不自行扩大范围
```

## 为什么禁止自行扩大范围

- 越界写入 = 侵占他人独占区 → 拼接期必然冲突
- 改契约 = 正在跑的其他砖头全部白做（契约只能在批次边界改）
- "顺手指带一个重构" = 本砖头验收范围失控，无法判定完成
```

### 1.5 `verify/`（自证工具）

```text
verify/
├── run.sh              # 一键跑全部验收（含契约测试与越界检查）
├── expected.md         # 期望输出清单（能力不足时人工核对的降级路径）
└── fixtures/           # 桩数据（构造异常路径用：失败 / 超时 / 空 / 脏数据）
```

`run.sh` 骨架（**必备四项：契约测试 + 本砖头测试 + 越界检查 + 桩残留自检**；缺项则该片的"绿"不可信）：

```bash
#!/usr/bin/env bash
set -euo pipefail
SLICE="{SR-XX}"
# ★ 两个基线不可混用（分批时不是同一个 commit）：
#   CODE_BASE    = 从哪算改动 → 骨架冻结点（分批 = 上一批合入后）。越界检查用它
#   CONTRACT_BASE = 本包实现的是哪版契约 → 未修订时 = 冻结点。仅记录，供拼接期门⑤ 比对
CODE_BASE="{hash}"
CONTRACT_BASE="{hash}"
OWNED_PATTERNS=("src/order/export/" "src/order/service.py")
# 桩标记来源：★ 与 premerge-check.sh 同源（.delivery/stub-pattern，由 design-to-code 生成）
# 切勿默认扫 NotImplemented（抽象方法会误报）；也不要用 ':!*test*' 排除（会漏掉 src/latest/ 这类路径）
STUB_PATTERN="${STUB_PATTERN:-$(cat .delivery/stub-pattern 2>/dev/null || echo 'STUB:')}"
SRC_GLOBS=('*.py' '*.ts' '*.go' '*.js'
           ':!tests/*' ':!test/*' ':!*_test.*' ':!*_spec.*' ':!*.test.*' ':!.delivery/*')

echo "① 本砖头组契约测试（★ 只跑本组，不跑他组）"
pytest "tests/contract/${SLICE}/" -q

echo "② 片级验收测试（断言由上游给定，不可改）+ 异常路径"
pytest tests/"${SLICE}"/ -q          # ★ 大写：目录约定是 tests/{SR-XX}/（勿写 ${SLICE,,}，Linux 下找不到目录）

echo "③ 数据走向预演（全 mock，本窗口期应【绿】）"
pytest tests/data-flow/ -q

echo "④ 越界检查（从 CODE_BASE 算起，不是冻结点）"
git rev-parse --verify "${CODE_BASE}" >/dev/null 2>&1 || {
  echo "❌ 代码基线 ${CODE_BASE} 不存在——检查 ownership.md 的 code_base（分批时第 N 批 = 上一批合入后）"; exit 1; }
# ★ 排除 sub-requirements/ 与 .delivery/：窗口本就要更新【自己包的 slice.md】状态标记，
#   不排除则每次误报越界（理由见 SKILL.md 阶段 3.2c）。改包内 contract/ 仍由门② 负责
git diff --name-only "${CODE_BASE}..HEAD" \
  | grep -vE '^(sub-requirements/|\.delivery/)' | while read -r f; do
  ok=0
  for p in "${OWNED_PATTERNS[@]}"; do [[ "$f" == "$p"* ]] && ok=1; done
  [[ $ok -eq 1 ]] || { echo "❌ 越界：$f"; exit 1; }
done

echo "⑤ 桩残留自检（★ 必备：不依赖测试是否覆盖到）"
# ★ 区分退出码：0=有匹配 / 1=无匹配 / >1=出错。
#   `2>/dev/null || true` 会把"出错"变成"无匹配" → 假绿（实测：git 返回 128 被吞）
if hits=$(git grep -n -E "$STUB_PATTERN" -- "${SRC_GLOBS[@]}" 2>&1); then
  echo "❌ 桩残留（接口未实现）："; echo "$hits"; exit 1
else
  rc=$?
  [[ $rc -eq 1 ]] || { echo "❌ 扫描失败（git 退出码 ${rc}）——不得当作「无残留」："; echo "$hits"; exit 1; }
fi

echo "⑥ 预检自跑（若已生成预检脚本）"
# ★ 用 if/else，不用 `cmd && ... || echo "跳过"`——后者会把【脚本执行失败】也渲染成"跳过"，掩盖真问题
if [[ -x .delivery/premerge-check.sh ]]; then
  .delivery/premerge-check.sh --slice "${SLICE}"
else
  echo "（无预检脚本：本步跳过；①–⑤ 已独立跑过，不依赖它）"
fi

echo "✅ 全部通过"
echo "ℹ️ 未跑：他组契约测试 / 挂载点测试——它们在本窗口期本就该红，不是你的职责"
```

> **④ 为何不能用「冻结 commit」当起点**：分批时 `CODE_BASE` = 上一批合入后的 commit，与冻结点**不是同一个**。填冻结点 → 上一批的改动全部被算成本窗口越界（误报）；填新 commit 而契约没改 → 门⑤ 又会说契约基线不一致。**两个基线各管一门，都要写对。**
> **⑤ 为何是必备而非"顺手跑预检脚本"**：桩残留必须**独立于测试覆盖**——契约测试只跑有测例的接口，漏实现的恰是没被覆盖的那些。若依赖 `⑥ 预检自跑`（可能无脚本而跳过），漏网接口就无人发现。

> **① 只跑本组**：`tests/contract/` 下按砖头分目录，本窗口只对自己那组负责。跑全局会把"他组的红"混进结果，让完成定义不可达。
> **③ 数据走向预演在当前为 mock 版本，期望绿**；拼接期由 `integration-merge` 换真实实现重跑。

> **④ 预检自跑是"拒收门前置"的落地**：各窗口完工前先跑一遍 6 项拒收门，把越界 / 契约改动 / mock 残留 / **桩残留**在自己手里解决掉——**拼接期才首次发现这些，是切片流程的失败**。未安装 `integration-merge` 时跳过即可，不阻塞。

> **`expected.md` 是能力降级路径**：窗口所在 IDE 无法执行命令时，人工按它逐条核对。

## 二、依赖分级与 mock 细则

### 2.1 判定流程

```text
两个砖头之间有依赖
  │
  ├─ ① 能对着对方的接口桩写完自己的代码吗？
  │      能 → 【接口级】不该分批（骨架的桩已解决）
  │
  ├─ ② 需要的只是表结构 / 枚举 / 状态定义吗？
  │      是 → 【数据级】不该分批（冻结点已定稿）
  │
  └─ ③ 需要对方产生的真实数据 / 运行结果吗？
         是 → 【实现级】→ 走 mock 可行性判定
                ├─ 5 条全过 → mock 降级为接口级 → 同批并行
                └─ 任一条不过 → 必须分批
```

### 2.2 mock 可行性 5 条判据（细化）

| # | 判据 | 怎么判 | 不合格时 |
|---|------|--------|---------|
| 1 | 对方接口**现在能确定** | 桩代码已合入且语义契约 10 项已填 → 能确定 | 契约不稳 → mock 无意义 → 分批 |
| 2 | 对方有**技术未知点**吗 | 有未验证的技术方案 / 不确定能否实现 | 先 `demo-verify` 验掉，再回来判 |
| 3 | 对方是**新增代码**还是**改造现有逻辑** | 看 ownership：新增型 / 挂载型 / 修改型 | 修改型 → 风险高一档，**倾向分批** |
| 4 | 对方依赖的**第三方 / 环境 / 数据可用**吗 | 依赖的服务能连、数据能拿到 | 不可用 → 对方本身有阻塞，mock 在掩盖它 |
| 5 | 对方的**契约会变**吗 | 业务是否仍在探索、需求是否可能调整 | 会变 → mock 作废风险高 → 分批 |

### 2.3 mock 保真边界（必须写进砖头包）

| 维度 | mock 能兑现 | mock 不能兑现 |
|------|------------|--------------|
| 签名 / 类型 / DTO / 错误码 | ✅ | |
| 空值策略 / 边界约定 | ✅（需显式配置） | |
| 排序 / 分页 / 去重语义 | ⚠️ 手工构造，容易失真 | |
| **失败模式**（部分失败 / 超时 / 重试） | ⚠️ 不显式构造就测不到 | |
| **性能 / 延迟** | | ❌ |
| **并发行为 / 锁** | | ❌ |
| **事务边界 / 副作用时机** | | ❌ |
| **真实数据分布**（脏数据 / 极值） | | ❌ |

**两条铁律**：
1. mock 必须**支持异常路径**（失败 / 超时 / 空 / 脏数据），否则只测了顺风路径
2. mock 通过 = **只证"形状"**，效果验收留到拼接阶段，不得省略

### 2.4 mock 红线

| 红线 | 后果 |
|------|------|
| 各片**自造** mock | 验证的是自己想象中的对方，拼接期必然翻车 |
| **互 mock**（双方都未实现且互相 mock） | 双重赌博，风险平方 → 必须合并或先定死一方 |
| mock 被带上生产路径 | 典型事故 → 拼接前必须残留扫描 |

## 三、批次与检查点

### 3.1 批次划分

```text
输入：砖头列表 + 依赖图（分级后）+ 互斥校验结果

1. 计算每个砖头的入度（依赖方中未排入批次的）
2. 入度为 0 且互斥校验与同批成员全过的 → 第 1 批
3. 移除第 1 批，重算入度 → 第 2 批
4. 循环至全部排完
5. 检查：批次数 ≥ 3 → 回头查骨架（骨架缺口？真实现级依赖？）
6. 检查：同批 > 5 片 → 边界数爆炸，考虑合并
```

### 3.2 检查点（每批结束时必查）

| # | 检查项 | 为什么 |
|---|--------|--------|
| 1 | 上批**契约测试全绿** | 不是"完成了"，是"测试绿"——完成为自我感觉，绿是证据 |
| 2 | 骨架是否需修订 | **契约只能在批次边界改**；批中途改 = 正在跑的其他砖头全部白做 |
| 3 | 主干可编译可运行 | 常绿被破坏则后续所有批次都无法验证 |

### 3.3 契约修订流程（唯一合法路径）

```text
实现中发现契约不够用
  │
  ├─ ① 不要就地改
  ├─ ② 写阻塞上报
  └─ ③ 等当前批次结束 → 在批次边界：
       ├─ 回 design-craft 改骨架（桩 + 语义契约 + 契约测试）
       ├─ 主干编译通过
       ├─ ★ 评估返工面：哪些砖头受影响？已完成的需要重做吗？报用户决定
       ├─ ★ 已完成批次重新对齐：更新冻结 commit → 对**最新契约**重跑契约测试
       │     （不重跑 = 新旧契约混用，拼接时必然对不上）
       ├─ 更新所有受影响砖头包的 contract/ 快照与冻结 commit
       └─ 下一批开工
```

**修订的代价必须说清**：受影响砖头的**已完成实现作废需重做**（不是"改个签名"）。契约越早冻、越晚改，代价越大——这正是"冻结点要等风险验证之后"的原因。

**单批次时的例外路径**：只有 1 批时"批次边界"= 全部完成后，窗口会干等。此时按 SKILL.md 阶段 0 的「单批次场景」三条路走（等 / 改 / 降级），**默认选"等"**（返工面最小），仅在缺口卡住多个片时才选"改"。

**禁止**：把修订分散到各窗口自行处理（各改各的 = 契约碎片化，比不改更糟）。

## 五、常见冲突场景与处置

| 场景 | 根因 | 处置 |
|------|------|------|
| 两片改同一文件 | 独占写粒度过粗 | 合并，或细到函数级重切 |
| 同文件不同函数仍互相绊 | 心智模型分叉 | 默认不同批（例外须注明理由） |
| 两片都加了 migration | 共享资源未归属 | 收归集成阶段；片内只提需求 |
| 两片都改了依赖清单 | 同上 | 收归集成阶段 |
| 两片都改了同一枚举 | 数据模型未定稿 | 退回阶段 0 补骨架 |
| 两片都改了 `utils/` | 公共代码未冻结 | 退回阶段 0 补骨架 |
| 两片各加了一行路由注册 | 接入点未预留 | 退回阶段 0，骨架预留挂载位 |
| 一片 import 了另一片 | 未做依赖分级 | 用允许矩阵扫描抓出，改为通过契约桩 / mock |
| 拼接时发现签名对不上 | 契约未冻结 | 说明骨架缺失，不可在拼接期就地改 |
| 拼接时行为不一致（编译过） | 语义契约未填 / mock 只测了形状 | 补契约测试 + 拼接级语义审查 |

## 七、骨架预演模板（阶段 0.5）

### 7.1 零上下文预演 · 派给独立核验方的提示词

```text
你是一个【独立核验方】，不参与任何设计。下面是砖头 {SR-XX} 包的全部内容。

请只回答五个问题（**不要写任何实现代码**）：
1. 我要做什么？（复述目标与验收标准）
2. 我能改哪些文件？（复述独占写 / 只读 / 禁碰）
3. 我怎么验证我做完了？（复述 verify 路径与期望输出）
4. 哪里我不确定 / 缺什么信息？
5. ★ 你回答 1–3 时用到了哪些"包外常识"？（逐条列出）

规则：
- 只读这个包，不要读包外的任何文档
- **不要用你的先验知识补全包外信息**；凡需要包外信息才能回答的，一律报告
- 问题 4 要具体（如"我不确定 X 指 A 还是 B"），不要写"整体感觉清晰"这类空话
- 问题 5 是重点：你用的每一条包外常识，都可能是一个包缺陷——请如实列出，
  不要因为"这是常识所以不用写"而省略
```

> **为什么要有第 5 问**：核验方也是 LLM，会用常识**脑补**包外信息——于是"它没提问"并不等于"包自包含"。第 5 问逼它自曝用到的常识，每条都是一个潜在缺陷（可能是"包该写清却没写"= 需修，也可能是"这条常识足够通用"= 可接受但需记录）。**在冷启动核验方（不带任何项目上下文）上效果最好。**

**结果归类**：

| 疑问类型 | 判据 | 处理 |
|---------|------|------|
| **包内缺失** | 骨架里有，但没写进包 | 补进包（不阻断） |
| **骨架缺失** | 骨架里就没有 | **退回 `design-craft` 补骨架（阻断）** |
| **表述歧义** | 能推断但易错 | 改进包表述 + 标为已知风险 |

**批量执行**：N 个砖头包 = **N 次独立预演**。

- **推荐**：用子 agent **并行批量**（一次派 N 个，每个只持一个包、互不通信）
- 不可并行时逐包串行，代价是 N 倍等待
- **不要合并成一次预演**（一次给多个包 → 核验方会跨包脑补，失去"自包含性"检验的意义）

### 7.2 分层测试的落盘位置与判定命令

**分层测试期望值**（全流程判别标准，各相关文档必须一致）：

| 测试组 | 落盘位置 | 骨架期 | 窗口期（本砖头） | 拼接期 |
|--------|---------|-------|----------------|--------|
| 契约测试 · **本砖头组** | `tests/contract/{SR-XX}/` | 红 | **绿** | 绿 |
| 契约测试 · 其他组 | `tests/contract/{其他}/` | 红 | **不跑** | 绿 |
| **片级验收测试** | `tests/{SR-XX}/` | **红** | **绿** | 绿 |
| 数据走向预演（全 mock → 真实实现） | `tests/data-flow/` | **绿** | 绿 | 绿 |
| 挂载点测试 | `tests/mount/` | 红 | 红（预期） | 绿 |

> **片级验收测试的断言由上游派生**（5.5.1 承接的验收项），**不是窗口照着自己实现写的**——这是"验收"与"自测"的分界线。

**契约测试分组口径**：按**被测接口的实现方**归属（`tests/contract/SR-01/` = SR-01 所提供接口的契约测试）。未分组 → 窗口完成定义不可达 → 窗口被迫改测试凑绿。

**骨架期判定命令**：

```bash
# 红因核对：抽 5 条失败，逐条确认原因是 NotImplementedError（不要只看计数）
pytest tests/contract/ -q --tb=line 2>&1 | grep -E "NotImplementedError" | head -5
# 期望：抽出的每条都是 NotImplementedError
# 若出现断言失败（assert 而非 NotImplementedError）→ 契约测试本身写错了，退回 design-to-code

# 意外绿检测（绿 = 假绿警报，必须归零才放行）
pytest tests/contract/ tests/mount/ -q --tb=no 2>&1 | grep -E "[0-9]+ passed" \
  && echo "⚠️ 出现意外绿：桩返回了看似合法的默认值，须改为 raise NotImplementedError"
```

> **为什么不用"失败数 == NotImplementedError 行数"这种计数比对**：一条调用链可能触发多个桩，`--tb=line` 只显示一个；fixture 阶段的异常也不计入该统计 → **多桩链下必然误报**。**抽样核对红因**比计数更可靠。

### 7.3 数据走向预演 · 链路说明文件

`tests/data-flow/flow-{场景}.md`：

```markdown
# 数据走向：{场景名}

| 跳 | 位置 | 输入 | 输出 | 单位 / 时区 / 空值约定 |
|----|------|------|------|---------------------|
| 1 | 入口 ExportRequest | 用户参数 | req | — |
| 2 | order.query（SR-01 桩） | order_ids | OrderDTO[] | amount=分（UTC） |
| 3 | exporter.build_rows（SR-02 桩） | OrderDTO[] | RowDTO[] | amount=分 |
| 4 | exporter.write（SR-02 桩） | RowDTO[] | file path | — |

【贯通断言】
- OrderDTO.amount → RowDTO.amount（单位一致）
- OrderDTO.created_at → RowDTO.created_at（时区与时间戳单位一致）

【预期缺口】（骨架期发现后回填）
```

**断言库**（建议随骨架提供，各链路测试共用）：

```python
def assert_shape(obj, dto): ...                    # 字段齐全 + 类型匹配（反射 DTO 声明）
def assert_fields_covered(src, dst, mapping): ...  # 源字段在目标有对应（抓断链）
def assert_units_aligned(a_field, b_field): ...    # 单位 / 精度一致
def assert_time_semantics(a_field, b_field): ...   # 时区 / 时间戳单位一致
def assert_null_policy(value, policy): ...         # 空值策略一致
```

> ⚠️ 这组测试**必须用 mock 填满全链路**。用 `NotImplemented` 桩会跑到第二跳就抛异常，后面的贯通断言根本执行不到。
> **因此 mock 套件必须包含两类**：① **跨砖头依赖 mock**（给调用方在实现期使用）② **桩的 mock 版**（给本组预演测试填满全链路）。只有第①类时，链路跑到本砖头自己的桩就会断。桩的 mock 版可由 design-to-code 随桩一并生成（同一签名、返回契约声明的形状数据）。

### 7.4 契约缺口清单（数据走向预演的产出）

| # | 场景 | 跳 | 缺口类型 | 具体 | 处理 |
|---|------|----|---------|------|------|
| 1 | 导出 CSV | 3 | 字段断链 | `OrderDTO.remark` 无对应字段 | 补 RowDTO 或确认丢弃 |
| 2 | 导出 CSV | 3 | 单位不一致 | `amount` 分 vs 元 | 契约 10 项第 5 项补明确 |

**缺口类型枚举**：字段断链 / 单位不一致 / 时区不一致 / 空值策略缺失 / 断言写不出 / 链路不通。

从需求侧验收标准反向走：

| # | 验收标准 | 归属砖头 | 归属契约 | 结论 |

## 八、产物归属（.gitignore 与禁止忽略清单）

### 8.1 追加片段（**追加式**，不改用户已有规则）

```gitignore
# ---- 并行交付脚手架（统一目录，一行覆盖）----
.delivery/
```

**追加规则**：

| 规则 | 说明 |
|------|------|
| **只追加不删** | 用户已有的忽略规则一律不动，即使看起来冗余 |
| **锚定路径** | 用 `.delivery/` 这类锚定写法，不用宽泛的 `mocks/`（可能误伤项目自己的目录） |
| **统一落点才好忽略** | 脚手架统一收 `.delivery/`，`.gitignore` 只需一行；分散落点会迫使规则零散、易漏 |
| **已跟踪项加规则无效** | 若脚手架**已被 `git add` 过**，`.gitignore` 对它不起作用 → 需先补规则，再 `git rm --cached -r {路径}`（**须先征询用户**，不擅自执行） |
| **非 git 环境跳过** | 落盘目录不是 git 仓库时，跳过本节检查，不提示、不阻塞 |

### 8.2 禁止忽略清单（这些**绝不能**进 `.gitignore`）

| 路径 | 为什么不能忽略 |
|------|--------------|
| `tests/{SR-XX}/` | 片级验收测试——断言由**需求验收项**派生的回归资产 |
| `tests/mount/` | 挂载点测试——装配回归 |
| `tests/contract/{SR-XX}/` | 契约测试——接口回归 |
| `tests/data-flow/` | 数据走向测试——**拼接期替换后即为 e2e 基线** |
| `sub-requirements/` | 砖头包等过程文档（与 `.requirements/` 同源，供复盘与跨轮续做） |

> **⚠️ 防误杀优先**：忽略规则写错顶多是"该忽略的没忽略"（可补救）；**把上面这些误杀，交付后就永久失去回归保护**——不可逆。
> 因此**不要整目录忽略 `tests/`**，也不要用宽泛模式（如 `*mock*`、`data-flow`）。

### 8.3 检查方法（五步，借 `topic-teach`「产物仓库卫生」模式）

```text
1. 列未提交项     git status --porcelain
2. 按 git 状态分流  ?? 未跟踪（.gitignore 有效）/ 第二位为 M（已跟踪，规则无效）
3. 三分类判定      ✅ 要提交（产品资产）/ 🚫 要忽略（脚手架）/ ⚠️ 存疑（问用户）
4. 追加规则        把 🚫 项追加进 .gitignore（对应分组）；已跟踪项另需 git rm --cached（先征询）
5. 校验            防误忽略：四类产品测试逐个 git check-ignore 应【无命中】
                  防漏忽略：.delivery/ 应【有命中】
```

> **只借模式，不复制内容**——`topic-teach/ops.md` 面向教学产物仓库，规则与本节不同；两处若冲突，**代码项目的场景以本节为准**。

## 九、反模式速查

| 反模式 | 为什么错 |
|--------|---------|
| **把阶段 0 打勾当骨架验证** | 只验"有没有"；漏/缺/不可实现/假绿/契约链断裂全抓不到 |
| **骨架预演自证** | 自证时已知所有隐含前提，测不出包的自包含性 |
| **数据走向预演用 NotImplemented 桩** | 第二跳即抛异常，贯通断言执行不到——必须用 mock 填满全链路 |
| **骨架阶段契约测试出绿就放行** | 假绿警报：桩返回了看似合法的默认值，拼接期也不会暴露 |
| **发现划分有误就地改边界** | 骨架落点会与边界脱节（桩落到别人的独占区）——应退回重划 |
| **多窗口共享同一工作目录** | 文件互相覆盖，ownership 与越界检查全部归零——硬前提，不是建议 |
| **把函数级独占误读成"同文件可并行"** | 函数级只提升越界检测精度；同文件被两个砖头碰，一律不同批 |
| **只算业务前置、漏算骨架成本** | 骨架常占 30%–50% 工作量，漏算会让"值得并行"的判定整体失真 |
| **多窗口共用端口 / 测试库 / 缓存** | 各自"全绿"是假绿，拼接时才暴露 |
| **契约修订后不重新对齐已完成批次** | 新旧契约混用，拼接时对不上 |
| 骨架不全就切 | 把共享面留给并行期，冲突必然发生 |
| 按用户功能直接切 | 用户视角独立 ≠ 代码可并行 |
| 独占写只到文件级 | 越界检测无法定位，且把文件内无关函数一并锁死 |
| 上游无文件路径信息仍硬切 | ownership 猜错 = 切片结论全错，漏掉的文件拼接期才暴露 |
| 允许"小心一点"式并行 | 有交集必须合并或串行，不接受口头保证 |
| 各片自造 mock | 验证的是自己的想象 |
| 互 mock | 双重赌博，风险平方 |
| 验收标准写描述性文字 | 无法机械判定，"完成"变自我感觉 |
| 批次数 ≥3 不回头查骨架 | 把骨架缺口当合理依赖，白白串行 |
| 实现期改契约 | 正在跑的其他砖头全部白做 |
| 砖头数量贪多（>5） | 边界数爆炸，集成成本吃掉并行收益 |
| 越界自行扩大范围 | 侵占他人独占区，拼接必然冲突 |
| 只靠对话框掌握进度 | 多窗口切换时状态失控；须以各包 slice.md 为准 + 批次边界重扫 INDEX.md |
