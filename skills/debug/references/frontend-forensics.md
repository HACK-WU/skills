# 前端运行时取证（前端页面类 Bug）

> **何时读**：现象落在**前端页面**上——白屏、点了没反应、样式错位、数据显示不对、偶发乱序、发版后空白。后端链路类（接口慢、数据错、日志报错）走原 Step 0–2，不必读本文件。

## 一、先划清三方分工

| 能力 | 回答什么 | 本文件怎么用 |
|---|---|---|
| `browser-evidence` | **能不能拿到画面 / 操作页面**（后端选型 + 档位 + 产物契约） | 先调它拿到 A 档后端与命令，本文件不重复探测 |
| `frontend-walkthrough` | **哪里可能坏**（十族 + 时序矩阵，扫未知问题） | 本文件只处理"已知坏了、要定位为什么" |
| 本 skill（debug） | **为什么坏了、怎么修** | 取证服务于根因，不为"报告好看"堆证据 |

> 一句话：walkthrough 是体检，debug 是急诊。急诊不需要整套体检报告，只要**能指认病灶的那一张片子**。

## 二、取证前置（三步，缺一即降级）

1. **能力**：调 `use_skill("browser-evidence")` 判定档位；非 A 档 → 按 B / C 降级，**不得凭代码断言"界面上是 XX 问题"**
2. **页面可达**：本地 / 测试环境起服务；线上页面需确认只读（见第五节）
3. **复现路径**：用户给的操作序列 + 触发数据（账号、角色、订单 id、时间窗）。缺 → 先问，不要靠猜构造

## 三、现象 → 证据矩阵（按现象查表，别撒网）

| 前端现象 | 该抓什么（最小集） | 命令示例（agent-browser） | 定位指向 |
|---|---|---|---|
| **白屏 / 整页不渲染** | 首个 console 异常 + 首个失败请求 | `errors`、`console`、`network requests` | 族 10（无 ErrorBoundary）/ 族 8（旧 chunk） |
| **点击无反应** | 元素是否在快照里、是否被遮挡、点击有没有报错 | `snapshot -i`、`eval` 取 `getBoundingClientRect()`、`errors` | 族 3（监听未挂）/ 族 6（权限只隐藏不拦截） |
| **样式错位 / 折行** | 实际渲染截图 + 关键元素计算样式 | `set viewport 375 812` → `screenshot`；`eval` 取 `getComputedStyle(el)` | 族 9（断点）/ 族 5c（截断） |
| **数据显示不对** | 请求 URL / 状态码 / 响应体原文；DOM 里实际渲染值 | `network requests --filter <api>`、`eval` 取 `innerText` | 族 5（形态/格式化）/ 后端契约 |
| **偶发（乱序 / 串台）** | 限速下操作序列 + 请求先后；前后两次快照差异 | `set offline` / `route` 拦截延迟、`diff snapshot`、`trace start / stop` | 族 1（竞态）/ 族 2（残留） |
| **发版后空白 / 菜单点不开** | `ChunkLoadError` 一类 + 资源 404 | `errors`、`network requests --filter .js` | 族 8（旧 chunk） |
| **卡顿 / 首屏慢** | Performance 指标 + trace | `eval`(`performance.getEntriesByType('navigation')`)、`trace` | 移交 `performance-analysis` 前先拿数 |

> **只抓指向根因的那一条**。debug 不产出走查级证据包（不需要"视频 + 每步截图"），一条 `console` 原文 + 一条失败请求 + 一张截图通常足够。

## 四、证据落盘格式

落 `.debug/{case-slug}-{YYYYMMDD}/artifacts/`（该目录已有 `.debug/.gitignore` 内容 `*`，**天然不入库**，无需额外处理）：

```text
artifacts/
├── repro-frontend.md          # 复现路径 + 环境 + 账号角色
├── console-20261112-1649.txt  # console 原文（脱敏）
├── net-failed.txt             # 失败请求（URL / 状态码 / 响应体片段）
├── before.png / after.png     # 修复前后对比
└── query-r1.txt               # 若还需线上只读查询，沿用远程取证流程
```

`evidence.md` 每条至少含：时间 / 来源（`本地实测` / `线上只读观察` / `静态分析`）/ 命令原文 / 现象与预期差异 / 脱敏说明。

## 五、线上只读硬边界（浏览器取证最容易破的口子）

`debug` 的「线上只读」约束**同样管浏览器**，且比 DB 更难自律——因为浏览器里什么都能点：

| 允许 | 禁止 |
|---|---|
| 打开页面、滚动、`set viewport`、截图 | **点击任何可能写数据的控件**（下单 / 提交 / 删除 / 审核 / 发送） |
| 只读 `console` / `errors` / `network` 观察 | 在 `eval` 里调用接口发写请求（`fetch(..., {method:'POST'})`） |
| 查看已有数据的渲染结果 | 改本地存储 / cookie 后以"新身份"触发写操作 |
| 复现到"操作前"就停 | 为了看错误提示，真的提交一次 |

- **要交互复现 → 回本地 / 测试环境**。线上只回答"它是什么样"，不回答"点下去会怎样"
- 线上拿到的证据标 `线上只读观察`，**不得与本地实测混记**
- 用户在自己的已登录会话里代执行时，任务卡写法沿用 [remote-forensics.md](remote-forensics.md)，只是把 SQL 换成"打开哪个页面、点哪里到哪一步停"

## 六、常见坑

| 坑 | 现象 | 处理 |
|---|---|---|
| **缓存 / Service Worker** | 本地改了但页面还是旧的，误判"修复无效" | 硬刷新 / 无痕窗口 / 注销 SW 再验；对照 `network` 里资源版本 |
| **旧 chunk 残留** | 本地正常、线上白屏，`ChunkLoadError` | 确认是发版问题而非代码问题（族 8），不当作本次修复对象 |
| **iframe 内元素点不到** | `snapshot` 里看不到目标元素 | 先切上下文（或确认该 iframe 跨域不可达） |
| **跨域 / 预检失败** | 请求 `network` 里显示 failed 但后端日志无记录 | 属于浏览器侧拦截，先看 CORS 头与混合内容，别去查后端 |
| **时区 / 格式化** | 本地显示正常、线上差 8 小时 | 对比 `eval` 里的原始值与渲染值，区分是数据问题还是展示问题 |
| **多账号串台** | 用错角色复现，结论完全相反 | 每轮记录使用的账号与角色；必要时换干净会话 |
| **截图含真实用户数据** | 列表页出现他人手机号 / 地址 | 落盘前打码，`evidence.md` 只写脱敏结论 |

## 七、反模式

- ❌ **非 A 档却写"界面上显示为空"**：没画面就是静态推断，标 `🟡` 或进待确认
- ❌ **一条现象抓一堆证据**：debug 要的是指认病灶的最小集，堆截图只是把不确定性往后推
- ❌ **线上点了写操作"验证一下"**：已经造成数据副作用，不再是只读排查
- ❌ **把 `frontend-walkthrough` 的十族全过一遍**：那是体检；此处按现象查表
- ❌ **修复只跑测试不看界面**：样式/交互类必须留改前改后截图，否则无法证明修好
- ❌ **用浏览器取证替代根因分析**：截图证明"现象存在"，不证明"为什么"——根因仍要回代码与证据链
