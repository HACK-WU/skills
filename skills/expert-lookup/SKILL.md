# 业务专家查找

## 概述

**目的**：在 AI 或用户需要了解某个业务模块 / 领域时，快速查找是否已有沉淀的"业务专家"资产包，避免重复阅读代码，直接复用既有领域资产。

**功能**：读取项目级和用户级的 `.module-experts/INDEX.md` → 关键词匹配定位候选专家 → 读取 `agent.md` 确认职责与适用场景 → 命中后**自动变身为目标专家**直接着手求解；问题跨域时**通过 task-dispatch 派生子 agent 请教其他专家**，并行协作提升效率。

**使用场景**：
- AI 接手 / 排查某个业务模块，需要先判断是否有现成专家资产可复用
- 用户问"有没有这个模块的专家""这个模块有现成资料吗""找一下告警相关的专家"
- AI 开始重大项目前，先查是否有对应领域的深度认知包
- 用户说"查专家""找专家""expert lookup"时
- 找到专家后希望 AI 直接以专家身份接手解决当前问题（而非只给资料）
- 问题涉及多个业务域，需要跨专家并行请教 / 协作

## 核心原则

1. **查找优先**：接手业务模块 / 排查领域问题时，先查专家库，再从头读代码
2. **双库搜索**：同时查项目级和用户级，项目级优先
3. **两级过滤**：先用 `INDEX.md` 做专家级粗筛，再读 `agent.md` 做职责 / 场景精判
4. **必须实读**：不能仅凭 INDEX 标题就断言命中，必须读 `agent.md` 获取职责与适用场景
5. **结果非阻塞**：找不到专家不阻塞后续工作，可建议用 expert-team 创建
6. **变身求解**：找到目标专家后，主 agent 自动加载其全部资产并以专家视角直接着手解决问题，而非仅展示概要
7. **跨专家协作**：问题跨域时，用 task-dispatch 派生子 agent（每个基于一个其他专家资产），向其咨询或派活以提升效率

## 存储位置

| 层级 | 路径 | 说明 |
|------|------|------|
| 项目级 | `.module-experts/` | 由 `expert-team` 生成，随项目版本控制 |
| 用户级 | `~/.module-experts/` | 跨项目通用的业务专家（**可选扩展**：expert-team 当前仅生成项目级，用户级需手动迁移或将来支持） |

两个层级各自维护独立的 `INDEX.md` 与专家子目录。每个专家子目录含 `agent.md`（名片）+ 技术切面 Wiki 文档（`01-架构.md`~`07-运维.md`）+ `skills/`（专用技能）。

## 执行流程

### Step 1：提取当前需求的关键词

从当前需求 / 问题中提取搜索关键词：

- **业务域关键词**：业务领域、功能分类（如 `告警`、`日志`、`支付`、`权限`）
- **模块名关键词**：模块根路径、包名、目录名（如 `pkg/alert`、`alert-service`）
- **问题 / 操作关键词**：正在排查的现象或要做的操作（如 `不触发`、`新增规则`、`查询历史`）

提取 3-6 个关键词。

### Step 2：读取 INDEX.md

同时读取两个层级的 `INDEX.md`：

1. **项目级**：`.module-experts/INDEX.md`（不存在则 `list_dir .module-experts/` 枚举专家子目录，逐个读 `agent.md` 作为粗筛来源，不漏检已有专家）
2. **用户级**：`~/.module-experts/INDEX.md`（不存在则同样枚举降级；该层级通常为空）

`INDEX.md` 中每条记录形如（由 `expert-team` Step 7 维护）：

```
## {中文专家名}  （职责摘要见 agent.md）
- 模块根：{path}
- 生成日期：{date}  git commit：{hash}
- 切面文档：01-架构, 02-实现, 03-数据流转, ...
- 专用技能：skills/{skill1}, skills/{skill2}（或「暂无」）
```

### Step 3：关键词匹配（专家级粗筛）

将 Step 1 的关键词与 `INDEX.md` 中每条记录的**专家名 / 模块根 / 切面文档 / 专用技能**进行匹配：

**匹配规则**：
- 精确匹配优先：关键词与专家名 / 模块根完全一致
- 包含匹配：当前关键词包含某记录的专家名 / 模块根 / 技能名
- 多关键词命中：命中的关键词越多，匹配度越高

**匹配结果**：
- **高匹配**：命中 2 个以上关键词 → 强候选
- **中匹配**：命中 1 个关键词 → 弱候选
- **无匹配**：未命中任何关键词 → 无现成专家

### Step 4：读 agent.md 核对（必须实读，逐个核对）

对 Step 3 命中的候选专家，按匹配度从高到低**逐个核对**：

1. **必须实读**该候选的 `agent.md` 全文（路径：`.module-experts/{中文专家名}/agent.md` 或 `~/.module-experts/{中文专家名}/agent.md`）。`agent.md` 含：
   - **一句话职责**：该专家负责的**业务领域**
   - **负责的模块**：模块根路径与一句话职责
   - **何时找这个专家**：典型使用场景清单
   - **包含的资产**：切面 Wiki 文档清单 + 专用技能清单（或「暂无」）
2. **核对是否覆盖当前需求**：将当前问题与"一句话职责 / 负责的模块 / 何时找这个专家"比对。
   - **agent.md 不存在、为空或缺关键字段**（无"一句话职责"或"负责的模块"）→ **视为无法解析，跳过该专家并记录原因**（如"`{专家名}/agent.md` 内容异常，无法确认职责"），继续核对下一个候选
   - **符合** → 标记为采用候选
   - **不符合** → **跳过该专家，继续核对下一个候选**（不阻塞、不强行使用）
3. 核对完毕，按结果分流：
   - 仅 1 个符合 → 直接进入 Step 5 变身求解
   - 多个符合 → Step 5 先列出候选清单供用户选择
   - 0 个符合 → 进入 Step 5「未采用任何专家时」

### Step 5：复用专家资产

**找到匹配专家时**：

1. 多专家同为高/中匹配时，按以下规则确定主视角：
   - **优先以匹配度最高且问题主导域对应的专家为主视角**（如"告警不触发"以告警处理专家为主视角）
   - 若多个专家匹配度相近且难以判断主导域，先列出候选清单（专家名 + 一句话职责 + 建议主视角理由）供用户选择
   - 未选定前，不自动变身
2. **自动变身为目标专家**：用户确认（或默认）主视角后，加载该专家资产到主 agent 上下文——
   - 已读 `agent.md`（职责 / 模块 / 场景 / 资产）
   - 按当前问题涉及的切面，**选读**相关 Wiki（`./{NN-切面}.md`，如 `./01-架构.md`），不必全读
   - 加载 `skills/` 下与问题相关的专用技能（标准 create-skill 格式，可直接调用）
3. 向用户声明：「已切换为 {中文专家名} 视角」，然后**基于专家资产直接解决问题**（读代码 / 改代码 / 调用技能 / 回答用户等）
4. 求解过程中注意 `agent.md` / 切面文档中的"风险提示""常见坑"
5. 若问题涉及其他专家职能域，进入 Step 6 跨专家请教

**未采用任何专家时**（Step 3 无命中，或 Step 4 全部候选核对后仍不符合）：

1. 告知用户未找到真正匹配当前需求的专家资产（可简述核对过的候选及其不符合原因）
2. 不使用专家，正常排查 / 阅读代码
3. 排查解决后，可建议使用 `expert-team` 沉淀该模块专家资产包

### Step 6：跨专家请教（涉及其他专家领域时）

若当前问题涉及其他专家的职能域（目标专家资产未覆盖，或问题天然跨域），已变身的主 agent 启动跨专家协作：

1. 识别需请教的其他专家（Step 2/3 的候选中挑选，或再次运行本 skill 查找）
2. 调用 `task-dispatch` skill，为每个需请教的其他专家**创建一个子 agent**：
   - 子 agent 上下文 = 该其他专家的 `agent.md` + 与子任务相关的切面 Wiki 文档，注入其系统提示，使其"扮演该专家"
   - 仅加载该专家资产，不混入无关资产
3. 主 agent 对子 agent 执行以下之一：
   - **咨询（ask）**：提出想了解的问题（如"告警模块的限流逻辑是什么"），获取领域答案
   - **派活（task）**：下达明确子任务（如"列出日志模块所有对外接口"），由其独立完成
4. 多个不相关的请教可**并行**派发，提升效率
5. **子 agent 失败降级**：若 task-dispatch 调用失败、子 agent 无返回或返回无意义：
   - 主 agent **自行读取**该其他专家的 `agent.md` 和相关切面 Wiki 文档
   - 基于读取结果继续求解，不阻塞主流程
   - 在最终回复中可说明"已尝试请教 {专家名}，子 agent 未返回有效结果，改由主 agent 直接读取资产"
6. 汇总各子 agent（或降级读取后）的回答 / 产出，**作为临时上下文参考**整合进目标专家的求解主流程，不写入任何专家资产

## 查找策略

### 遇到业务模块任务时的查找顺序

```
1. 提取需求关键词
2. 查 expert-lookup（本 skill）→ 命中则变身为目标专家求解；跨域时并行请教其他专家
3. 查 solution-lookup → 有则复用具体问题解法
4. 查 ki 记忆索引 → 有则参考
5. 查代码库 / 调 expert-team 创建专家资产
```

### 常见匹配场景

| 需求类型 | 提取关键词示例 | 可能命中的专家 |
|----------|---------------|---------------|
| 接手某模块 | `模块名`、`业务域` | 同名 / 同域专家 |
| 排查告警不触发 | `告警`、`不触发`、`规则` | 告警处理专家 |
| 新增业务规则 | `模块名`、`新增`、`规则` | 该模块专家（及其专用技能） |
| 查询历史数据 | `日志`、`查询`、`历史` | 日志查询专家 |

## 输出格式

### 找到专家

```markdown
## 查找到业务专家

**匹配专家**：{中文专家名}
**存储层级**：项目级 / 用户级
**匹配关键词**：{命中的关键词}
**路径**：{专家目录路径}

### 专家概要
- 一句话职责：{agent.md 中职责}
- 负责的模块：{模块根} — {职责}
- 何时找他：{典型场景}

### 包含的资产
- 切面文档：01-架构, 02-实现, ...（或「暂无」）
- 专用技能：skills/{skill1}, ...（或「暂无」）

是否深入阅读某切面文档，或调用其专用技能？[列出可选项]
```

### 未找到专家

```markdown
## 未找到匹配的业务专家

已搜索：
- 项目级 .module-experts/INDEX.md（{N} 位专家）
- 用户级 ~/.module-experts/INDEX.md（{M} 位专家）

提取的关键词：{关键词列表}

未命中任何专家资产包。可使用 expert-team 为「{目标模块}」生成专家资产包。
```

## 与相邻 skill 的边界

| skill | 关系 |
|---|---|
| **expert-team** | **本 skill 查找其产出的专家资产**；找不到时建议调用它创建。本 skill 只读取复用，不生成 / 修改 |
| solution-lookup | 本 skill 查"业务领域专家（模块知识包）"，solution-lookup 查"问题解法 skill"，两类资产互补 |
| code-survey | 本 skill 复用既有深度资产；无资产时可先走 code-survey 轻量调研，再决定创建专家包 |
| task-dispatch | 跨专家请教时，用其创建基于其他专家资产的子 agent（咨询 / 派活），实现并行协作 |

## 行为边界

- **查找非阻塞**：找不到专家不阻塞后续工作，正常排查即可
- **不修改资产**：查找阶段只读取和复用，不修改已有专家资产（创建 / 更新用 expert-team）
- **项目级优先**：同时命中时，项目级专家优先于用户级
- **必须实读**：不能仅凭 INDEX.md 标题就断言命中，必须读 `agent.md` 确认职责与适用场景
- **行号快照**：专家资产中的 `#Lx-Ly` 为生成时快照，代码变更后可能失效（属 expert-team 已知权衡），不以过期行号否定资产其它内容
- **用户级为可选扩展**：当前专家资产实际均位于项目级 `.module-experts/`；用户级 `~/.module-experts/` 通常为空（需手动放置），勿因用户级为空而误判"无专家"
- **不替代创建**：本 skill 是查找 / 复用，不是生成；建立新专家资产用 expert-team
- **变身不篡改资产**：变身为目标专家仅加载其资产用于求解，不修改专家资产本身
- **子 agent 只读**：派生的子 agent 只读取其所基于的其他专家资产，不修改、不创建
- **协作边界**：目标专家负责主流程与整合；子 agent 仅解答 / 完成被指派的部分，不越权接管主线
- **子 agent 输出为临时上下文**：跨专家请教产生的子 agent 回答仅作为当前问题的临时参考，不写入主专家资产或任何持久化文件
