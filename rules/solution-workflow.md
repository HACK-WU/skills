# Solution Workflow

## 规则

AI 在遇到问题或解决问题后，**必须按以下规则决定是否调用解决方案技能**：

| 时机 | 条件 | 调用技能 |
|------|------|----------|
| 遇到问题时 | 非平凡问题（3步以上、需要调试、可能有现成方案） | `solution-lookup` |
| 解决问题后 | 解决过程涉及3步以上、试错、查找文档、或包含非显而易见的技巧 | `solution-capture` |

**非平凡问题判定**：满足以下任一即为非平凡
- 需要 3 个以上步骤才能解决
- 需要查找文档、试错、调试才能解决
- 问题具有复现性，可能再次遇到
- 解决方案包含非显而易见的技巧或注意事项
- 涉及特定工具/框架的坑或最佳实践

**平凡问题（跳过）**：一行命令能解决、常规 CRUD、一次性问题、AI 知识库已覆盖的标准操作

## 执行流程

```
遇到问题 → 判断是否非平凡
  ├─ 是 → use_skill("solution-lookup") → 有方案？→ 复用
  │                                        → 无方案？→ 正常排查
  └─ 否 → 跳过查找

问题解决后 → 判断是否非平凡
  ├─ 是 → use_skill("solution-capture") → 评估 → 记录/跳过
  └─ 否 → 跳过记录
```

### 查找优先级

遇到非平凡问题时，按以下顺序查找：

1. **solution-lookup** → 已沉淀的解决方案（本规则管理）
2. **ki 记忆索引** → 项目代码级知识
3. **代码搜索** → 从头排查

### 沉淀优先级

问题解决后，沉淀到：

1. **solution-capture** → 完整的"问题→解决步骤"配方（本规则管理）
2. **update_memory** → 一行事实/偏好（不适用解决方案）
3. **ki 知识库** → 代码级知识（模块/API/函数级）

## 与其他技能的关系

| 场景 | 本规则技能 | 其他技能 | 判定 |
|------|-----------|----------|------|
| 完整的"问题→解决步骤"配方 | `solution-capture` | — | 用本规则技能 |
| 一行事实/偏好 | — | `update_memory` | 用 memory |
| 代码级知识（模块/API/函数） | — | ki 知识库 | 用 ki |
| 通用工作流（人工编写） | — | `skills/` | 用 skill |

## 例外

以下情况跳过 `solution-lookup`：
- 问题明显平凡（一行能解决）
- 用户明确说"不用查"、"直接解决"

以下情况跳过 `solution-capture`：
- 解决过程平凡（常规操作）
- 问题一次性、不会再现
- 用户明确说"不用记录"、"跳过沉淀"
- 已有相同解决方案存在且无需更新
